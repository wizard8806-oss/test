# Нативный интерфейс · кандидат SCADA11

Перенос согласованного макета в формат Simple-Scada2.6.15.0. Основа —
проверенная SCADA10, а не демонстрационные значения браузера. По умолчанию
в каталоге только реальный стенд `codex.Device1.`.

Локальный [прогон02.11.2026](../../docs/reports/station11-native-ui-20261102T003600Z.md)
подтвердил установку Python, native open/save/Compile All и черновик без записи.
Исправлены слот фона/флаги заголовка окна и metadata новых скриптов: модуль
клонирует StationDiagnostics, события — ProcessSpPlus_OnClick, без autostart.
11 пока не принята: часть новых переходов не срабатывает, вёрстка и RAW-шкалы
требуют доработки. Рабочая10 возвращена,11 сохранена неактивной. Guard четырёх
SHA и пустой исходной коллекции окон остаётся обязательным. Архивные точки
проверять после учёта буферизации: пустая панель до flush не означает отсутствия
SQL-записи. Маску исторического давления/BAD нельзя заменять одним GOOD OPC.

Продолжение исправления уже сохранённой11:
[переходы/вёрстка/шкалы](../../docs/tasks/station11-navigation-layout-followup.md).
Читающая диагностика `tools/audit_native_ui_navigation.py` требует только stdlib,
проверяет файлы без выполнения скриптов и не заменяет native UI-прогон.
Для исправления существующей11 не применять заново установщик копии10→11.

## Сборка и создание копии

Для сборки достаточно Python3.10+ без дополнительных пакетов. Если его нет,
пользователь разрешил установку официального Python для своей учётной записи:

```powershell
$setupOutput = & powershell -NoProfile -File .\tools\Install-ProjectPython.ps1
if ($LASTEXITCODE -ne 0) { throw 'Project Python setup failed' }
$projectPython = $setupOutput | ConvertFrom-Json
& $projectPython.pythonPath -I -B .\tools\build_native_operator_console_01.py
if ($LASTEXITCODE -ne 0) { throw 'SCADA11 build failed' }
powershell -NoProfile -File .\artifacts\operator-console-native-01\Install-Operator-Console-01.ps1 -SourcePath "$env:USERPROFILE\Documents\Simple-Scada 2\Projects\codex_diag_10"
```

Helper проверяет закреплённый SHA256 и действительную подпись Python Software
Foundation. Установка по умолчанию LOCALAPPDATA\Programs\Python\Python313,
без добавления в PATH/ассоциаций/launcher/pip, без автоматической перезагрузки.
Существующая совместимая подписанная версия повторно не устанавливается.
Результат/лог нужно сохранить локально; Windows-установка ещё не подтверждена
облачными тестами. [Проверка источника и ограничений](../../docs/reports/station11-python-bootstrap-20261102.md).

Источник указывать после проверки фактического пути. Установщик **только
создаёт файлы кандидата** по умолчанию в
`%LOCALAPPDATA%\CodexCandidates\SCADA11\codex_diag_11`, с доступом владельцу/
SYSTEM в Windows. Он не запускает Editor/Server/Client, не переключает
проект и не подключается к оборудованию/БД. Существующий каталог не заменяет.
Пользовательский `-TargetPath` должен быть отдельным новым каталогом вне Git.
Сохранение несохранённой модели Editor выполняется локальным CLI отдельно.

Генерируются `Pages.spg`, `Windows.swn`, `OperatorConsole.txt`,
`archive-plan.json`, манифест и установщик. Результаты сборки игнорируются
Git; авторитетные исходники — этот каталог и сборщик/шаблон в `tools/`.
Не добавлять приватную рабочую копию, пользователей, лицензии и пароли в Git.

## Что перенесено

- Шесть нативных страниц: общий обзор, станция, диагностика, аварии,
  графики и настройки. Тёмная компоновка1440×920, боковая навигация.
- Основная карточка сохраняет все26 исходных объектов и ссылки обработчиков
  `ProcessSpMinus/Plus/Apply/Cancel`. R2100, проверки/владелец черновика,
  подтверждения ПЛК/ПЧ и таймауты остаются прежними.
- Отдельное окно наблюдения станции. Оно показывает ту же станцию и
  реальные данные, не создаёт второго командного черновика.
- Общий обзор/окно/текущий статус обновляются серверным таймером без
  дополнительных прямых OPC/Modbus-соединений и без команд.
- Аварии открывают штатные активные/неподтверждённые/все сообщения и
  действия оператора. Подтверждение остаётся штатным, без сброса ПЧ.
- Графики открывают штатный архив за1/6/24ч и группу конкретной станции.
  **Группы и архивирование переменных нужно настроить в нативном Editor**
  по плану; установщик намеренно сохраняет существующие `Trends.str` и
  параметры архива. Пока группы нет, показывается понятная причина.
  Первым подключается график уставки; давление — после проверки маски
  достоверности источника/свежести в архиве, без недостоверного нуля.
- Страница настроек показывает каталог и подключения. В первой нативной
  версии каталог редактирует наладчик в JSON с пересборкой новой копии;
  полноценная форма редактирования каталога из Client ещё не реализована.

Насосы2–4 показывают «нет данных», пока нет проверенных отдельных тегов.
Слова состояния ПЛК не подменяют коды ПЧ. Свежесть требует продвижения
счётчика, давление — отдельного достоверного источника; GOOD-ноль сохраняется.
HMI/ПЛК и внешний PowerShell-радиосборщик не изменяются.

## Добавление станций

Редактировать [catalog.json](catalog.json): стабильный `id`, название/группа,
проверенные `itemPrefix`/компьютер/ProgID, число насосов и предел свежести.
Первая станция сохраняет проверенный контракт управления. Дополнительные
станции в этой версии только для наблюдения, `commandEnabled=false`.
Все страницы/окна/обзор формируются одним сборщиком, вручную копировать
обработчики под каждую станцию не нужно. Имена групп трендов зависят от
stationID, а не позиции строки (`UiTrend_station_001`).

Поддержано1–16 станций профиля карты32 с1–4 насосами; для другого ПЛК нужен
проверенный адаптер. Добавление записи не создаёт OPC-теги и не настраивает
модем. Для новой станции используются независимые счётчик/маршрут; при
отсутствии данных приборы не получают вымышленных нулей.

## Проверки и ввод в работу

```bash
python tools/validate_native_operator_console_01.py --report /tmp/native-ui.json
python tools/run_checks.py --report /tmp/station-checks.json
```

Первому тесту нужны FreePascal и PowerShell, переменные путей как в корневом
README. `--vendor-pages` добавляет чтение страниц оригинальным x86-загрузчиком
в изоляции; это не Windows GUI/F9. Заголовок окна проверяется структурно по
официальному Demo2.6.15; нативное открытие/сохранение/компиляция обязательны.

Установщик принимает точные хеши Pages/Scripts/Variables/Servers последней
проверенной10 и пустой исходный `Windows.swn`. Если они отличаются, он
останавливается с сохранением источника; сначала выяснить локальные изменения,
не менять хеши для обхода проверки. Старый compiled-кэш в новую копию не
переносится. Прочие ресурсы/профили/настройки сравниваются поSHA256.

Порядок нативной проверки/архива/переключения:
[задание локальному CLI](../../docs/tasks/station11-native-operator-ui.md).
До его отчёта не считать SCADA11 установленной или успешно скомпилированной.

# SCADA «Ошский»: компоненты UX r4

25.11.2026, МСК. Пользователь поручил реализовать предложения из
`docs/ui/oshsky-scada-ux-comparison-20261125.md`. База — **сохранённая native r3**
из коммита `459a999578c4b6071f28b1e74bf4d90513083200`, а не старый public builder.
Эти файлы — проверяемые исходники для интеграции; нового native-проекта
Simple-Scada в Cloud нет.

## Состав

- `layout.json`: четыре одинаковые карточки, крупные F/I/часы, верхняя сводка,
  conditional PLC countdown, сравнение часов и последние изменения.
  1920×1240 — **ориентир композиции**, не измеренный размер private проекта.
  Сначала снять actual canvas/DPI/Scale в Editor; сохранить верхние native-вкладки.
  Одинаковая геометрия карточек задаётся одним `cardTemplate`.
- `OperatorUxR4.txt`: native Pascal-модуль с форматированием и ограниченной
  лентой пяти наблюдавшихся изменений каждой станции. Нет обращений к OPC,
  записи переменных, SQL, сообщений в архив или вызова команд.
- `additional-readonly-tags.json`: четыре дополнительных **кандидата RO**
  для фактического участия насосов в АВТО, R720..723. Применяются в отдельном
  review-профиле после сверки allocation; не устанавливаются в действующий OPC.

## Подключение к сохранённой r3

Сначала инвентаризировать actual native имена и ссылки. Известны
`R3Cell<0..3><0..6>`: номер, состояние/RUN, F, I, код, часы, задание частоты;
`R3Wait`, `R3Summary`, `R3Delays`. Сохранить UID/привязки/producer этих полей
и единственного существующего владельца черновика уставки. Либо явно
перенести все ссылки по карте соответствия. Недопустимо оставить обычный
переход на старые статические карточки насосов2–4, а новые спрятать отдельно.

Добавить модуль через поддерживаемый Editor импорт скриптов. Native-адаптер
вызывает форматирование **после принятия исходного снимка r3**, не по
прочитанным `Text` объектов и не по цвету индикатора. Входы:

| Вход | Условие |
| --- | --- |
| `CoreFresh` / `Fresh` | Уже проверены map32, schema27110, качество, движущийся общий heartbeat и согласованность полей |
| `OwnFresh` | Принят снимок конкретного ПЧ; Q1 только F0, Q2 только F1..5990, Q0 неизвестен |
| `FaultGood` | Достоверен native-код этого ПЧ, не код координатора |
| `CurrentFresh` | Независимо принят current-export27401/heartbeat/свой канал; отсутствие тока не скрывает F/часы |
| `State` | Native state из своего снимка; подтвердить vendor mapping1/2/3 в actual проекте до адаптации |
| `Mode`, `Leader`, `Mask` | R2300, R2304, R2306; маска четырёх RUN-выходов, не датчик вращения |
| Наработка | Четыре согласованных unsigned32 **минуты**, не строки часов и не signed16 |
| Участие в АВТО | Fresh RO R720..723, только0/1; неизвестное не означает исключение |

`R4PumpRole` требует подтверждённого номера ведущего для роли ведомого.
`R4DriveState` не объявляет насос остановленным по одной нулевой частоте
при противоречивом native state. Статус «ПЧ работает» означает данные ПЧ,
а не независимый сигнал физического вращения. `R4PumpHint` поясняет качество,
ток и RUN; при противоречии основного состояния не скрывать его этой подсказкой.
Строки роли и участия объединяются в одной области `role`, без накладывающихся
объектов. Имя UI-поля ленты — `R4EventsText`, отличное от функции `R4RecentEvents`.

`R4RuntimeSpread` считает разницу из исходных минут с Int64. Индивидуальные
часы оставляет существующий r3 formatter с округлением половин к чётной
десятой. Нулевая наработка достоверна; unknown не подменяется нулём.

## Лента изменений

`R4Observe` принимает station index0..15, проверенный snapshot, монотонные
секунды одного источника времени и явно переданный timestamp для показа.
Время форматирует native-адаптер с проверенным часовым поясом; не выдавать
часовые пояса Windows/Server/PLC за одинаковые без сверки.

Наблюдатель вызывается в **одном существующем цикле публикации станции**,
а не отдельно из каждой открытой страницы/Client. Если движок изолирует
скрипты по Client, отметить границу сессии; не смешивать их часы и baseline.
UI только читает результат. Повторный heartbeat не создаёт события, переходы
10↔11↔12 не являются сменой физического режима. Первое чтение тихое.
После потери данных/перерыва >10с устанавливается новая база, пропущенные
пуски/остановки не придумываются. Имена событий RUN прямо говорят о **команде**.

Подпись ленты — «Изменения с начала наблюдения». Она не заменяет native-архив
аварий, не переживает перезапуск и не является полной историей событий.
Подтверждённые аварии/ack/действия пользователя открываются в прежнем архиве
с правильным station filter; новые фиктивные записи не создаются.

## Проверка

`python tools/validate_oshsky_scada_ux_r4.py` компилирует фактический Pascal
модуль в FPC с проверками диапазона/overflow и полным вычислением Boolean.
95 утверждений покрывают все четыре роли/состояния, независимую неизвестность,
границы unsigned32, смену режима/ведущего/команды, потерю/возврат, wrap,
повторные кадры, перерыв и отдельные станции. Проверяется геометрия manifest.
Это **не native Compile, Client, OPC polling или доказательство archive-gap**.
Локальная интеграция и проверка описаны в
`docs/tasks/oshsky-scada-ux-r4-local.md`.

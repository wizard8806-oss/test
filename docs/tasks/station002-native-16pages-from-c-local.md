По сравнению найден пропуск двух страничных массивов. Следующее задание —

Пользователь теперь сообщил OpenFAIL A и затем «C открылся». Его текущий
путь/SHA ещё нужно прочитать локально. Не просить вспоминать путь и не
повторять старые Open-пробы. Использовать **уже открытый C**. Цель — получить
учёт16экранов, сохранённый самим SKTool7.1, для сравнения с неоткрывающимися
generated A/полным проектом. Новую production r15f сейчас не делать.

## Выполнить доступное локально

1. Прочитать фактический путь проекта из текущего окна SKTool/его заголовка.
   Записать имя/размер/SHA файла на диске, если путь доступен. Не подменять
   открытый проект одноимённой другой копией. Прежний C_MACRO_ONLY —
   1298619/SHA95e6b3cd163effa7c1624470c8ac870f726b0b30e73175fdec09d8ff9be0d272;
   C_native_alarm_sample —1298542/SHA0ecac7d67dcfc42648f8f468098fadb7b84b782ae4fd6f70f944195ca0947c3f.
   Эти данные помогают опознать проект, а не доказывают, какой открыт сейчас.
   Более новую операторскую копию сохранять и описать, не затирать.
2. **File→Save As → C_native_16pages.skm** рядом с исходным C. Это новый
   отдельный файл. Исходный C не перезаписывать; существующий native-файл
   сохранить, при необходимости выбрать новый суффикс и сообщить реальный путь.
3. Проверить дерево экранов: ожидается14исходных. Добавить через штатную
   команду создания экрана **два пустых экрана Screen15 и Screen16**. Должно
   получиться16. Если исходных уже не14 или редактор отказывает в добавлении,
   записать фактическое число/имена/ошибку, не удалять и не добавлять вслепую.
4. **File→Save** новой копии. Не менять старые экраны/их названия/раскладку,
   модель, макрос, Batch-переменные, Alarm Login, стартовые настройки и лого.
   Не переносить пока сгенерированные виджеты A в эти пустые страницы.
5. По возможности штатно переоткрыть именно новый C_native_16pages.skm и
   отметить загрузку дерева16экранов либо точную ошибку. Сохранить все копии.
   Записать реальный полный путь/размер/SHA нового native-файла и передать
   оператору для приватного прикрепления в облачный чат.

Если GUI агенту недоступен, закончить доступное чтение пути/хеша и передать
оператору одну короткую инструкцию для уже открытого C:

> File→Save As → C_native_16pages.skm. Если сейчас14экранов, добавьте два
> пустых Screen15 и Screen16, сохраните новую копию и прикрепите её сюда.

Не застревать на Tips/скрытых процессах, не завершать массово SKTool и не
выдавать Python-перезапись за native Save. Сохранение/создание выполняет
сам SKTool7.1. При уже полученном native-файле повтор не нужен.

## Результат

Нужен приватный **C_native_16pages.skm**, а не очередной generated SKM.
В отчёте handoff-ветки раздельно указать source/path/SHA, начальное число
экранов, nativeSaveAs, добавленные экраны, nativeSave/reopen и путь результата.
Обновить HANDOFF. SKM/PDW/JPG/vendor/сырые закрытые данные в Git не публиковать.
Это эталон формата, не готовая HMI: Compile/Simulator/Download/оборудование
не нужны. PLC/runtime/reset-guard/main не менять. Шкаф отдан.

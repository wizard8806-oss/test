## 2. Прочитать только разрешённые параметры MasterOPC

В репозитории подготовлен `tools/Read-MasterOpcProfile.ps1`. Это чтение MBP/MBC
на диске: ZIP/JSON разбираются локально, повторяющиеся Node/Teg/поля сохраняются.
Вывод — только whitelist тегов codex.Device1 и полей Address/Region/Type/
TypeInDevice/Access/Enabled, флага TegCalculation и KoffA/KoffB, имя/SHA файла.
Пароли, каналы связи, полные деревья, тела скриптов и вычислений не выводятся.
Считыватель не подключается к OPC/Modbus и не сохраняет/не меняет конфигурацию.
Он рассчитан на Windows PowerShell5.1 без установки модулей; облачные13 тестов
выполнены на PowerShell7/Linux, нативный5.1 запуск ещё не проверен.

Сначала определить путь **текущей** конфигурации по уже работающему MasterOPC
или достоверным метаданным. Не выбирать первый MBP на диске. Затем выполнить
из локального Git-репозитория, подставив установленный локально путь:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\Read-MasterOpcProfile.ps1 -Path '<путь текущего MBP>'
```

Секреты/сырой MBP в Git не переносить. Если текущий файл установить нельзя,
можно прочитать известный кандидат, но отчёт должен назвать его кандидатом.
Не подставлять старый MBP вместо активного и не менять выбранную конфигурацию.
При ошибке считывателя сохранить код ограничения, а не вывод полного документа.

Проверить команду PressureSP_Command и зеркало PressureSP_x100. Ожидаются
PDU2100/2360, Holding Registers, uint16→uint32, ReadWrite/ReadOnly. Коды enum
не угадывать; сопоставлять с надёжным описанием или читаемыми свойствами UI.
При дублях, неоднозначных свойствах или опущенном вычислении нет автоматического PASS.
Коэффициенты MasterOPC не доказывают отсутствие масштабирования в SCADA:
offset0/множитель1 Variables.svr остаются отдельным пунктом. Проверить их только
доступным чтением, не пересохранять проект и не придумывать смещения двоичного
формата. Если прочитать нельзя — точно назвать оставшееся неизвестным.

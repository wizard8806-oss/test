# Утверждённый комплект «Бабанов»: 3 насоса, HMI r21c + PLC r16

24.11.2026 пользователь утвердил r21c для объекта «Бабанов», 3 насоса,
панель SK-070HE 7″/800×480, затем поручил сделать отдельную папку со всеми
вложениями. Это новое поручение на упаковку; старый комплект r15/r17a от
13.11 не использовать вместо текущей пары и не перезаписывать.

## Создать на компьютере пользователя

На фактическом Рабочем столе пользователя создать каталог
`Бабанов_3насоса_Утверждено_2026-11-24` и ZIP рядом с ним.
Рабочий стол определить штатно через Windows SpecialFolder, учитывая
перенаправление в OneDrive. Если имя занято отличающимся комплектом,
сохранить его и выбрать суффикс времени. В конце проверить существование
и выдать полные фактические Windows-пути папки и ZIP, без многоточий.

Доступ к локальным файлам и упаковка уже разрешены. Не останавливаться
на плане или предполагаемом пути. Cloud подготовило это задание и запись
утверждения; у Cloud нет новых приватных native-байтов и прямого управления
Windows пользователя, поэтому сам комплект должен создать локальный агент.

## Сохранность и проверка

- SKM/PDW не переписывать ради упаковки и не менять их ссылки. Копирование
  assets само по себе не делает абсолютные ссылки относительными: README
  объясняет восстановление путей либо перепривязку на отдельной копии.
  Не объявлять переносимость на другой ПК проверенной без такой проверки.
- Проверить SHA обоих проектов, каждого изображения и шрифта после копирования.
  Все активные внешние зависимости должны присутствовать; недостачи перечислить
  явно. При недостающей обязательной зависимости завершить доступное копирование,
  но пометить комплект НЕПОЛНЫМ, без подмен/нового запроса общего доступа.
- ZIP создать рядом, не внутри папки. Проверить CRC и совпадение прочитанных
  из ZIP байтов с manifest/файлами. Использовать установленный Python/PowerShell,
  без установки ПО. Копирование не требует повторения Compile/Simulator.
- README: дизайн r21c утверждён; локальные Compile/Simulator пройдены;
  реальные телеметрия/ток/RS485 и аппаратные блокировки требуют стенда.
  Не представлять визуальное утверждение как аппаратную приёмку пары.
- TEST_ONLY SKM, candidates, старые сборки, секреты и несвязанные документы
  в рабочий комплект не добавлять. Оборудование не подключать/не загружать.
  Native/JPEG/ZIP и полные приватные manifests не публиковать в Git.
  В Git передать только краткий отчёт/HANDOFF без закрытых данных.

# Продолжение унификации: рабочий контекст и отдельные проекты

06.11.2026 МСК. Пользователь уже передал локальному CLI задание на реализацию
в отдельных копиях. Ранняя формулировка «только оценка» больше не текущая.
Последний снимок подтверждает восстановление05/статическую карту32, но
N=2/3/4, новые HMI/SCADA-копии и native-компиляция не выполнены. Подробный
локальный отчёт в cloud не получен.

## Один целевой проход доступа

1. Сохранить готовый график и другие открытые проекты. Пути WinProLadder/
   SKTool уже найдены; общий поиск установок и `where` не повторять.
2. Получить текущий session/window-station/desktop исполнителя существующим
   `tools/Get-ScadaUiContext.ps1`. Он по умолчанию перечисляет только SCADA;
   отсутствие в нём WinProLadder/SKTool не означает отсутствие их окон.
   Для фактически найденных процессов этих приложений отдельно получить
   читающие сведения SessionId/MainWindowHandle и конкретные ошибки.
3. При изолированном контексте проверить фактическую доступность штатного
   режима по `station11-supported-desktop-access.md`. Только если текущая
   политика разрешает запрос, выполнить один читающий запуск точного helper
   предусмотренным инструментом способом. Запрещённый/отклонённый запрос
   не повторять, ограничение не обходить. Разрешение пользователя само
   не означает появления технического доступа.
4. Отдельно проверить чтение нужных исходников и создание новой копии в
   разрешённой рабочей директории. Отказ FETCH_HEAD записать отдельно;
   ACL/Git-метаданные не менять, местные изменения не сбрасывать. Исходники
   PLC уже доступны. Недоступная SCADA-папка блокирует её адаптацию,
   но не весь разбор ПЛК.
5. При оставшемся ограничении дать пользователю один конкретный запрос
   о недостающем действии/штатной настройке. Если причина не установлена,
   запросить сравнительную читающую диагностику из его обычного PowerShell.
   Такой запуск не даёт исполнителю прав и не считается восстановлением
   доступа. Общее разрешение на стенд повторно не запрашивать. Недоступным
   GUI вслепую не управлять; служебный альтернативный канал не создавать.

## Продолжение реализации

- Составить карту прямых обращений, многословных диапазонов, таблиц,
  косвенных обращений и внешних HMI/SCADA-привязок для новых параметров.
  Непроверенные диапазоны перечислить конкретно. Отсутствие R-номера в
  строках не доказывает, что он свободен. При неполноте подготовить
  символическую спецификацию и перечень неподтверждённых привязок.
- Общий алгоритм: четыре адресных слота, установленное количество2/3/4
  с HMI, проверка/хранение в ПЛК, применение в STOP, отдельный состав AUTO.
  Исключить отсутствующие каналы из обмена, команд, ротации, выбора давления
  и аварий. Применение само не пускает насос. Адреса выделить после аудита.
- При доступном native-контексте открыть насосную базу05 в отдельной копии,
  проверить целевой CPU FBs-24MCR2-AC, реализовать конфигурацию и выполнить
  F8. Другой открытый WinProLadder-проект не является насосной базой.
- Для SK070HE подготовить копию существующего HMI и подтвердить профиль
  в SKTool, затем настройку количества и отображение2/3/4. Save As, смена
  модели, компиляция и проверенное поведение — отдельные результаты.
  Уточнение: пользователь уже вручную подготовил unified-draft под
  SK-070HE/800x480 и показал Simulator. Сначала сохранить/принять эту копию,
  не повторять перенос старого SKM поверх неё. Для2/3/4 нужен соответствующий
  фон с нужным числом насосов и трубных ветвей; подписи, показатели и команды
  должны совпадать с расположением насосов. Все части получают подтверждённый
  N из ПЛК. Допуск AUTO фон не меняет. Новые черновые изображения2/3 из чата
  пока не импортированы; существующий4 сохраняется. Адрес N не угадывать.
- Актуальную SCADA-копию адаптировать при полученном доступе к ней,
  сохранив native-график. Количество читать из соответствующего ПЛК,
  разделить данные/команды двух станций и контексты Client.

Результат прохода: измерение доступа, состояние каждой части, доступные
изменённые файлы/карта и точные оставшиеся зависимости. Восстановление05
и старый общий аудит не повторять. Наличие процесса/статический PASS не
доказывают доступ или реализацию. Загрузок в действующее оборудование нет.
Полные частные проекты/журналы остаются локально; публично — согласованная
краткая сводка и обезличенные исходники/тесты. main сохраняется.

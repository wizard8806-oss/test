## 1. Снять реальное мерцание по цепочке данных

Перед изменениями определить фактически загруженные PLC/HMI по файлам/build/
readback, сохранив пользовательские буферы. Подключение физической HMI уже
сообщено: не начинать с рассуждения, что она вообще не соединена. Прочитать
два-три полных перехода в обе стороны с временами; по возможности60–120с.

На PLC фиксировать R2840/R2508, R2500/R2504/R2510, rawR2800…2806,
M1740/M1744/M1748/T92, D300/D301/M600…602 и actual owner/паузы Port3.
X1 читать как есть; отсутствие провода не равно сбою RTU. Сопоставить
момент успешного именно семисловного ответа slave1/row0 с интервалом до
следующего, watchdog и опросом трёх отсутствующих адресов. Сохранять причину
каждого сброса cache: own-row error, таймер, boot, другой writer.

На physical HMI одновременно наблюдать directR2510/частоту/ток/heartbeat,
те же Batch aliases и возраст/причину допуска, выводимые Main local-слова и
visibility. Проверить actual period, RTC, byte offsets/types, фоновые обновления
и page-local poll: зелёный link/движение общего heartbeat не доказывают
свежесть каждого собственного снимка. Если программирование занимает общий
порт, использовать независимый доступ/сохранённый trace; второго master
на линию HMI или Port3 не подключать. Отдельный Online Simulator не заменяет
этот физический опыт и может сам повлиять на нагрузку/владение портом.

Разделить исходы: Q уже падает наPLC; либо Q стабилен, но aliases/age/вывод
мигают наHMI. Cloud показало механизм Q-мигания при искусственном7с опросе
и5с expiry, но настоящий период/причина неизвестны. Измерить, а не назначать
виноватыми отсутствующие ПЧ заранее. Если цикл реально слишком длинный,
исправить доказанную проблему опроса/арбитража/обработки отсутствующих устройств
с сохранением периодического контроля всех4; если ошибка в HMI — исправить её.
Не увеличивать timeout, не отключать guards и не удерживать0 при реальной
потере данных ради красивого экрана. READY/pressure не добавлять в допуск чтения.

## 2. Прочитать уже имеющуюся ошибку ПЧ

До Reset/перезагрузки/перезаписи параметров снять фактическую надпись ПЧ и
успешный ответ действующего запроса: адресат/функция/диапазон, rawсемьWORD,
код/состояние/результат и время. Проект читает0x1000…1006, fault→R2801;
проверить actual r3f и соответствие AC590. Если запрос не поддержан/код0
не соответствует дисплею, найти подтверждённый адрес по точному руководству/
штатному чтению, не сканировать вслепую и не переносить AC590-различие в M900G.
Ранее согласованная одинаковость настроек — рабочая предпосылка, не raw-доказательство.
Если Err уже исчез, использовать сохранённый код/историю при подтверждённом
протоколе либо отдельные тестовые входы, новый силовой RUN не нужен.

Проверить всю цепочку native fault, а не только F/Q: poll→принятый снимок→
качество/возраст→actual HMI alias→статус/номер/расшифровка→история. Не объявлять
код0 по начальному/старому буферу или неуспешному ответу. Для четырёхнасосной
базы Cloud не нашло прямого потребителя R2801 в PLC, станционная неготовность
формируется по X. Проверить, что native HMI-путь действительно реализован.

## 3. Довести native fault для всех четырёх насосов

Реализовать минимально необходимое в actual паре. Сначала переиспользовать
существующий семисловный опрос, не добавлять одинаковый Modbus-запрос ради UI.
Для fault нужен собственный достоверный снимок; отсутствие READY, давления,
команды ПЛК, нулевая/невалидная частота не должны сами скрывать успешно
прочитанный код. При неизвестной связи последний подтверждённый код можно
показывать только с явной пометкой, не как текущую неисправность/исправность.

Main: при свежем native fault показать «Авария ПЧ: кодN» у правильного насоса
вместо «Остановлен». Диагностика: raw, подтверждённая расшифровка, качество/
возраст. История: насос, появление/смена/снятие кода и время в штатной
поддерживаемой SKTOOL форме; код в старой записи не должен меняться вслед
за текущим регистром. Неизвестный словарю код показывать числом.
Снятие подтверждается свежим нулём, не пропаданием связи. Ошибку чтения
и дискретную неготовность оставить отдельными состояниями.

Ориентир — прежний native-fault Бабанова r14 и его словарь. Не копировать
его трёхканальные адреса/пакеты/Map и не объявлять весь словарь проверенным
для AC590. Четвёртый канал полноценный, соответствие Err09↔raw подтвердить.
Сохранять существующий дизайн Main, ручное управление, отсчёты/роторы, SCADA.

При необходимости новых PLC/HMI-экспортов сначала аудит actual памяти/ABI/
профилей. У r3f свободно741слово; R3080 ужеrow-decoder, R3200…3555 и
R3560…3609 заняты capture. В R2551 старшие биты заняты Boot/generation:
новые alarm-биты поверх них не размещать. Использовать компактную реализацию,
сохранив capture ПЧ4. Один и тот же code не создаёт новое событие/звук на
каждом полле; настоящее новое событие соблюдать по прежнему mute-протоколу,
без второго писателя R2553 или конфликтующего владельца звука.

## 4. Проверить на физическом стенде, затем продолжить GSM

Достаточный минимальный протокол: стабильный0/Qvalid первого при отсутствии
трёх других; независимое истечение/возврат каждого качества; разные причины
ошибок RTU; уже имеющийся native fault при X1неподключённом/без давления;
смена/неизвестный код/свежий0/обрыв, все4канала в отдельном TEST_ONLY без
силовых команд. Production не содержит подмен и bench-перемычек.

Для изменённойPLC — nativeF8/reopen, сохранность данных/защит/9таблиц,
реальный STOP после backup/загрузки. Для HMI — Script/Full Compile/reopen,
загрузка в физическую панель и повтор того же живого опыта; показать срезы
до/после, а не только свойства объектов/Offline Simulator. Вскрытые проблемы
fault/OwnFresh учесть в r4a SCADA, сохранив RW-whitelist и другие станции.

Затем выполнить оставшийся [GSM/OPC/Client этап](oshsky-gsm-route-and-client-local-20261127.md).
Обновить отдельный исправленный комплект/manifest/пути/SHA при изменениях,
HANDOFF/карточку/лист выезда; публикация безопасного отчёта с remoteSHA.
Не объявлять устранение нового дефекта по старым 222 тестам или одному
нулевому STOP-кадру. Остаток M900G/нагрузка/CL50 указать явно. Закрыть свои
промежуточные окна после сохранения, сохранив пользовательские.

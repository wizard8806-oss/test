# Стенд шкафа без двигателей: связь и сохранение программы

09.11.2026 МСК. Пользователь сообщил: шкаф собран, под напряжением,
двигателей нет, ПК пока не подключён. Кабель исправный/привычный; используется
Port0 ПЛК, который также занят HMI. Повторно кабель не подбирать.

На последнем снимке WinProLadder Simulation уже активен, виртуальнаяCPU STOP
(End Simulation доступен; Run PLC доступен, Stop PLC серый). X6OFF,
R2522=0,R2525=0 — исходное состояние, динамики таймера ещё не было.

## Первый этап на реальном шкафу

1. Аппаратный переключатель шкафа поставить в STOP/0.
2. В WinProLadder завершить именно виртуальный режим: PLC→End Simulation.
3. Для работы ПК использовать привычный кабель кPort0 вместо подключения
   панели. ПК/HMI на этом порту проверять поочерёдно; не строить неизвестную
   параллельную схему и не менять назначение COM-портов/CM55 наугад.
4. PLC→On-Line(F12). Первое действие — идентификация реального CPU/состояния,
   затем чтение текущей программы PLC→PC и сохранение её отдельным PDW с датой.
   Сохранить также имеющиеся настройки/комментарии, насколько они доступны;
   readback не объявлять полным исходником, если комментариев/символов нет.
5. При различии PC/PLC не выбирать автоматически DownloadPC→PLC.
   Сначала прочитать фактический диалог и направление. Встроенный Upload
   обычно означает PLC→PC, но решающим является направление, показанное GUI.
6. Записать модель CPU, состояние RUN/STOP, исходный путь/размер/SHA readback,
   исходные состояния X1..X3(READY),X5(аварийная цепь),X6(вода),X7(питание),
   X8/X9(селектор),Y1..Y4. Пока это наблюдение, не force/set выходов.

Планируемая новая программа — текущая трёхнасосная countdown-r2,
185409байт,SHA780267f80d2f107c584ded1e8f48a63c65ad23d977255cdcbe895ed2b791b73b.
Её локальная validation-copy сохранена и ранее статически сверена по
отчёту пользователя. F8 пользователь сообщал; точный итог текущего файла
не получен. Динамический native-тест/оборудование не подтверждены.
Не подменять текущую программу ПЛК новым файлом до сохранения readback/
сверки целевой модели и отдельного конкретного шага записи.

## Дальнейшая проверка

После идентификации/резервной копии можно переходить к целевой программе,
входам защит/селектора, связи сПЧ1..3, корректности команд/телеметрии,
остановам и задержкам. Фактическое чтение вводов сопоставить с проводкой:
код ожидает X5/X6/X7=1 для здоровых сигналов, AUTO X8=1/X9=0, STOP оба0.
Не обходить вычисляемые M210/M221/M1774/M1034 для видимости «работы».

Без двигателей это проверка шкафа/сигналов/команд; механическая работа,
направление вращения, регулирование давления и динамика под нагрузкой
потребуют двигателей/насосов. Возможная защита ПЧ от отсутствия двигателя
не является автоматически ошибкой обмена; её не отключать ради результата.
При RUN напряжение U/V/W появляется и без двигателя; выходные цепи должны
быть закрыты/изолированы. Силовые цепи не перемонтировать под напряжением.

HMI-r5 локальный закончил по сообщению пользователя, но осмотр новой
раскладки/active timer visibility не подтверждены. После проверки ПЛК
вернуть панель наPort0 и отдельно проверить её команды/индикацию. Факт
наличия готового SKM не означает загрузку проекта в физическую панель.

## Короткая независимая проверка отсчёта в Simulation

Она возможна до подключения ПК к шкафу. При подтверждённом виртуальном
режиме и CPU STOP задать X5=X6=X7=1,X8=X9=0, затем Run PLC(F9).
Наблюдать R2520(по умолчанию15с),R2522,R2525,M1753,M1764.
Перевести виртуальный X8=1, имитировать X6=0, затем вернуть X6=1.
Должен защёлкнуться запрос M1753; после возврата воды R2522 растёт до
периода, R2525 уменьшается до0. Повторное X6=0 сбрасывает elapsed/остаток,
возврат воды начинает выдержку заново. При STOP X8=X9=0 pending отменяется.

Полный rearm дополнительно требует валидного давления/HP-разрешения,
готового PI-лидера, подтверждённого STOP ПЧ и AUTO-контекста, затем исходные
2сT96. Отсутствие этого шага без ПЧ в симуляции не доказывает сбой паузы.
Эта последовательность подготовлена по compiled30.R000..064/CD; она ещё
не исполнена в nativeSimulator. На реальный ПЛК виртуальные входные
force-операции не переносить автоматически.

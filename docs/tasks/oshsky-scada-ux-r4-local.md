## 2. Реализовать читаемый экран станции

Использовать `assets/scada/oshsky-ux-r4/layout.json`, `README.md` и
`OperatorUxR4.txt`. Импортировать модуль, сделать и проверить тонкий адаптер
к **принятому** снимку r3. Не угадывать offsets private Pages или API движка.

1. Четыре равные карточки с одинаковыми отступами/числовыми линиями:
   номер, роль и участие в АВТО, состояние ПЧ, крупные частота/ток, наработка,
   код неисправности и действующее задание частоты, короткая причина unknown.
   Сохранить actual UID/producer `R3Cell<0..3><0..6>` либо все их ссылки
   перенести по явной карте. Максимум6553.5А и71582788.2ч должен помещаться.
2. Роль «Ведущий/Ведомый» только из проверенных режима/номера/RUN. Ноль Гц
   не создаёт «Готов/Резерв»; RUN-команда не доказывает вращения. При плохом
   собственном Q4 скрывать его F/I/состояние, но сохранить свежие часы4 и1–3.
   Неизвестный ток не скрывает доступную частоту. Неизвестность — прочерк
   с причиной, валидный0 — число. Обобщение не пишет «Аварий нет» при unknown.
3. Общая сводка PV/действующая уставка/команды RUN из4/задание ведомых.
   Не подписывать число RUN-выходов как физически подтверждённое вращение.
   Причина недостоверности и возраст **продвижения** данных постоянно видимы,
   потеря ПЛК/OPC/данных одного ПЧ различаются. Радио отдельно, если его
   состояние действительно доступно; не выводить «радио исправно» из GOOD OPC.
4. Существующий `R3Wait`: «До запуска насоса №N: S с» либо «До остановки…»
   только active/valid по R3120..3125 и своему heartbeat. Никакого местного
   вычитания времени. Нажатие открывает read-only выдержки2/3/4 и общего снятия.
   STOP/MANUAL/потеря каскадной свежести скрывают отсчёт.
5. Ротация: ведущий, прошло/интервал с верными единицами. Четыре часа и разница
   по исходным минутам; по нажатию — сравнение четырёх накопителей. Не выдавать
   разницу часов за диагноз износа, не добавлять reset/правку накопителей.
6. Компактная лента пяти изменений «с начала наблюдения» из `R4Observe`:
   режим, смена ведущего в AUTO, команды RUN, потеря/возврат данных. Один
   producer/timebase на станцию, UI читает ленту; повторные Client/страницы
   не дублируют события. Перерыв не создаёт выдуманных стартов/остановок.

Для участия в АВТО добавить RO R720..723 только в отдельный review OPC-профиль
из прежнего `oshsky_r3_review_only.mbp`; кандидаты в
`additional-readonly-tags.json`. Actual allocation/типы/freshness сверить;
профиль не устанавливать на рабочем сервере. Это не новые команды/признак
физического монтажа/готовности. Остальные параметры каскада/ручные частоты RO.

## 3. Согласовать оформление и все входы на станцию

Сохранить одобренные **верхние native-вкладки**, тёмную палитру/Segoe UI и
штатный trend viewer. Белые цифры — показания, голубые — действительно
редактируемые, серые — запрещённый ввод, янтарный — активный отсчёт.
У подписей/цифр прозрачный фон; общая карточка единая, без индивидуальных
плашек/рамок. Шрифты/зазоры проверить в native масштабе, не только в Editor zoom.
Уставка заметнее задания ведомых; длинные причины не накладываются на числа.

Выбрать один канонический экран станции. Обычный переход из обзора,
нативная вкладка и отдельное окно показывают одни четыре актуальные карточки,
а не старый статический PageProcess параллельно с PageR3Observation.
Сохранить рабочие ссылки/возвраты/контекст станции, насоса, периода.
Не возвращать левый дублирующий sidebar или кнопку текущей страницы.

Существующий pressure draft/client/user/owner остаётся единственным.
Показать черновик, действующее значение и стадии ожидания PLC-echo/ПЧ.
Изменение селектора/пользователя/базы отменяет недействительный draft;
переходы10↔11↔12 не отменяют его сами по себе. R2100 остаётся единственным
существующим RW: без новых SCADA Пуск/Стоп/Reset/записи active presets,
автоповтора/отката/записи на открытии страницы или восстановлении связи.

## 4. Графики и история

Сохранить работающие native PV/SP в барах и F в Гц. Добавить выбор насосов1–4
с независимыми производными архивными рядами F; токи четырёх — отдельная
группа в амперах. Не менять источник общего F1 ряда при выборе насоса:
иначе смешается история разных насосов. Не рисовать три единицы на одной
шкале. Выбор насоса/период1/6/24ч/возврат не теряется, Client-контекст
не подменяется общим пользовательским состоянием другого диспетчера.

Кнопки карточек ведут к реальному native-архиву с station/pump filter.
Для аварии показать причину, фактическое время/ack/снятие при наличии данных
и действие персонала из проверенной инструкции. Модель РКФ Ошского сначала
сверить с документами шкафа: CHINT XJ3-D подтверждён для Бабанова, не автоматически
для Ошского. При отсутствии памятки честное «инструкция не привязана».
Сессионная лента не заменяет устойчивый архив и не получает фальшивые старые записи.

## 2. Воспроизведение и исправление переходов

- В Editor проверить реальную OnClick-привязку по имени, не только визуальный
  фокус объекта. Если неверны ID/скрипт/flags, исправить только найденные связки
  и сохранить воспроизводимую поправку генератора/валидатора в репозитории.
- Если связки правильны, сначала установить, вызывается ли сам обработчик:
  после backup11 временно добавить в **один неработающий новый OnClick** видимый
  диагностический текст этой кнопки/отдельного UI-поля. Не менять ProcessMainScope
  или состояние запроса уставки и не генерировать фиктивную аварию/сброс.
  Диагностика: факт вызова, пустой/непустой GetClientName, запрошенная цель и
  точная ошибка. Имя пользователя/секреты в публичный отчёт не включать.
- Захватывать GetClientName непосредственно в OnClick перед передачей в общий
  модуль, как у уже работающего UiOpenWindow и исходных кнопок уставки.
  Не подставлять вымышленный клиент/пользователя и не убирать авторизацию.
  Подтверждённый пустой клиент отличать от неверной привязки/ненажатия.
- Проверить реальное попадание mouse down/up по текущему объекту: foreground
  окна, его MSAA/UIA/экранный прямоугольник и DPI/масштаб. Фокус/наведение не
  равно выполненному OnClick. Не использовать прежние координаты другой страницы.
- При доказанном вызове с правильным клиентом сравнить переход с работающей
  штатной кнопкой. Использовать документированные GoToMessagesGroupClient
  (MSGG_ACTIVE/UNCONFIRMED/ALL/ACTIONS) и GoToTrendsClient/GroupClient; не угадывать
  группу по позиции и не объявлять права причиной без сообщения/проверки.
- После исправления убрать временную диагностику, штатно сохранить и Compile All.
  Выполнить точечную регрессию: существующие карточка/окно и +/−/Отмена, без Apply.
  Нативные изменения сохранить в воспроизводимых исходниках/проверках, не только
  в приватном бинарном проекте. Исходные профили и настроенный архив не затирать.

## 3. Вёрстка и действительные шкалы

Сначала измерить native рабочую область/верхнюю панель/масштаб проекта и окна
Client. Заголовки вынести из перекрытия, фон растянуть на рабочую область без
серого пустого поля. Для недостоверного давления допустима короткая надпись
«Нет данных» с полной причиной рядом; не обрезать её и не подменять нулём.
Не менять масштаб первичных данных или профиль записи ради вёрстки.

В нативном Editor/руководстве установить, где задаётся **числовая** шкала группы
трендов и где только процентное расположение. Текущая0–100% панель и raw400
не являются графиком4.00бар. При поддерживаемом независимом отображении задать
давление/уставку raw/100, частоту/ток raw/10 в раздельных шкалах. Иначе минимум
исправить числовой RAW-диапазон (вмещающий400), оставить явную легенду RAW/divisor
и описать неподтверждённое преобразование. Не менять command/адреса/
DecimalOffset/множители и не перемасштабировать старую историю незаметно.

SQL уже подтвердил архивные точки после flush: SP16×400, SourceOK/frequency/
current по16×0, Alive287. Пустая линия до flush не означает отсутствия записи;
проверить диапазон времени/числовую шкалу/буферы прежде нового setup БД.
Нужны видимость сохранённых точек, периоды1/6/24ч и курсор с верным временем/
единицами. Native q/flags не приравнивать к OPC192 без документированного
декодирования. PressurePV по-прежнему не подключать без исторической маски
SourceOK/свежести. Физический BAD/отключение связи в этом UI-задании не нужны.

# «Ошский»: короткая приёмка исправления на27.11.2026

**Новое стендовое замечание27.11:** после подключения physicalHMI мигают
данные насоса1, а собственная ошибка ПЧ не показана; релеПЧ/датчик отсутствуют.
Сначала [исправить и проверить живой тракт](oshsky-live-pump1-data-and-native-fault-local-20261127.md).
Ни прежний STOP-кадр, ни TEST_ONLY не закрывают этот новый дефект.

На 27.11 проверены ПЛК r3f, HMI r3h и отдельная SCADA r4a. Файлы, контрольные суммы и четыре прямых чтения FBs приведены в [стендовом протоколе](../reports/oshsky-finish-gsm-r3f-local-20261127.md). Рабочие полевые параметры сохранить до любых обновлений. На стенде уставка 4.10 бар и активные выдержки 10/10 с. Их перенос в шкаф не предусмотрен.

[Исходное наблюдение пользователя](../reports/oshsky-physical-hmi-user-check-20261126.md) и [предыдущий этап r3/r3d](../reports/oshsky-live-bench-20261126.md) сохранены для сравнения. Исполнительная схема, полевые параметры четырёх ПЧ и принадлежность GSM-маршрута требуют сверки на месте.

1. Сверить объект/моделиM900G/PLC/HMI, имена и SHA файлов с итоговым manifest.
   Записать установленную версию и сохранить программу/полевые параметры
   перед обновлением. Стендовый AC590/1насос/TEST_ONLY не переносить.
2. При загрузке соблюдать фактическую процедуру сохранения рабочих данных:
   не затирать retained настройки заводским/стендовым data image. Если PLC
   не менялся, необходимость его повторной загрузки определить по сравнению.
3. До команды пуска прочитать direct/alias: R2509=27401/R3120=27402,
   движение R2508/R3125/R2840 двумя наблюдениями2–3с. В диагностике видны
   actual RTC/call/freshness. Правильный marker без движения не PASS.
4. Проверить0.0А на достоверно опрошенном остановленном ПЧ, собственныеQ,
   активные новые выдержки3/4 и отсутствие ложного полного ACK при unknown.
   Токи/параметры не должны требовать переключения вAUTO для чтения.
   Отдельно при штатном AUTO-ожидании проверить обе строки Main: до запуска
   и до остановки ведомого, физический номер/уменьшение остатка/исчезновение
   при завершении или отмене. Пользователь сообщил отсутствие обоих отсчётов;
   успешный STOP-check/видимые preset не закрывают этот пункт.
5. При штатной работе по процедуре оператора сопоставить показание тока
   конкретного M900G с raw PLC и HMI, затем остальные реально доступные
   приводы. Работу с двигателем/нагрузкой AC590-бенч не подтверждал.
   Проверить смену кадров вентилятора именно своего работающего насоса,
   включая4, остановку при нулевой частоте и unknown. Один зелёный цвет
   и надпись «Работа» не подтверждают вращение анимации.
6. Зафиксировать режимную ошибку только при естественном событии: адресат/
   запрос/успешный ответ/WR и сохранённые коды одного цикла; не определять
   виновника по суффиксу«(2)» или старому D232. Ошибку не маскировать reset.

Записать время/номернасоса/источник/PASS-FAIL-not-tested. GSM/OPC/SCADA,
квитирование/архивные разрывы остаются отдельными пунктами по фактической
доступности. Лист не даёт автоматических команд полю; этапы обновления и
работы выполняются пользователем с оператором по условиям на объекте.

Отдельная приёмка звука: mute непрерывно активных аварий не истекает по
времени. Если звук вернулся без новой строкиHAD — сохранить first-rearm
контекст PLC/CL50 generation/маски/новый бит, запуски PLC/HMI и состояние
звуковых outputs. Краткий PLC-бит мог не попасть в периодический HMI-журнал.
Новые настоящие аварии должны сохранять оповещение; отсутствие самой CL50
на столе не подтверждает физическую работу внешней сирены на объекте.

# Найти и исправить связь анимации первого с запуском третьего

**Дополнение пользователя после публикации исходного задания:** включает
**только третий** ПЧ, а анимация и индикатор состояния срабатывают у **первого**.
Это отдельный опыт, не только прежняя последовательность1→2→3. В первую
очередь проследить соответствие3→1 через прямые частоту/quality PLC,
реальные native input aliases, выходы LW и адреса виджетов. Перестановка
каналов теперь сильнее подтверждается поведением, но точный участок ещё
не установлен; не чинить неизвестный сдвиг массива по предположению.
В исправленной версии «только3» должен менять ротор/статус3, сохраняя1
в состоянии, соответствующем его собственной обратной связи.

Продолжение текущего пользовательского проекта после native ремонта журнала.
Пользователь уже загрузил HMI и сообщил, что журнал работает. Сохранить
именно его native редакцию с новым HAD; старые r8/r11/r12 генераторы не
запускать поверх неё. Предыдущая приёмка журнала остаётся актуальной,
но не повторять создание объекта/снимки пустой таблицы ради этой задачи.

## Новый сценарий на реальном шкафу

MANUAL: при работе только ПЧ1 шкала меняется, но статус1 «Остановлен» и
ротор серый. После добавления2 у2 «Нет данных». После добавления3 у1
начинается анимация и статус «Работа». Всем задано25Гц, фактически сами
ПЧ показывают25Гц. Цифра actual на сенсорном HMI отдельно не установлена;
не выдавать уставку за обратную связь. Это новые наблюдения текущей HMI,
не старые фото1000298229/8230. Загруженные SHA пока не установлены.

Сначала найти конкретное ошибочное соответствие/участок, затем узко исправить
отдельную копию. Статус «Остановлен» в известном C требует внутри макроса
frequency0/quality1. Если прямой actual R2500 уже положительный, такой статус
наводит на расхождение macro input/output/binding; это ещё не доказанный
сдвиг массива. Не заменять достоверность частоты командой RUN/уставкой,
не связывать анимацию с давлением и не увеличивать watchdog наугад.

## 1. Сначала фактически скомпилированные переменные HMI

Установить пути/SHA текущего сохранённого SKM с новым HAD, PDW и последнего
скомпилированного image. Native-сохранения/буферы/сборочные артефакты сохранить.
Последний native файл предпочтителен; имя ...base.skm само по себе не означает,
что файл всё ещё пустой. Нельзя копировать прежнюю основу поверх него.

Из доступных **артефактов последнего настоящего Compile** получить C/H
с объявлениями входов: конкретный Macro*.c, MacroInit.h, VarSetting.h либо
соответствующие файлы установленной версии. В некоторых поставках aliases
добавляются в .c, а не в общий MacroInit.h. Поиск вести в установленном
SKTool/Marco/*/bin и известных output-папках; выбрать файл, содержащий именно
PumpAnimation/PumpAnimTelemetry текущего проекта, сверить время/содержимое.
Пустой VarSetting.h, vendor-пример или остаток другого проекта не принимать
за результат нужной компиляции. Сначала сохранить найденные артефакты,
не перезапускать чужие компиляции и не терять исходное свидетельство.

Сопоставить нативные Variable settings и реально сгенерированные aliases:

| Имя | Ожидаемый PLC вход | Формат / используемая часть |
|---|---|---|
| AlarmWords | R2550..2554 | Batch UInt16,10bytes; map=элемент4 |
| MapVersion | R2554 | исходный UInt16 alias; C переопределяет через AlarmWords[4] |
| BootAck | R2553 | существующий write UInt16; не смешать со следующими входами |
| PumpAnimTelemetry | R2500..2512 | Batch UInt16,26bytes; freq[0..2],quality[10..12] |
| PumpAnimRoles | R2320..2326 | Batch UInt16,14bytes |
| PumpAnimManual | R2380..2382 | Batch UInt16,6bytes |
| PumpAnimLeader | R2304 | UInt16 |

В отчёт достаточно собственных имён/типов/PLC адресов/размеров/pVar offsets
и признака соответствия. Проверить порядок, реальную семантику batch size,
шаг16-bit элемента, границы/перекрытия и скалярные write/read поля. Не
угадывать смещения по сумме размеров и не переносить их из host IN. Сверить
оба C mirror в SKM и реально скомпилированный источник с panel-services-r8.
Проверить все записи в LW900..908 из остальных макросов/объектов: нет ли
перезаписи/общего адреса. Нативный тип/привязки новых HAD к этому не менять.

## 2. Связать входы макроса с виджетами

| Насос | Прямой actual | Quality | Частота в сыром PLC буфере | Ротор / статус |
|---|---|---|---|---|
| 1 | R2500 | R2510 | R2803 | LW900 / LW903 |
| 2 | R2501 | R2511 | R2811 | LW901 / LW904 |
| 3 | R2502 | R2512 | R2819 | LW902 / LW905 |

В известном проекте роторам соответствуют MD70010/11/12, статусам
MD10004/18/32; шкалы BG10012/26/40. Проверить фактические native descriptors,
индексы состояний и адреса **текущей** сборки, а не только наличие QString.
Состояния:0 нет данных,1 остановлен,2 работает,3 подготовка,4 ПЧ не готов.

Для live сравнения нужны эти прямые значения, **реально увиденные** макросом
freq/quality и LW900..905 в одной временной привязке; дополнительно карта
R2554, слово аварий R2550 и связь LB60107. Пуски1→2→3 одновременно увеличивают
прошедшее время: не считать перестановку доказанной по единственной такой
последовательности. В наблюдении отделить позднее обновление первого от
изменения его входов именно вслед за третьим. Если текущая HMI их не показывает,
подготовить отдельную read-only диагностическую копию/страницу с подписью
каждого поля. Не подменять рабочие настройки этими адресами и не загружать
диагностическую копию автоматически. Новую рабочую таблицу аварий сохранить.
Если GUI или live недоступны, всё равно закончить файловую проверку пункта1
и дать ОДИН следующий шаг, который различит оставшиеся ветки. Повторный
запуск с Tips/невидимым Simulator, переустановка и массовое закрытие окон
не помогают получить эти данные; их не повторять.

ПК и HMI используют общий FATEK Port0. Не запускать конкурирующий master,
не переключать кабели автоматически. Последовательные PLC/HMI снимки
не выдавать за одновременные. Запусками шкафа управляет пользователь.

## 3. Исправление определяется результатом

- Прямой R2500>0, а macro freq1=0/данные следуют за3: исправить подтверждённые
  адреса/типы/пакет/aliases чтения. Не лечить это новым поллингом PLC.
- Входы правильные, LW outputs неверны: найти конфликт/ошибку текущего macro
  source и его исполнения. Host C с придуманным IN не доказывает native ABI.
- LW903=2 и LW900 меняется1..4, но виджет остаётся серым/«Остановлен»:
  исправить его реальную привязку/state table/resource в текущей HMI.
- Если quality0/неверный actual формируются уже в PLC, взять трассу кэша
  M1748..1750, M1744..1746, T92..94, M601/602, D300/301 и приёмов частоты.
  Измерить успешные выборки/ошибки/интервалы. У известного r10 ROM R5000
  всё ещё18строк; рабочий FUN150 SR переключён на RAM таблицу14строк
  (инициализация сети10.N3...), частотные индексы0/3/13. Не объявлять
  ROM-шаблон причиной и не менять индекс13на16 без проверки фактического SR.
  D300 low byte=transaction, high byte=result; D301 high=station,low=function.

Исходники сохранить, исправление — отдельный кандидат, без возврата старых
HAD/четвёртого насоса. Сохранить каскад8строк, две **независимые** задержки
(вторая может быть меньше/равна первой), ручной режим без датчиков давления,
защиты/таймеры. Аппаратные Download/Force/RUN и параметрыПЧ не выполнять.

## 4. Приёмка независимости

В изолированной offline проверке исправленного соответствия использовать
разные частоты, например25/30/35Гц, и8сочетаний включения трёх насосов:
ни одного, каждый отдельно, каждая пара, все3. Для исправного остановленного
freq0/quality1; для работы quality2 и соответствующая собственная частота.
Каждый ротор/статус должен следовать только своей обратной связи; запуск3
не меняет1 при неизменных данных1. При качестве0 — «Нет данных»/неподвижный
ротор. Отсутствие датчиков давления2/3 не должно мешать анимации частоты.
Отдельно проверить смену/снятие own-run, READY/link и возврат данных.
Проверку с реальным generated C/заголовками и проверку на настоящей панели
разделить; одинаковые25Гц всем хуже выявляют перестановку индексов.

Выдать точное место ошибки/её доказательство, изменённые файлы/объекты,
полные Windows-пути/размеры/SHA кандидатов/отчётов и результаты фактических
проверок. Если ещё нет доказательства — назвать недостающую пару значений,
а не объявлять анимацию исправленной. Краткую сводку опубликовать в рабочую
handoff-ветку, main не менять; полные native-проекты/vendor binaries/сырые
логи/фото/секреты в публичный Git не добавлять.

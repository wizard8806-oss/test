## 1. Доказать загрузку диагностической версии

Сохранение/Compile All в Editor само по себе не подтверждает загрузку этой
версии Server. Выбрать новый уникальный идентификатор вместо `UINAV11-P1`
во всех метках ниже. Перед тестом установить реальный путь Server-log.txt,
зафиксировать его позицию/время; читать только новые строки своих меток,
полный журнал/пути/имена клиентов публично не публиковать.

В **OperatorConsole**, в существующую секцию глобальных переменных временно
добавить `UiProbeBootSent: Boolean;`. В начало OperatorUiUpdate добавить:

```pascal
if not UiProbeBootSent then
begin
  Log_Add('[UINAV11-P1] BOOT', True);
  UiProbeBootSent := True;
end;
```

Это один лог на экземпляр модуля, без изменения таймера или данных станции.
Использовать именно **Log_Add**: название `LogAdd` в строке синтаксиса
справки ошибочно; пример и встроенная декларация Editor2.6.15
содержат `procedure Log_Add(const AMessage: string; ATimings: Boolean = TRUE);`.
Облачная сверка символа не заменяет native Compile All.

Подготовить также обработчик из раздела2. После этого сохранить, выполнить
Compile All и штатно загрузить кандидат, убедиться,
что активна ровно11, Client подключён к ней. Дождаться **новой BOOT-метки
этого уникального опыта**. Если её нет, сначала установить загруженный путь,
версию/ошибку Server и вызов OperatorUiUpdate: клики пока неинформативны.
Не маскировать эту ситуацию сменой прав, именем вымышленного клиента или БД.

## 2. Отделить вход в OnClick от навигации

Временно заменить только `UiOverview0Nav1_OnClick` следующим телом;
проверить в Editor его реальную привязку. Не использовать тип `Exception`,
не поддержанный прошлой native-компиляцией; общий except не требует типа.

```pascal
var aClient: string;
begin
  Log_Add('[UINAV11-P1] ENTER UiOverview0Nav1', True);
  UiOverview0Heading.Text := 'Проверка: обработчик вызван';
  aClient := GetClientName;
  if aClient = '' then
  begin
    Log_Add('[UINAV11-P1] CLIENT_EMPTY', True);
    Exit;
  end;
  Log_Add('[UINAV11-P1] CLIENT_PRESENT', True);
  if GetPageByName('PageUiAlarms') = nil then
  begin
    Log_Add('[UINAV11-P1] TARGET_MISSING', True);
    Exit;
  end;
  try
    Log_Add('[UINAV11-P1] BEFORE_HELPER', True);
    UiGoPage('PageUiAlarms', aClient);
    Log_Add('[UINAV11-P1] AFTER_HELPER', True);
  except
    Log_Add('[UINAV11-P1] EXCEPTION', True);
  end;
end.
```

BOOT и обработчик должны попасть в **одно** сохранение/Compile All/загрузку.
Снять фактические foreground/DPI/видимую область, один mouse down/up по кнопке
и новые строки журнала. Рамка фокуса не является ENTER. Заголовок не относится
к таймерным полям состояния; ProcessMainScope и командный черновик не менять.
Логировать только наличие клиента, не само имя/пользователя/секрет.

- BOOT есть, ENTER нет: доставка события ещё не доказана. Сначала подтвердить
  работающий UI-only обработчик этой же загруженной версии. Для сравнения
  допустимо временно в новый `UiMainOpenWindow_OnClick` добавить свою
  DRIVER_ENTER-метку и вызвать `UiOverview0Nav1.OnClickEvent;` вместо открытия
  окна. Метод документирован и зарегистрирован в Editor. Нативный переход
  на исходную страницу — штатной навигацией; не старыми координатами.
  Это программный вызов события для сравнения, **не доказательство работы мыши**.
  Отсутствие обеих меток — основание проверить runtime/журнал, а не права.
- ENTER/CLIENT_EMPTY: зафиксировать пустой реальный клиент; настройки/имя
  клиента уже исправлялись раньше. Не подставлять имя и не снимать проверки.
- TARGET_MISSING: сравнить реально загруженные страницы/имя, не генерировать
  их заново из10 по предположению.
- AFTER_HELPER есть, перехода нет: при новом BOOT-ID сравнить прямой
  документированный `PageUiAlarms.GoToPageClient(aClient);` с UiGoPage.
  Если появился EXCEPTION — сохранить точное native сообщение/стек только
  доступными штатными средствами, без дампа памяти или секретов.

Не менять сразу геометрию, метаданные и навигационный API: это скроет причину.
Изменение проверять по одной установленной гипотезе. При конкретной ошибке
внести воспроизводимую поправку исходника/генератора и подходящую регрессию.
Если причина снова не установлена, описать полученные BOOT/ENTER/ветки и
ограничение; не сообщать об исправлении и не повторять тот же опыт вслепую.

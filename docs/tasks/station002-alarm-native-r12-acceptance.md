# Принять новый native журнал r12 и проверить записи

Продолжение пользовательского ремонта HMI, без нового PLC или генерации
ещё одной таблицы. Пользователь уже вручную создал **новый** History Alarm
через Tool Box → Function elements → Display; ID в диалоге HAD1794244624.
На Screen9 он виден в редакторе **и Offline Simulator**: три колонки
«Время / Дата / События», шесть строк, таблица помещается. Эти проверки
засчитать по снимкам пользователя; снова просить пустую сетку не нужно.
Старый HAD8288 редактор зависал; не восстанавливать его и не запускать
генераторы r8/r9/r11/r12 поверх пользовательских правок.

## Сначала сохранить текущую работу

Рабочая папка Windows:
`C:\Users\user\CodexProjects\pump-station\.worktrees\station002-alarm-rebuild-local-12\`.

На последнем снимке title по-прежнему содержит
`pump_station_3p_alarm_rebuild_r12_base.skm`. Пользователь получил инструкцию
сохранить отдельный `pump_station_3p_alarm_r12_native.skm`. Проверить оба
пути и текущие дисковые файлы, не предполагая, что SaveAs уже выполнен.
Сначала зафиксировать фактические размер/SHA, сохранить отдельную резервную
копию найденного файла с новым HAD. Старый SHA e5ae403…64606a относится
только к основе БЕЗ таблицы; не требовать его от пользовательской редакции.

Если на диске только неизменённая основа и нового объекта нет, текущая
работа, вероятно, ещё в открытом SKTool. Дать один конкретный шаг оператору:
закрыть только свой Simulator и File → Save As в native-файл выше. Не убивать
SKTool, не перезаписывать текущий буфер генератором и не копировать пустую
основу под видом готового native-файла. Если отдельный native-файл уже есть,
принять его; если новый HAD сохранён под именем base, сохранить именно эту
редакцию отдельной копией, без потери/замены исходной текущей работы.

## Приёмка сохранённого проекта

1. Прочитать новый объект и свойства: Rows6, Reverse, Time/Date/Select all
   alarm content включены, Clear Alarm Date/Time выключены. В языке Chinese
   введены русские заголовки; этот язык проекта не менять автоматически.
   Visibility: By Bit/User Level/Permission/Logic/Word control выключены.
   Проверить итоговый цвет активного текста (ранее ещё был чёрный, дана
   инструкция выбрать красный), зелёный для восстановления. Заголовки/шрифт
   и колонку «События» оценивать на двух длинных реальных текстах.
2. Проверить сохранность существующих Digital/Analog alarm definitions B00,
   их адресов, всех макросов, карты аварий32, каскада8строк/двух независимых
   задержек и ручного режима. Источники прежней r12 основы/точного r11 доступны
   в предыдущем локальном пакете. Нативный SaveAs может пересериализовать
   служебные поля; любое отличие байт не считать автоматически потерей логики.
   Не ослаблять source-lock старых генераторов ради этой новой редакции.
3. Кнопка «Сохранить журнал» ранее привязана к LB60123. Проверить её native
   действие на текущем сохранённом проекте и по установленной версии SKTool.
   Не переназначать на ID нового HAD или HADStation без подтверждения, что
   это требуется форматом. Экспорт/файл на носителе считать проверенным
   только после фактического получения и чтения результата; аппаратный
   экспорт сейчас не наблюдался. Сохранность привязки не равна тесту экспорта.
4. Через доступный штатный GUI: открыть сохранённый native-файл заново,
   Screen9 → другой экран → Screen9, свойства нового объекта; выполнить
   Compile, зафиксировать результат/путь image и затем Simulator. Уже
   показанный Simulator из пользовательского буфера не заменяет reopen.
   Не повторять неудачные CLI-запуски с Tips/сразу закрывающимся Simulator,
   не переустанавливать редактор и не завершать чужие процессы по маске.
   Если CLI опять не имеет доступа к GUI, выполнить доступную файловую
   приёмку, записать ограничение и дать оператору один конкретный оставшийся
   GUI-шаг вместо повторной генерации или неподтверждённого native PASS.
5. Проверка записей — в **отдельной временной offline-копии** проекта:
   безопасным штатным средством симулятора вызвать две длинные записи,
   затем восстановить одну. Если для этого нужны тестовые alarm definitions
   с локальными битами и кнопками, выбрать подтверждённо свободные адреса
   после проверки использования и добавить их только в тестовую копию
   через штатный редактор. Тестовая копия не подключается к реальному PLC
   и не становится рабочим native-файлом. Проверить оба текста/порядок
   последних записей/цвет восстановления/прокрутку. Не форсировать PLC-входы,
   не обходить карту в рабочем макросе и не имитировать аварии питания или
   сухого хода на реальном оборудовании ради проверки таблицы.

Отчёт: фактические Windows-пути принятого native SKM/резервной копии/image,
их размер/SHA, ID нового HAD, что подтверждено пользователем и что сделано
самим CLI, результаты файловой приёмки и каждой доступной native проверки.
Не объявлять два сообщения/экспорт/звук проверенными по пустой таблице.
Краткий статус опубликовать в рабочей handoff-ветке, main не менять; полные
проекты, vendor binaries, сырые логи/снимки и секреты в Git не добавлять.
HMI на аппаратную панель, PLC и параметры ПЧ этим заданием не загружать
и не менять; аппаратные Download/Force/RUN не выполнять.

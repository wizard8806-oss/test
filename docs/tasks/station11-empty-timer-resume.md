# Продолжить ввод таймера из сохранённой модели Editor

**Результат принят 05.11:** сводка `830b298` подтвердила импорт, native
Compile/Save, запуск копии и видимые три ряда с архивом. Следующее задание —
[качество и свежесть работающего графика](station11-trend-quality-acceptance.md).
Пустой таймер ниже — история; повторный импорт не нужен без нового дефекта.

04.11.2026 МСК. Пользователь показал Script_49 с пустым `begin … end.` и
несохранённые Script_48/49. Это состояние буфера на снимке, не доказательство
содержимого дисковых Scripts.ssc. В публичном `d813ecf` есть только preflight-
сводка; фактический подготовленный код таймера/модуля остаётся локально.

Продолжить существующую задачу трёх рядов штатного графика, не создавать
проект/переменные/модули заново и не повторять неподтверждённый ввод текста
через координаты/клавиатуру. Если после снимка ввод уже завершён, сохранить
и проверить актуальный результат; не возвращать его к пустому скелету.

## Сохранить и установить фактический источник

1. Найти существующее окно Editor и текущую модель. Сохранить **новую
   приватную копию модели** штатным Save As, явно пометив её UNVERIFIED.
   Оба несохранённых скрипта сохранить вместе с остальным проектом. Исходник,
   рабочую R2 и уже подготовленные материалы не перезаписывать. Если канал
   GUI снова мешает, попросить оператора только выполнить этот конкретный
   Save As/открыть нужное окно, продолжая независимое чтение файлов.
2. Из сохранённой копии прочитать Scripts.ssc через bounded parser. Установить
   точные ID/имена Script_48/49, тела, тип события и включённость таймера по
   фактическим native-свойствам. Номер в имени не считать гарантией ID.
   Снять SHA Pages/Scripts и приватную инвентаризацию; новый класс графика
   не подавать в старый Text-only page parser.
3. Найти подготовленный код в своих местных артефактах. Проверить модуль48
   и точную процедуру, которую должен вызывать таймер. Шапка
   `procedure Script_49(Sender: TM_Control);`, показанная Editor, не является
   частью event-body для файлового импорта. Не подставлять имя процедуры из
   синтетического теста импортёра. Если модуль48 ещё пуст/неполон, сначала
   закончить и проверить его в отдельном source; одним заполнением49 это
   не исправить.
4. Проверить код под Simple-Scada2.6.15: производитель данных обновляет
   только свои внутренние переменные представления по уникальным именам.
   Исходные OPC-переменные/команды не изменяются. Три ряда — давление PV,
   действующая уставка SP и фактическая частота. PV/SP raw/100, частота raw/10;
   PV требует GOOD, SourceOK=1 и свежего ПЛК. Пропуски/архивирование нужно
   доказать в native, не выдумывать поддержку NaN или setter качества.

## Если сохранённый таймер всё ещё пуст

Готов `tools/import_native_empty_timer.py`. Он принимает проверенный UTF-8
файл **тела события**, реальные ID/имя и три SHA. Патчит только пустой
`begin … end.`; заполненный/неожиданный скрипт отклоняет. Остальные записи
Scripts.ssc сохраняются побайтно, ID/metadata целевого скрипта не меняются.
Pages.spg и другие native-ресурсы копируются как непрозрачные данные, поэтому
новые штатные классы не теряются. Сохранённый источник остаётся неизменным,
старый bytecode исключается. Защита новой приватной папки устанавливается
до копирования. Инструмент не запускает Editor, Server или код события.

CLI сам устанавливает переменные по своим проверенным местным файлам:

```powershell
python -I -B tools/import_native_empty_timer.py `
  --project $timerSavedSource --out $timerImportCopy `
  --payload $timerReviewedBodyFile `
  --script-id $timerNativeId --script-name $timerNativeName `
  --expected-pages-sha $timerPagesSha `
  --expected-scripts-sha $timerScriptsSha `
  --expected-payload-sha $timerBodySha
```

Это схема вызова, не заполненные пути/хеши. Назначение — новый
`codex_diag_11_trend_timer_<уникальный суффикс>` вне исходника и Git.
Payload должен содержать `begin … end.` либо `var … begin … end.`, без
`unit`/`procedure`-шапки. Поддерживается сохранённый формат2.6.15 без папок
скриптов. При отказе не снимать guard и не редактировать байты metadata;
установить фактическое отличие, сохранив source.

## Native-проверка и продолжение графика

Открыть новую импортированную копию штатно, проверить непустое тело49 и
совпадение нетронутого48 с сохранённым source. Проверить реальный тип/период/
включённость таймера штатными свойствами. Выполнить Compile All; при ошибке
зафиксировать точные имя/строку/сообщение и исправить source, а не повторять
неподтверждённый ввод. Save, прочитать итоговый Scripts.ssc, сравнить тела и
классифицировать изменённые native metadata; сам Save не доказывает исполнение.

Затем в рамках уже разрешённых программных переключений проверить единственный
нужный проект в Server/Client, выполнение таймера и три внутренних ряда.
Без Apply/пусков/сбросов ради UI. Продолжить
[штатный график давления, уставки и частоты](station11-native-trend-viewer.md):
две физические шкалы, настоящие архивные точки, качество/свежесть и периоды.
Не остановиться на одном факте успешной вставки или компиляции.

Подробные source/SHA/журналы/снимки хранить локально. Публично — согласованная
краткая сводка и отдельно проверенные исходники/тесты; частный native-проект
не публиковать. Сохранять местные изменения; main не менять. Если конкретное
действие отклонит автоматическая проверка, сохранить причину, не обходить её
другим API и завершить доступную часть.

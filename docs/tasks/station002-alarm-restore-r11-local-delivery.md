# r11: восстановить таблицу и закончить native подгонку в SKTool

У пользователя уже открыт r10 в SKTool/Offline Simulator. На новом снимке
`station002-cascade-local-10/pump_station_3p_cascade_r10_candidate.skm`
«Аварии и история» по-прежнему не имеет даже рамки/заголовков/сетки.
Это наблюдаемый отказ отображения r10. Одиночная правка36 в r9/r10
оказалась недостаточной. Не просить пользователя снова проверять тот же
неизменённый r10 и не объяснять исчезновение сетки только offline-map0.

Сейчас задача HMI-only. Восемь настроек каскада, независимость задержек,
ручной режим, макросы/анимации/определения аварий и PLC r10 сохранить.
Предыдущая файловая сборка r10 уже выполнена: не начинать заново перенос
CPU/создание PLC. WinProLadder на фото виден позади консоли; пустой список
процессов в CLI не доказывает его отсутствия. Редакторы не переустанавливать.

1. Получить `artifacts/station002-alarm-restore-r11/delivery-manifest.json`
   из того же pinned-коммита, что это задание. Скачать files[] по rawBase
   и проверить размеры/SHA. Достаточно Python3stdlib, без установки DLL/pip.
2. Новая обычная папка:
   `C:\Users\user\CodexProjects\pump-station\.worktrees\station002-alarm-restore-local-11\`.
   Source — точный уже созданный r10:
   `C:\Users\user\CodexProjects\pump-station\.worktrees\station002-cascade-local-10\pump_station_3p_cascade_r10_candidate.skm`.
   1287912байт,SHA e7752b52bfbbc9e74f04391aa0aa9ffc09e9437cc189d55632a41401495c76f4.
   Текущий native-save/несохранённые изменения сохранить отдельно. Если
   source изменён, найти прежний exact-кандидат по отчёту, не ослаблять guard
   и не уничтожать пользовательские правки.
3. С сохранением структуры tools создать готовую восстановительную копию:

```text
python -S -B tools/restore_alarm_widget_r11.py --source "ПОЛНЫЙ_ПУТЬ_К_R10.skm" --out pump_station_3p_alarm_restore_r11_candidate.skm --report hmi-r11-restore.json
python -S -B tools/validate_alarm_restore_r11.py --source "ПОЛНЫЙ_ПУТЬ_К_R10.skm" --candidate pump_station_3p_alarm_restore_r11_candidate.skm --report hmi-r11-preservation.json
```

4. ВАЖНО: эта копия возвращает и исходные большие bounds976×360.
   Это не готовая подгонка под800×480 и ещё не результат native проверки.
   Не выдавать SHA/Compile/«старый объект восстановлен» за видимую таблицу.
5. В уже установленном интерактивном SKTool через File → Open открыть
   именно НОВЫЙ r11. Штатно Compile и Offline Simulator, открыть «Аварии».
   Даже при0 и без ПЛК проверить рамку/заголовки/сетку. Зафиксировать
   реальный вид; окон редактора/Simulator с чужими проектами не закрывать.
   Новый basename и новая папка исключают использование старого image/cache.
6. Если таблица появилась, закончить подгонку штатными свойствами SKTool,
   а не очередными неизвестными byte offsets. Закрыть только свой Simulator,
   на Screen9 выбрать HAD8288 и отредактировать его native свойства:
   - положение примерноX16/Y112, доступная область доY400, footer начинается438;
   - ширина в пределах768px с учётом рамки/scrollbar;
   - колонки «Время», «Дата», «Событие», «Снято (дата)», «Время снятия»
     должны помещаться. Отдать основную ширину событию; ориентир соответственно
     62/80/440/84/62px, всего728px, чтобы осталось место рамке/прокрутке;
   - подобрать число строк/шрифт/перенос текста нативно, чтобы длинные
     сообщения читались и минимум два сообщения помещались одновременно.
     При8строках в288px полезная высота около33px, но реальный размер
     определяет сам редактор: после изменения проверить Simulator.
   Сохранить отдельный `pump_station_3p_alarm_restore_r11_native_fit.skm`,
   вновь Compile/осмотреть «Аварии» и «Каскад» с8строками. Повторно не
   вводить сравнение второй задержки с первой: равная/меньшая разрешены.
7. Если даже с whole-original HAD таблицы нет, не объявлять успех.
   В native свойствах проверить Visible/common Visibility, тип alarm-history
   control, набор HADStation/существующие определения аварий, объект и
   реальный файл/scene, который компилируется. Сначала записать фактические
   значения свойств, затем исправлять отдельный native-save. Не переключать
   карту ПЛК/не переписывать макросы/не обходить защиты ради этой сетки.
8. Выдать абсолютные Windows-пути candidate/native-fit/compiled image и
   отчёта, размеры/SHA и отдельно реальные Compile/Simulator результаты.
   Если native GUI из CLI недоступен, всё равно создать готовый r11 и
   сообщить полный путь, а затем ОДНО точное действие оператора для
   недостающей проверки. Не повторять неудачный CLI-start с Tips и не
   заменять native-приёмку повторением хешей или переустановкой редактора.
   Оставить честный статус «native grid/fitting pending», пока не увидели.

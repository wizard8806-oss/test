# Собрать диагностическую HMI-копию для живой проверки анимации

Не повторять host-проверку старого C и общий просмотр bindings вместо сборки.
Эти проверки уже сделаны, но пользователь **включает только ПЧ3, а ротор/
«Работа» появляются у1**. Нужна отдельная HMI, на которой он сможет показать
значения из PLC и из реального макроса без переключения общего Port0 на ПК.

1. Скачать `artifacts/station002-animation-probe-r13/delivery-manifest.json`
   из того же pinned-коммита, что это задание. По rawBase получить5 files[],
   проверить bytes/SHA256. Это Python3stdlib; ПО/шрифты не устанавливать.
   Исходники закреплены к `98c79cb7f657f200cd3e4b6ce1021be4e4461866`.
2. Взять **пользовательский native с новой таблицей**, принятый предыдущим
   локальным заданием:

```text
C:\Users\user\CodexProjects\pump-station\.worktrees\station002-alarm-rebuild-local-12\pump_station_3p_alarm_r12_native.skm
```

   Ожидается1280596байт,SHA256
   `562b049266e9fb3ede17a870c928392f2ff008eed816463a075f9fd05ef54958`.
   Сначала сохранить backup и зафиксировать фактический SHA. Не заменять
   этот файл прежней пустой основой, не запускать восстановление HAD8288.
   Если текущая копия отличается, сохранить её и закончить узкую проверку
   структуры/своего C перед source-locked адаптацией; guard не убирать ради
   неизвестного файла. Допустима новая строгая адаптация к проверенному
   фактическому SHA с инверсией всех изменений; пользовательские правки
   сохранить. Временная недоступность GUI не мешает созданию отдельного SKM.
3. Новая папка:
   `C:\Users\user\CodexProjects\pump-station\.worktrees\station002-animation-probe-local-13\`.
   Выполнить из пакета (подставить полный source-путь выше):

```text
python -S -B tools/build_animation_probe_hmi.py --source "ПОЛНЫЙ_ПУТЬ_К_NATIVE_R12.skm" --macro assets/hmi/panel-services-r8/panel_services.c --out pump_station_3p_animation_probe_r13.skm --report animation-probe-build.json
python -S -B tools/validate_animation_probe_hmi.py --source "ПОЛНЫЙ_ПУТЬ_К_NATIVE_R12.skm" --candidate pump_station_3p_animation_probe_r13.skm --macro assets/hmi/panel-services-r8/panel_services.c --report animation-probe-preservation.json
```

   **Не использовать `--fixture-source`**: это только облачный тест на основе
   БЕЗ пользовательской таблицы, его результат не предназначен для панели.
   Не нужен `--host-check`/cc на Windows. Native target SHA должен быть
   получен фактической сборкой здесь; manifest намеренно не подставляет
   hash облачной фикстуры вместо native результата.
4. Builder временно заменяет Screen13 (историю запусков CPU) страницей из
   78объектов/31числового поля. Главная «Диагностика» ведёт в Screen13;
   две кнопки выхода сохранены. В этой временной копии «Запуски ПЛК» также
   открывает заменённый Screen13. Исходная рабочая HMI остаётся отдельной.
   Screen2..12, включая **новую пользовательскую таблицу Screen9**, сохранены
   точно. PLC/VarSettings/контроль/защиты/таймеры/каскад не меняются. Новых
   write inputs к PLC нет. В собственном C добавлены только snapshots в
   свободные локальные LW920..930; существующий BootAck остаётся прежним.
5. Через доступный штатный GUI открыть **именно новую** диагностическую
   копию, проверить Screen13. В свойствах двух полей первой строки подтвердить
   F ПЛК=FATEK R2500 и F макр.=локальный LW920, UInt16/read-only: probe сам
   не должен повторять ошибку привязки. Сохранить/reopen, настоящий Compile.
   Старую `.prjCompiled` от ...base не принимать за её сборку. Сохранить путь/
   SHA/date фактического image и C/H с текущими generated aliases. Если GUI
   опять недоступен из CLI — всё равно закончить SKM+validator и сообщить
   полный Windows-путь и один следующий шаг оператору: File→Open этого
   r13 файла и Compile. Не повторять Tips/невидимый Simulator, установку,
   массовое завершение SKTool или отчёт без созданного кандидата.
6. Страница показывает для каждого из3ПЧ:

| Поле | ПЧ1 | ПЧ2 | ПЧ3 |
|---|---|---|---|
| F ПЛК | R2500 | R2501 | R2502 |
| Q ПЛК | R2510 | R2511 | R2512 |
| F макр. | LW920 | LW921 | LW922 |
| Q макр. | LW923 | LW924 | LW925 |
| Кадр | LW900 | LW901 | LW902 |
| Статус | LW903 | LW904 | LW905 |
| RX F* | R2803 | R2811 | R2819 |
| Код* | R2801 | R2809 | R2817 |

   LW930 должен показывать **27119** — подпись реально исполняемого нового
   C; LW926 меняется. Рядом R2554/LW927 (обе карты32), R2550/LW928 (слова
   аварий), LW929 (связь HMI). Карты не менять на27119/27110. Частоты —
   сырые WORD (ожидаемо250=25Гц). Q:0 неизвестно,1 достоверный стоп,2 работа.
   Статус:0 нет данных,1 стоп,2 работа,3 подготовка,4 ПЧ не готов.
   Кадр0 неподвижен,1..4 — вращение. RX F*/Код* — **сырой буфер**, без
   утверждения его свежести; это не законченный вывод fault в рабочий журнал.
7. После native Compile оператор может выполнить живое наблюдение отдельной
   копии; сам CLI аппаратные Download/Force/RUN не делает. При работе только
   ПЧ3 получить снимок/короткое видео этой страницы с меняющимся «Снимок».
   Сравнивать устойчивые значения в течение15с: поля HMI обновляются
   асинхронно, один кадр не даёт атомарности. Запусками управляет пользователь;
   ПК не занимает Port0 параллельно панели. Не генерировать аварии/сбросы
   автоматически и не переподключать кабели вместо HMI наблюдения.
8. Ветвление: wrong R250x/R251x уже на странице — трасса upstream PLC/RX;
   direct PLC правильный, macro input чужой — native Variable settings/
   generated offsets/исполняемый C; входы правильные, LW неверны — код/
   перезапись LW; LW правильные, рисунок чужой — native виджет/ресурс/образ.
   Подпись не27119/счётчик не идёт — сначала подтвердить новый Compile/image
   и исполнение C. Не объявлять статические host-тесты решением live проблемы.
   У r10 **рабочая RAM R2900 содержит14строк**, ПЧ3 —13с0; ROM R5000 имеет
   старые18строк/ПЧ3строка17с1. Исполнение FUN150 проверять по фактическому SR.
9. Отдельно пользователь сообщил **A52** на ПЧ1. В используемом руководстве
   900G/900M ver1.26, PDFстр58: Err52(A52)=нехватка воды. Сырое R2801 ещё
   не измерено; не подставлять52 константой и не выдавать readiness за fault.
   Если ошибка ещё активна, поле «Код*» позволит записать значение для
   будущей правильной публикации/расшифровки. Настройки/перезапуски ПЧ не менять.

Результат: созданный diagnostic SKM/backup/отчёты с полными Windows-путями,
bytes/SHA, validator, фактические native результаты либо точный следующий
шаг оператору. Анимация ещё НЕ исправлена. Краткую сводку опубликовать в
рабочую handoff-ветку, main не менять. Полные native/vendor файлы, сырые
логи/снимки и секреты в публичный Git не добавлять.

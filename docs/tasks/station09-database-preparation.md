## 1. Проверить существующую установку СУБД

Чтением получить относящиеся к БД названия/версии установленных компонентов,
службы/их состояние и при наличии локальные слушающие порты/принадлежность
процессу. Сначала MySQL/MariaDB и порт3306 из показанной формы; MS SQL Server,
PostgreSQL и другие компоненты учитывать, если реально обнаружены.
Версия клиента Workbench/pgAdmin или наличие
DLL не доказывают установленный/работающий сервер. Running/listening тоже
не подтверждают доступ к схеме/учётке. Если сведений нет, записать именно это.

Использовать Get-Service/метаданные процессов/выбранные поля uninstall-
реестра/локальную таблицу TCP без подключения к портам. Не использовать
Win32_Product (может запускать восстановление MSI), команды запуска/
перезапуска служб, установщики или изменение firewall. Не печатать командные
строки/профили, содержащие учётные данные. Не опрашивать всю сеть/машины.

порт, состояние/ошибка подключения, очередь/пропущенные запросы если показаны.

необходимые поля;

Editor самостоятельно не запускать, F8/F9 не выполнять; рабочие файлы/
параметры не сохранять. Не нажимать «Проверить»/«Подключить» — это новая
сессия БД, не чтение существующего статуса. Прямое SQL/БД-подключение,

Если параметров нет в доступном интерфейсе, точно назвать непрочитанное;

## 3. Подготовить конкретное предложение, не применять

По фактам выбрать подходящий существующий сервер/версию либо обосновать
необходимость установки. Не предлагать новую СУБД только потому, что не
получилось прочитать UI. Указать подтверждённую совместимость с2.6.15.0;
общее текущее руководство и наличие провайдерной DLL сами по себе не
доказывают конкретную рабочую конфигурацию.

В предложении перечислить: выбранный engine/version/службу/локальность,
существующий или предлагаемый отдельный архив/schema, где брать учётные
данные приватно (без значений), какие именно файлы/параметры проекта/
службы будут изменены, резервная копия и проверка после настройки,
потребуется ли перезагрузка проекта/процессов и какие пункты ещё неизвестны.
Существующие архивы не заменять пустой БД ради зелёного статуса; если была
настроена другая база, сначала объяснить выбор. Пароль пользователя Client
не является автоматически паролем root/пользователя SQL.

Для будущей проверки различить: соединение БД, читаемый архив/новые сообщения
и отдельно результат PLC/OPC. Подключение БД не объявлять исправлением
таймаута записи и не обещать восстановление старых сообщений, которые могли
не сохраняться. Сначала готовый план; общую просьбу «разреши БД» вместо него
не формулировать. Применение — только по последующему конкретному заданию.

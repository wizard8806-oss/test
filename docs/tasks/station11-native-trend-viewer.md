## Нужный результат

В одной штатной группе и одной области времени:

| Ряд | Проверенный источник | Физическое значение | Подпись шкалы |
| --- | --- | --- | --- |
| Фактическое давление | `PressurePV_x100`, подтверждённый источник | `OriginalAsInt / 100.0` | бар, один знак |
| Уставка ПЛК | `PressureSP_x100`, действующая обратная связь | `OriginalAsInt / 100.0` | бар, один знак |
| Фактическая частота ПЧ 1 | `Vfd1FreqRaw`, фактическое значение | `OriginalAsInt / 10.0` | Гц, один знак |

Черновик и заданная частота не подменяют эти источники. Каждому ряду нужны
свой цвет, название и значение под курсором. Давление и уставка используют
общую шкалу «бар» с одинаковыми диапазоном и форматом; частота — отдельную
шкалу «Гц». Общая ось X — время. Диапазон общей шкалы давления должен
покрывать проверенные диапазоны PV и SP, не обрезая один из рядов.
Бары и герцы нельзя объединять в одну числовую шкалу.
Размещение шкал использовать поддержанное native-панелью; противоположные
стороны не имитировать неподтверждённой настройкой.

В native-просмотре уже имеются календарь, период, автопрокрутка, масштабирование
и перемещение, курсор, легенда/список рядов, скрытие рядов и печать. Проверить
эти средства на настоящей группе. Переходы страницы «Графики» должны выбирать
её и требуемый период 1/6/24 ч на текущем Client. Возврат — штатный «Назад».
Отдельное общее окно станции и основная верхняя навигация сохраняются.

Проверить существующую группу `UiTrend_station_001` и её фактический ID в
сохранённой копии. Понятное название — «Давление, уставка и частота». Внутреннее имя/ID
не менять без обновления зависимых переходов; не подставлять выдуманный ID.

## Масштаб и исходные контракты

Справка именно 2.6.15: `trend-prop.html`, `client-trends-view.html`,
`varextra.html`, `edit-scale.html`. Свойства тренда наследуют формат, единицы,
сдвиг запятой и диапазон переменной; native объединяет шкалы только при
совпадении минимума/максимума/единиц. Проценты и надпись «RAW/100» в легенде
не заменяют физические значения в курсоре/на шкале.

Сначала прочитать реальные свойства трёх источников и их использование в
скриптах. `Value`/`AsFloat` учитывают DecimalOffset, `OriginalAsInt` — исходный
raw. `Read-ScadaVariableMetadata.ps1` и контракты управления проверяют raw
привязки: не менять их DecimalOffset, адреса, типы или общие шкалы вслепую.
Новые диапазоны взять из проверенного профиля; не обрезать данные удобным
максимумом и не нормировать разные величины в проценты без физических шкал.

Если штатный тренд не позволяет независимое преобразование, подготовить
отдельные переменные представления с уникальными именами/ID, физическими
единицами и проверенным получением данных только для отображения/архива.
Исходные command/readback-переменные и прежние архивные ряды сохранить.
Не создавать неоднозначность `GetVariableByAddress` дублированием исходного
OPC-адреса. Внутренние переменные представления обновлять по уникальному
имени, убедившись, что цель внутренняя; не записывать в исходные OPC-теги.
Для архива engineering-значений использовать новые ID, не смешивать их с
прежней raw-историей. Доказать преобразование на синтетических примерах:
PV raw290 → 2,9 бар, SP raw400 → 4,0 бар, частота raw350 → 35,0 Гц,
без реального изменения оборудования. Это тестовые примеры, не новые
измерения стенда. Для объединения шкал PV/SP должны совпадать минимум,
максимум и единица, а не только подпись «бар».

Качество и свежесть проверять для каждого ряда. Отсутствие значения и
потеря свежести должны давать недоступность/разрыв, а не начальный ноль или
продолжение последнего значения как достоверного. Нулевую подтверждённую
частоту отображать как 0,0 Гц. Конкретное представление пропусков проверить
в native; не изобретать неподтверждённый API/NaN-сериализацию. Если этот
контракт требует новой реализации, подготовить её source и проверку, а не
ограничиваться просьбой прислать ещё один скриншот.

Для фактического давления дополнительно использовать тот же контракт,
что в `OperatorConsole.UiSample`: подтверждённая карта ПЛК, свежий прогресс
`PlcAliveCounter`, GOOD у PV и `PressureSourceOK`, значение `PressureSourceOK=1`.
Потеря подтверждения источника при живой связи прерывает только ряд PV;
уставка и частота остаются доступны при собственных достоверных данных.
После восстановления источника продолжать PV новыми точками, не соединять
разрыв ложной достоверной линией. Подтверждённое нулевое давление допустимо.

## Архив и проверка в Client

Проверить архивацию нужных рядов и работу существующей БД. Для постоянной
уставки нужен режим, который сохраняет значение и при отсутствии изменения
(например, подтверждённый native-комбинированный режим с подходящим интервалом).
Дождаться сохранения настоящих значений при обычной работе, открыть выбранную
группу и показать реальные точки/числа курсора. Пустую область сначала
разобрать по конкретным причинам: не тот период, нет записей, ряд скрыт,
неверная шкала, качество/свежесть, права. Не рисовать фиктивную кривую.

Штатно сохранить/Compile изменённую копию, проверить нужный проект в Server/
Client и три ряда в native-панели. Без Apply, пусков, изменения частоты,
сброса паролей/БД и ручных INSERT ради демонстрации. Нужные программные
переключения уже разрешены; не включать одновременно второй управляющий
проект. При препятствии доступу попросить только конкретное окно/кадр,
параллельно читая доступные сохранённые свойства. Полный новый обход окон
не нужен. Большой встроенный блок на странице можно убрать после проверки
штатного графика; не удалять единственный сохранённый образец компонента.

Итог — три различимых ряда на двух физических шкалах, корректные значения,
настоящие архивные
точки и рабочие переходы периодов. Добавить воспроизводимый source/настройки
и уместные проверки преобразований/защиты команд. Сохранить подробные
native-пути/SHA/действия/снимки локально; в handoff-ветку — проверенные
исходники/тесты и согласованную краткую публичную сводку. Не переносить
частный проект/профили/журналы в Git. Настройки с рабочими полями остаются
следующим UI-этапом; открытие пустой панели не закрывает графики.

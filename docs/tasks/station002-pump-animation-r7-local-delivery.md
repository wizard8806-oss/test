# HMI-r7: анимация трёх насосов, сохранить динамические шкалы

Пользователь согласовал индикатор состояния, вращающуюся крыльчатку и метку
ведущего. Динамические шкалы уже есть — сохранить все три. Результат нужен
в виде готового отдельного SKM, с сохранением r6-навигации, трёх колонок,
таймеров и последних исходников. ПЛК/ПЧ/оборудование этим заданием не менять.

1. Из того же pinned-коммита, что это задание, скачать
   `artifacts/station002-pump-animation-r7/delivery-manifest.json`.
   Скачать все files[] по его rawBase, проверить bytes/SHA, сохранить
   относительные пути. Использовать существующий установленный Python3.13,
   например `%LOCALAPPDATA%\Programs\Python\Python313\python.exe`.
   Для сборки достаточно stdlib, pip/vendor DLL/переустановка не нужны.
2. Создать новую папку `.worktrees/station002-pump-animation-local-07/`
   (обычная папка, git worktree/fetch ради неё не требуются).
   Найти готовую r6 `pump_station_3p_navigation_r6.skm` по прежним отчётам:
   1240334байта,SHA256
   e8c1a0f6ca3684f301728b97f43d481a252cb89cd5b6296ccac8b4f76fce7ade.
   Если r6 ещё не создана, из точной последней обычной r5(1254272байта,
   SHA1d6449d8884fb9f44e3c6a2c71193d044788d8c2832e884c88e44c0707bdf3a3)
   воспроизвести r6 включёнными build_three_pump_hmi_r6.py/repair/recipe.
   Источники/более новые native-save не перезаписывать. При неизвестных
   дополнительных native-правках сохранить их и указать расхождение;
   не ослаблять source-lock и не терять изменения молча.
3. Собрать новый файл:

```text
python -B tools/build_pump_animation_hmi.py --source "ПОЛНЫЙ_ПУТЬ_К_R6.skm" --recipe artifacts/station002-pump-animation-r7/animation-recipe.json --macro assets/hmi/pump-animation/pump_animation.c --out pump_station_3p_animation_r7_candidate.skm --report hmi-r7-local-build.json
```

4. Проверить target по manifest:1271370байт,SHA256
   61ec747e1ff6629d931063e8df429255071fe1f8229cf1bd6b66e772658fe25d.
   Проверить неизменность источника. Сначала довести до готового SKM,
   отсутствие GUI не должно мешать файловой сборке.
5. Установить собственный шрифт в текущий Windows-профиль:

```powershell
& .\tools\Install-PumpAnimationFont.ps1 -FontPath .\assets\hmi\pump-animation\PumpStationRotor.ttf
```

   Администратор не нужен. Скрипт проверяет SHA, сохраняет чужую отличающуюся
   копию, регистрирует только Pump Station Rotor и уведомляет приложения.
   Не менять Arial/системные шрифты. Никакой установки fontTools/Python-пакетов
   для готового TTF/SKM не требуется.
6. В уже установленном интерактивном SKTool — File→Open нового r7.
   CLI-открытие с Tips/мгновенным завершением Simulator ранее не давало
   осмотра; этот неработающий цикл/переустановку не повторять. Чужие окна
   не завершать. Сначала сохранить несохранённые изменения в отдельную копию.
7. Проверить семейство Pump Station Rotor и четыре ориентации крыльчатки:
   настоящие лопасти, не квадрат/символ замены. Если работающий Qt-кэш ещё
   не видит установленный шрифт, один штатный перезапуск после сохранения
   работы допустим. Скомпилировать штатной командой Compile; записать реальные результаты,
   отдельно ошибки исходного macro и новых переменных/шрифтов. Если нужен
   native-save, сохранять как новый `pump_station_3p_animation_r7_native.skm`,
   кандидат и r6 оставить. Проверить две C-source mirrors и Variable settings:
   четыре новых input исключительно R; имена/типы/размеры в interface.json.
   SKTool должен сгенерировать свои символы MacroInit.h; pVar offsets не гадать.
8. Offline Simulator запускать без связи с реальным шкафом. Осмотреть главный
   экран: три крыльчатки на двигателях, статусы под насосами, нет четвёртых
   объектов/наложений. Старые3BG/числаГц и footer r6 сохранены. Без свежих
   PLC/VFD данных все крыльчатки серые/неподвижные, ведущий скрыт, статус
   «Нет данных». Полные динамические показания можно подтвердить позже на
   согласованном стенде; отсутствие связи не обходить в рабочем macro.
9. Цвета: серый остановлен, зелёный фактическая частота>0 со свежим качеством,
   жёлтый подготовка, красный «ПЧ не готов». Не выдавать это за внутренний
   fault code. «ВЕДУЩИЙ» требует выбранного номера AND подтверждённой роли6.
   Крыльчатка показывает выходную частоту, не измерение вала/расхода.
   Динамические шкалы НЕ удалять. Таймеры/навигацию/кнопки управления не менять.
10. Выдать абсолютные Windows-пути готового SKM/отчёта/возможного native-save,
    размеры/SHA и реальные результаты File→Open/Compile/шрифта/Simulator.
    Облачные59Cсценариев и Chromium-макет уже PASS, но не заменяют native.
    При недоступном GUI всё равно выдать готовый SKM и конкретный оставшийся
    native-шаг. Полные SKM/PDW/vendor-exe/сырые журналы в Git не добавлять.

Шкаф под напряжением без двигателей, Port0 общий ПК/HMI. Не подключаться,
не запускать реальный PLC/VFD, не делать Download/Force ради анимации.
Проверка подключения/backup контроллера остаётся отдельной задачей.

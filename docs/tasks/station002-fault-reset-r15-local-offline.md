## ПЛК — доступная нативная проверка

Открыть новый PDW в существующем WinProLadder, F7/сверка памяти и F8.
Проверить R3200..3288, M1815..1839/M1871..1879, T124/T125, сохраняемые
R2857..2859 без пересечений/косвенного использования. CPU free664байта.
Native-сохранение с иным ключом допустимо, записать отдельный SHA и сравнить
декодированные программу/таблицы, не требовать равенства шифрованных bytes.

Reset: ModeSTOP/selector/T51/X8/X9/Y1..4, свежая частота0 и ненулевой код,
READY не требуется. Только Port3/M1936, FC06/0x2000=7 → FC03/0x1000/7WORD,
FUN150 ссылки8193/4097. Другие Port3работники согласованы; Port2CL50 не
изменён. D4044 читается, непрерывный режим Port3 отклоняется. Успех только
свежий0 после обеих успешных операций. Кнопка не подаёт RUN. Нет нового
прикладного повтора; физические протокольные повторы/тайминги без линии
ещё не измерены. Полная карта `docs/interfaces/station002-vfd-reset-r15.md`.

При нативной ошибке изучить конкретную сеть/фактическое сообщение и
исправить отдельную копию с повторным byte/host/native контролем. Не
переписывать рабочую защиту или старые TU-контакты ради isolated API.

## HMI — Compile и Offline Simulator

Открыть именно r15 через File→Open, штатный Compile с новым C, не старый
`prjCompiled`. Сверить оба Variable Settings и generated aliases:

```text
R AlarmWords Batch16/10bytes R2550
R MapVersion Batch16/2bytes R2554
R PumpAnimTelemetry Batch16/26bytes R2500
R PumpAnimRoles Batch16/14bytes R2320
R PumpAnimManual Batch16/6bytes R2380
R PumpAnimLeader Batch16/2bytes R2304
R NativeFaultData Batch16/80bytes R3040
R DriveResetData Batch16/64bytes R3200
W DriveResetRequest Batch16/12bytes R3216
W BootAck scalarUInt16 R2553 ПОСЛЕДНИМ
```

Перед BootAck216байт/кратно4. Не добавлять scalarR, не править pVar-offsets,
не менять адреса насосов. Probe13 остаётся27124, новая featureLW940=27130,
faultcontractR3049=27120, resetcontractR3200=27131. Source map остаётся32;
диагностика PLC27110 — другая карта, её не менять на32.

Simulator: главная/раскладка пользователя; работа навигации; «Аварии» с
прежним HAD без зависания; «Коды ПЧ» Screen15 с тремя кнопками, code/last/
freshness; «Запуски ПЛК» Screen16; Screen13probe; loading/saver14.
Без PLC нули/неподтверждённая связь ожидаемы, не объявлять реальные ошибки
или удачный сброс по этому экрану. В offlineSimulation кнопка при отсутствии
подтверждённого reset-профиля не должна создать команду.

Для активной симуляции1/2/3/52/53/unknown/timeout использовать только
отдельную явно названную OFFLINE_TEST-копию с локальными входами/без PLC
writes. ProductionR-адреса ради неё не менять. Обычный Simulator не
подтверждает взаимодействие с ПЛК/ПЧ и ABI реального образа.

В журнал добавлены отдельные коды1..80 всех трёх,37известных описаний,
прочие числом. >80 — общий unknown-event, точное текущее/последнее число
на15; числовая история произвольных >80 пока не реализована. A52↔raw52
настоящего ПЧ2 и звук/mute уже подтверждены пользователем ранее. Новая
HMI-обвязка/сброс ещё аппаратно не принимались.

Если GUI по-прежнему недоступен локальному сеансу, **всё равно закончить
изготовление/проверку двух файлов и копирование JPG**, дать оператору
точные пути и конкретные оставшиеся File→Open/F8/Compile/StartSetting шаги.
Не выполнять CLI Tips-циклы, массовое завершение процессов или повторную
установку ПО. Несохранённые native-изменения сохранять отдельным Save As.

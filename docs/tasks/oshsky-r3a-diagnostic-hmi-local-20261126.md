## 1. Два компактных read-only экрана

Через штатный Editor добавить доступ со страницы «Диагностика», возвраты
к ней/Main и две страницы. Их actual IDs определить по модели, не менять
номера/ссылки14существующих страниц. В шапке явная метка `R3a DIAG 26.11.2026`.
Стиль проекта, читаемые подписи с адресами и крупные числовые поля, без
клавиатур/команд. Сырые данные **не скрывать** по LB2100..2103/LB2110.

### «Экспорты» — сравнение PLC и макроса

Для соответствующих полей показать две колонки:

| Назначение | Прямой native read PLC | Значение существующего macro alias |
| --- | --- | --- |
| Маркер токов | R2509, ожидается27401 | OshTelemetry[9] |
| Счётчик токов | R2508 | OshTelemetry[8] |
| Маркер каскада | R3120, ожидается27402 | CascadeBlock[0] |
| Счётчик каскада | R3125 | CascadeBlock[5] |
| Общий счётчик | R2840 | если отдельного alias нет, так и подписать |
| Контракт | R2329, ожидается27110 | OshContract |
| Карта | R2554, ожидается32 | фактический MapVersion из AlarmWords[4] |

Добавить прямые R2884/R2885 — active выдержки3/4, LB2110 и причину закрытия
его допуска. Календарь RTC LW60000..60005 показать **сырыми hex** и отдельно
фактически декодированные значения/ClockValid; формат не предполагать.
LW821/LW828, отдельный локальный номер свежего снимка aliases и возраст
существующих heartbeat помогают отличить остановку кода от остановки источника.
Номер должен изменяться при выполнении нового capture, не просто иметь
сохранённое ненулевое значение. Два экрана/фото через2–3с должны показывать
продвижение либо его отсутствие без WinProLadder.

Прямые native numeric reads должны использовать обычный штатный путь
контроллера, а не локальные копии OshTelemetry/CascadeBlock. Указать доступный
для этой версии признак ошибки связи/чтения; не обнулять недоступный кэш при
открытии. Одно начальное0 не выдавать за доказанный ответ PLC.

### «Токи / режимы» — четыре собственных канала

Четыре равные колонки: прямые R2504..2507(Iraw), R2510..2513(Q),
значения этих же индексов OshTelemetry[4..7]/[10..13], существующие
LW54000..54003 и LB2100..2103. Единица сырыхI — raw; масштаб0.1А обозначить,
не выдавать raw заамперы. При достаточном месте показать исходные
R2806/2814/2822/2830 либо сделать отдельный read-only просмотр.

В блоке ошибки режима: M667/M1563, D251/D231/D232, D320/321, D340/341,
R2402 и четыре пары M1624/R2390…M1627/R2393. Привод/запрос/ответ относятся
к одному подтверждённому циклу; D232 может быть старым, D251 уже относиться
к следующей операции. Надпись общей аварии и суффикс«(2)» номер не доказывают.
Не создавать режимную ошибку ради съёмки, не очищать защёлки.

## 2. Пассивный capture и минимальный дефект текста

Использовать существующие **семь** generated Variable settings и native
индексацию массива. В compiled r3 шаг4байта подтверждён по ARM, но это не
основание угадывать typedef или делать `(unsigned short*)` cast. Читать
alias поэлементно штатным типом с нужным приведением значения, не адреса.
Новые local LW/LB для снимка выбрать после collision audit, опубликовать карту.
Не размещать diagnostic данные поверх54000..54012/2100..2112/ретенции.

Capture вызывает только присваивания локальной памяти. Существующие
OshCurrents/CascadePanel дополняются наблюдением фактически вычисленных
ClockValid/age/moving/quality/false gate при каждом пути return. Не делать
вторую независимую модель свежести вместо этих состояний, не менять guards/
таймаут3с/очереди/исходы. Не добавлять новые глобальные PLC Variable reads
ради копирования значений уже существующих aliases.

Поля прямого просмотра опрашивать только в рамках открытой диагностики
поддерживаемым способом, не включать новый постоянный журнал/фоновые опросы
других устройств. Оценить период macro/source до и после; сам probe не должен
становиться причиной очередного истечения свежести.

**Доказанный UI-дефект MD5070:** он выбирает полный ACK по R2166 независимо
от LB2110. В новой копии заменить только подтверждённый текст полного успеха
нейтральным «Последняя операция подтверждена ПЛК» и отдельно при LB2110=0
показать «Новые выдержки3/4: данные не подтверждены». Сохранить все остальные
тексты отказа/ошибки и их приоритет, старые controls/transaction/sources.
Не скрывать ошибку PLC за одним общим сообщением и не показывать новый ACK
на основании только значения current/cascade marker.

## 3. Проверить и выдать файл

- Actual props должны подтверждать прямые R/D/M источники и RO у каждого
  нового поля, отсутствие свежестных hide на сырых значениях и точные источники
  колонки macro. В production никаких TEST_ONLY источников/приёмников.
- Тестировать actual generated C/native representation. Где буфер имеет
  32-битные элементы, дать различимые значения соседних/верхних половин, чтобы
  ошибочный16-bit stride не проходил. Использовать настоящий typedef/layout,
  а не выводить тип из одного sizeof. Провести original vs instrumented на
  одинаковых входах: все прежние outputs/допуски/PLC writes должны совпасть,
  новые отличия только в явно выделенной diagnostic local memory.
- Проверить oldACK+LB2110=0 и oldACK+LB2110=1, сохранить сообщения отказов.
  Нулевая/невалидная RTC, неподвижный/обновлённый HB, Q0/1/2, wrap/reconnect,
  MANUAL/STOP/AUTO не должны незаметно менять старую обработку.
- Script Compile HMI/local → полный Compile → Save As → независимый reopen
  с диска. Сохранить изображения новых страниц/таблицу адресов, исходные7pins,
  подтверждение прежних маршрутов/controls и новые пути возврата. Offline
  Simulator/host test не назвать чтением поля.
- Если обнаружена воспроизводимая причина основной неисправности, дополнительно
  подготовить отдельный минимальный исправленный файл с regression и объяснением.
  Синтетический успешный экран не подтверждает исправление в шкафу.

Итог обязательно: **полный фактический Windows-путь SKM**, папки Compile,
SHA/размер и точное назначение; список двух экранов и что сфотографировать
через2–3с. PLC/SCADA не пересобирать. Original комплект не перезаписывать.
В Git передать краткий отчёт/безопасные изменения/HANDOFF, native/private нет.
Закрыть свои промежуточные окна после сохранения буферов, оставить один
итоговый Editor/Simulator при необходимости. Отсутствие Online не задерживает
создание этого файла; actual field/root cause до наблюдения остаются pending.

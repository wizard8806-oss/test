# SCADA11: исправить ухудшение относительно согласованного макета

02.11.2026 МСК. Пользователь указал: «очень много отличиий в худшую сторону».
Это уточнение текущей работы, а не просьба заменить согласованный дизайн.
Использовать [визуальный контракт](../ui/operator-console-visual-contract.md)
и [разбор известных отличий](../reports/station11-visual-parity-audit-20261102.md).

1. Получить ветку с сохранением местных изменений, прочитать HANDOFF. Если
   идёт пусковой опыт, штатно завершить его; не переключать интерфейс посреди
   незафиксированной команды. Разрешения на переключения/пуски уже есть в
   [задании стенда](station11-authorized-bench-validation.md), повторно не просить.
   Не повторять установку Python/БД/перенос10→11 и уже выполненный RAM Save As
   без новых изменений. Архив/профили/ПЛК/HMI/радио02 и исходную10 сохранить.
   По [новому локальному отчёту](../reports/station11-authorized-bench-log-review-20261102.md)
   основная Git-копия осталась на5e3cbae с местными изменениями, документы
   опубликованы из другой актуальной копии. Работать из актуального worktree,
   сохранить и сравнить местные исходники; старую папку не reset/clean/stash.
2. Установить, **что реально показывает оператору Client**: точное имя/путь
   проекта10 или11, viewport, DPI, масштаб/тема, панели Simple-Scada. По
   последнему отчёту рабочей оставлена10; её старый технический экран нельзя
   выдавать за окончательный перенос нового макета. Новый результат11 тоже
   не считать соответствующим без просмотра.
   Последний сеанс прочёл только logs, не получил HWND/заголовков. Сначала
   проверить session ID CLI и Server/Client/Editor, доступную desktop/window
   station и перечисление их верхних окон. Нулевой MainWindowHandle одного
   Get-Process не доказывает отсутствие всех окон. Пользователь уже уточнил:
   CLI находится «В терминале рядом со SCADA»; другой сеанс пока не установлен.
   Сопоставить **процесс, в котором реально исполняются команды CLI**, с
   приложениями; видимый терминал и исполнитель могут отличаться по контексту.
   Новое согласие на стенд не требуется. Не обходить границы сеансов/допуска инструментов
   инъекцией или отключением проверок. Без живого окна не публиковать визуальный PASS.
   Отдельно проверить уже доступный штатный read-only OPC DA-канал через
   существующий MasterOPC: отсутствие GUI не доказывает отсутствие чтения тегов.
   Это может закрыть независимую сверку калибратора, но не заменяет UI-кадры.
   Конкурирующий Main/Modbus-клиент не создавать.
   Дополнение504f2c5/893fa41: фактическое имя процесса MasterOPC —
   modbusopcserver. Поиск OPCDAAuto.dll в стандартных папках дал отрицательный
   результат; отдельно проверить зарегистрированные доступные OPC DA-интерфейсы
   и разрядность, не считать наличие OpcEnum.exe клиентом чтения и не
   регистрировать DLL/менять DCOM по предположению. Запись о задержке7265мс
   в Server-log не является сама по себе диагнозом связи или поводом перезапуска.

   Выполнить готовый читающий инструмент через тот же исполнитель CLI из
   **актуального worktree**; старый каталог на5e3cbae его не содержит:

   ```powershell
   $uiContextOut = Join-Path $env:TEMP ('scada-ui-context-' + [Guid]::NewGuid().ToString('N') + '.json')
   powershell -NoProfile -File .\tools\Get-ScadaUiContext.ps1 -OutPath $uiContextOut
   ```

   Скрипт не нажимает кнопки/не переключает окна/не запускает SCADA/не создаёт
   OPC-объектов. Сохраняет новый JSON без перезаписи, только metadata целевых
   приложений; произвольные заголовки хешируются, пути DLL не выводятся.
   `status=measured` означает сбор метаданных, не визуальный PASS.
   Интерпретировать факты:
   - найденные EnumWindows окна при hasMainWindow=false указывают, что прежний
     способ обнаружения был недостаточен; использовать реальные HWND/класс/
     размеры/DPI для следующего штатного UI-доступа и снимка;
   - разные session ID/desktop, отсутствие окон/ошибки перечисления или разные
     уровни запуска исследовать как конкретную причину доступа, а не менять
     политики/привилегии/сеанс по предположению;
   - разные уровни elevation могут объяснять ограничения UI Automation,
     но сами по себе не доказывают причину отказа;
   - регистрация Automation только в одной разрядности — основание выбрать
     подходящий уже установленный клиент чтения, не регистрировать DLL вслепую;
   - отсутствие этих трёх ProgID не доказывает отсутствия всех OPC DA-клиентов.
   Записать результат/причину и перейти к кадрам Client11. Если остаётся отказ
   конкретного API/инструмента — привести его точный тип; не повторять ту же
   пассивную инвентаризацию без нового различающего действия.
3. Штатно открыть/загрузить проверяемую копию11 и получить исходные снимки
   её карточки/обзора. Для других страниц при необходимости использовать
   штатную навигацию; отказ новой кнопки отмечать отдельно. Сгенерировать
   эталон из неизменённого ui/operator-console при том же размере. Зафиксировать
   обычную/неизвестную информацию и длинную подпись. Демоданные не переносить
   в рабочие теги. Не сравнивать растянутый PNG с другим DPI/масштабом.
4. Исправлять **сначала карточку станции**: место под native-панель, иерархию
   заголовка/значений, три показателя, четыре одинаковые карточки насосов,
   символы/статусы, блок уставки, события/связь. Сохранить один знак давления,
   настоящую достоверность/свежесть, права и весь проверенный контракт команд.
   Исправить обрезку/перекрытия/серое поле. Штатные графические/текстовые
   контролы и ресурсы проверить в Editor/документации, не списывать вид на
   ограничения без фактов. Не делать ещё один произвольный HTML-дизайн.
5. Довести **обзор**: оформление/активная навигация, сводка, таблица, поиск/
   фильтры, статусы/обновление/насосы и отдельное окно. По этому же комплекту
   компонентов исправить аварии, графики, настройки и окно станции. Видимые
   графики/формы не заменять памятками или только ссылками. Для каждого
   реального ограничения назвать проверенный факт и ближайшее представление.
6. Native-правки выполнять в отдельной сохранённой копии текущей11; не
   применять повторно установщик10→11, который потеряет настроенный архив.
   Каждую поправку сохранять воспроизводимо в исходниках/генераторе/ресурсах,
   с нужной регрессией. Изменения виду не должны менять командные адреса/
   x100/права/таймауты/автоотправку; новые элементы используют тот же контекст.
7. После Save/Compile/загрузки получить **парные кадры до/после и эталон**,
   отдельно проверить клики, длинный текст, неизвестные данные и отдельное
   окно. Указать что реально проверено, а не только изменено в генераторе.
   Только изображения операторской области без чужих окон/паролей/лицензий;
   private-снимки/дампы не публиковать. Для совместного просмотра допустимы
   отдельные очищенные от приватных данных кадры операторского UI в отчёте.
   Эталонные результаты сборки/PNG остаются вне Git по прежнему правилу.
8. Самостоятельно обновить отчёт/HANDOFF: версии/пути/снимки, реестр отличий,
   что исправлено/проверено в Client и что осталось. При незавершённой приёмке
   вернуть10, указать реальную активную версию. Функциональные стендовые
   проверки продолжать по известному плану, но не откладывать соответствие
   дизайну до «когда всё остальное заработает».

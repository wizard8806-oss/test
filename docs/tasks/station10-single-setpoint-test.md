# Предложение: одна диагностическая запись4.00бар в общий R2100

**СТАТУС: ПОДГОТОВЛЕНО, НЕ РАЗРЕШЕНО, НЕ ВЫПОЛНЯТЬ ДО ОТДЕЛЬНОГО
КОНКРЕТНОГО ПОРУЧЕНИЯ ПОЛЬЗОВАТЕЛЯ.** Основание подготовки —
[preflight cd40a14](../reports/station10-setpoint-preflight-20261101T174035Z.md)
и [облачный разбор](../reports/station10-preflight-review-20261101.md).
Прежняя одна запись4.0/09 использована; её нельзя повторить автоматически.
Разрешение, если получено, записать в HANDOFF с конкретным объёмом.

После такого поручения локальный CLI получает актуальную рабочую ветку,
сохраняет местные изменения/JSONL/индекс и читает AGENTS/HANDOFF. Полевая
часть выполняется только на ноутбуке. Облачный mock-тест — не команда ПЛК.

| Параметр | Единственная предложенная операция |
|---|---|
| Проект/станция | Уже активная codex_diag_10, codex.Device1/station-001 |
| Цель | 4.00бар, raw400, общая уставка HMI/SCADA |
| Запись | PressureSP_Command, Holding/PDU2100, существующий Apply Client10 |
| Число | Не более одного Apply/одного setter, без повтора и отката |
| Проверка | R2100 и зеркало R2360, новый счётчик2840, SQL-запрос/итог |
| Отдельный результат | Приём ПЛК и подтверждение ведущего ПЧ различать |

## До нажатия

Использовать существующие Server/Client/MasterOPC/радиосборщик. Не запускать
параллельную управляющую копию/новый OPC/Modbus-клиент, не занимать Main50008.
Не сохранять/компилировать/загружать проекты, не менять таймауты/опрос/права/
журналирование. Не пуск/стоп/режим/сброс насосов и не прямой setter через
консоль. Не редактировать HMI и не отключать его связь ради опыта.

Заново кратко подтвердить активную10/одного оператора/непустое имя клиента,
сохранённые6 хешей, карту32/feedback1/GOOD/режимСТОП и продвижение счётчика.
Сохранить существующую авторизацию; при необходимом штатном входе использовать
ранее разрешённый операторский DPAPI без вывода секрета. Учётки не менять.
Оба readback должны быть согласованы и равны350. Если значение/режим/проект
изменились, есть pending или другая управляющая сессия — не настраивать
стенд обратно автоматически; остановить опыт и записать факты. Если уже400,
не нажимать Apply и не подбирать другую цель вместо согласованной.

Подготовить ограниченное SQL SELECT через архивную учётку/её DPAPI,
проверить прежние события, записать UTC/МСК и границу поиска. Корреляция:
проект10 + время + номер запроса + цель400, не один serial после рестарта.
Не имитировать сообщение SQL INSERT/AddMessage ради проверки. Если журнал
не читается или актёр/данные не подтверждены — закончить без Apply.

На время опыта оператору не редактировать уставку с HMI/другой SCADA.
Это временное условие наблюдения, не изменение приоритета/схемы HMI.
До записи начать чтение текущей таблицы MasterOPC и доступного штатного
источника результата OPC. Если существующий источник не содержит результата
write/HRESULT, заранее отметить ограничение; не включать новое логирование
или вторую сессию по гипотезе и не выдавать отсутствие записи в логе за отказ.

## Единственное действие и наблюдение

При исходных350 выбрать в существующем Client черновик4.0 штатными пятью
нажатиями+0.1. Проверить показанную цель4.0 и сохранение рабочей3.50.
Нажать «Применить» ровно один раз; записать собственные UTC/МСК момента.
Не нажимать больше Apply/+/−/Отмена и не выполнять откат.

Далее только чтение не более90с, сохраняя актуальные имя+PDU+значение+
качество в согласованной строке. Несогласованные MSAA-строки исключать.
Нужны R2100/R2360/2840, режим, семь feedback-тегов, видимый статус SCADA;
не повышать частоту опроса устройства. Из SQL получить только строки
`Уставка [codex.Device1.] #` этого окна, номер/цель/переходы/итог; обезличить
имя клиента/оператора. Результат OPC брать лишь из действующего источника,
если реально доступен. Возврат setter без исключения не равен доставке.

Наблюдения трактовать раздельно: виден ли запрос в SQL; изменились ли
согласованные R2100/R2360 на400; когда продвинулся счётчик; какой итог SCADA;
есть ли отдельное подтверждение ПЧ. При таймауте20с и400/400 указать возможное
несовпадение результата алгоритма с readback, а не повторять команду.
Если400 сменилось обратно350 — сохранить последовательность и источники;
не объявлять HMI виновным без доказательства. СТОП может хранить уставку
без подтверждения ПЧ. Позднее эхо не переписывает исторический таймаут.

## После

Сохранить отчёт/результат/ограничения и самостоятельно обновить HANDOFF,
указать ровно одно действие или конкретную причину, почему его не было.
Хеши6 файлов до/после сверить. DPAPI/сырые логи/скриншоты/native остаются
приватно; публикация только санитарных документов, main не менять.
Проверить SHA origin после публикации. Ни успех, ни ошибка этой попытки
не разрешают вторую/откат/смену режима/новую уставку автоматически.

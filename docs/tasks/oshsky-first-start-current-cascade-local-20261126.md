## Что установлено и что неизвестно

- На Main РУЧНОЙ, зелёный PLC; F меняются25→35Гц, давление0.0→0.7бар,
  часы0.0→0.1/0.2. Есть кадр4/4 RUN и кадр3/4 с остановленным насосом4.
  На всех четырёх токах прочерки, включая остановленный. Это не доказательство
  общей потери PLC-связи или нулевого измеренного тока.
- «Каскад»: старые параметры читаются, выход на2насоса30с; строки выхода
  на3/4насоса — прочерки. Сообщение «Вся группа настроек принята ПЛК»
  при этом видимо. Нужно проследить источник текста и не обещать чтение
  недоступных новых полей. Пользователь словом «второго» описал проблему;
  по фотографии неизвестны именно две новые строки.
- История содержит смены связи/готовности ПЧ и недопустимых частот; по одному
  кадру не выводить, какие события сейчас активны и почему они возникли.
- Root cause ещё **не установлен**. Не объявлять устаревшую программу,
  неисправный ПЧ, RTC, проводку или неправильную загрузку доказанным фактом.
  Офлайн-тесты и упаковка не воспроизвели этот аппаратный путь.

## 1. Быстрое чтение на объекте, если доступно

У пользователя запрошено наличие WinProLadder. При доступном Online monitor
читать только через существующее подключение к нужному контроллеру.
Не применять Download/Force/запись/переключение режима ради диагностики.
Не останавливать работающие насосы и не запускать конкурирующий Modbus-клиент.

Минимум два среза с интервалом2–3с:

| Регистр | Ожидаемое назначение |
| --- | --- |
| R2509 |27401, возможность нового экспорта токов |
| R2508 | Должно наблюдаться движение, зеркало общего heartbeat |
| R3120 |27402, возможность каскада r3 |
| R3125 | Новый собственный движущийся heartbeat каскада |
| R2840 | Общий heartbeat для сравнения |

Затем R2329/2554(27110/32), R2504..2507(сырые токи×0.1А),
R2510..2513(своиQ0/1/2), R2884/2885(активные новые1..3600с),
R2887/2888(shadow), R2886(подпись инициализации27402).
Если надо проследить ток до источника: R2806/2814/2822/2830 — последний
элемент своего7-wordснимка. Сверить с показанием тока на конкретном ПЧ,
не изменяя параметров привода. Записать значения/время/номер насоса/источник.

Числа маркеров сами по себе недостаточны: они могут остаться в памяти после
отката. Счётчики сравнивать по факту изменения,65535→0 допустим. Не требовать
побитного равенства всех трёх счётчиков при несинхронном чтении разных слов.

## 2. Разделить причины по данным

**Дополнение по уточнённому фото журнала:** активна красная «Ошибка
подготовки режимов ПЧ»;12:53снята12:57 и вновь активна12:59. Строки связи
ПЧ4 зелёные, имеют время снятия. В базовом HMI это общий текст R2550.bit13,
источник95.A018/M1563; номер насоса в текст не включён. Суффикс«(2)» сам
по себе не определяет ПЧ2, семантика native суффикса ещё не проверена.

Дополнительно проследить неизменённый узел подготовки режима:65.40(write
error),65.44(readback error/mismatch),65.47(timeout) устанавливаютM667.
В базовой программеD251 — latched target изD250, D231 — запрошенное
значение режима, D232 — чтение обратно. Снять вместе сM667/M1563 и
M1624..1627/R2390..2393: общая авария может учитывать сохранённую ошибку
другого/предыдущего запроса. Один D251 вне контекста цикла не доказывает
виновный привод. Сверить actual installed р3, не считать trace source04
повторным чтением программы из шкафа. Назначение удалённого параметра
и one-based адрес FUN150 сверять с точным руководством ПЧ; ничего в ПЧ
не перенастраивать по одной надписи. Связь этой аварии с прочерками токов/
таймеров пока **не установлена**; исходную ветку диагностики не заменять.

1. Если маркера нет/нет движения только новых счётчиков при движущемсяR2840,
   проследить фактически исполняемые сети экспорта и версии ПЛК. Где доступно,
   выполнить штатное read-only compare/выгрузку без изменения RUN. Сравнивать
   decoded program/операнды с эталоном: native Save меняет маску сериализации.
   Открытый файл на ноутбуке не доказывает загруженную программу.
2. Если маркеры/счётчики правильные в PLC, сравнить **сырые** значения в HMI
   до visibility/freshness. Счётчик, правильный в PLC, может не дойти в alias.
3. Если значения дошли в alias, найти точный false gate: link/map/contract,
   RTC/tick, движение/возраст, свойQ, условие видимости либо место вызова.
4. Отдельно сверить сами R2884/2885 и источник токов. Работа частоты не
   подтверждает величину/масштаб тока. Нулевое новое время не объявлять
   допустимым рабочим preset, потерю данных не заменять нулём.

## 3. Что локальный может проверить независимо от доступа к шкафу

- Взять exact HMI/PLC r3 из Desktop-комплекта, сверить7pins и сохранить
  пользовательский RAM/диск отдельно. Экспортировать фактические оба
  представления C, generated MacroInit/aliases, настройки Variable и свойства
  объектов токов/новых времён. Не работать на TEST_ONLY вместо production.
- ОшTelemetry: один read-only Batch16 R2500..2513/28байт. Индексы4..7 —I,
  8 —R2508,9 —27401,10..13 —Q. OshContractR2329; MapVersion может быть
  переопределён через AlarmWords[4]. Проверить реальный controller/link,
  read/write direction, generated pointer type/stride и ошибку чтения batch.
- CascadeBlock: read-only R3120..3125/12байт, индекс0 marker,5 heartbeat;
  реальные UI active/shadowR2884/2887 иR2885/2888. Сверить не только подписи,
  но actual address/type/visibility из сохранённых native props.
- Вызовы обоих обновлений должны реально исполняться циклически. Проверить
  scope/ранние return/настройку запуска global macro и соответствие его
  compiled-результата загруженной модели. Четыре верных изображения Main
  не доказывают, что runtime исполняет новый macro/читает новые aliases.
- Проверить фактическую RTC и функцию InfoBCD, не подкладывать заранее
  выбранный тип/год в harness. У current возраст использует секундуRTC,
  у опубликованного CascadePanel — полный календарь. Не назначать одну
  ошибку RTC причиной обеих функций без проверки actual кода.
- LB2100..2103 — допуск токов, LB2110 — свежесть новой каскадной функции;
  их actual allocation проверить. LB2111/2112 — только active countdown.
  **Новые настройки не должны зависеть от AUTO или активного ожидания**:
  опубликованный CascadePanel обновляет свежесть и в MANUAL/STOP.
- При необходимости сделать отдельный read-only диагностический экран/trace
  с raw PLC→alias→gate/call counter. LW/LB выбрать после actual collision audit,
  не угадывать свободные адреса. До установки такого экрана закончить native
  Compile/Save/reopen; не выдавать диагностический файл за исправление.

## 4. Исправление и проверка

Не менять логику управления/защиты/каскада ради отображения и не писать
случайные значения в регистры для «оживления». Не снимать marker/heartbeat/Q
guards, не подменять прочерки0 и не увеличивать timeout без измеренного цикла.
Если окажется несовпадение загруженной пары, сначала доказать его и назвать
точные файлы; не переделывать уже верный экспорт. Действия установки/загрузки
на поле согласовать отдельно после готового reviewable результата.

Для доказанной ошибки сделать отдельную r3a-копию только затронутой части,
сохранить original r3/ZIP. Regression должен воспроизводить **найденный**
сбой: actual generated types/alias values/clock/mode, а не обходить входы
записью прямо в локальные valid-биты. Подтверждение настроек должно различать
полную/частичную достоверность группы; старый ACK не должен выдавать
недоступные новые строки за прочитанные и подтверждённые.

Проверить четыре разныхI/валидный0/диапазон, loss-Q4 без потери1–3,
маркер без движения/recovery/wrap, новые времена в STOP/MANUAL/AUTO,
read-only отображение при отсутствии active countdown, прежний Edit/Apply/
Cancel без новой записи active напрямую. Сохранить существующие пределы и
подтверждения. Native Compile/F8, Save/reopen и актуальные tests — по реально
изменённой части; результаты отличать от настоящего чтения на объекте.

Выдать: установленная причина с сырыми значениями и кодом/свойством,
минимальный diff, actual файлы/полныеWindows-пути/SHA/проверки и точный
остаток поля. Пока root cause неизвестен — так и написать, без «исправлено».
Отчёт/HANDOFF/карточку опубликовать в handoff-ветке; native/полевые дампы
и фотографии из чата приватны. Рабочие службы/SCADA/OPC/радио не переключать.
Собственные промежуточные окна закрыть после сохранения буферов.

## 2. HMI r19 из последнего r18a

Создай stage новым файлом:

```text
python tools/prepare_telemetry_hmi_r19.py --source "ПУТЬ_К_r18a_native.skm" --out "НОВЫЙ_КАТАЛОГ/pump_station_3p_babanov_r19_telemetry_STAGE.skm" --report "НОВЫЙ_КАТАЛОГ/hmi-stage.json"
```

Stage меняет только два C-зеркала и подпись зонда, сохраняет native
настройки/Batch-таблицы/7групп. Он **не готов к загрузке**: добавь поля
тока штатно в SKTool и перекомпилируй. Default pin — r18a, не меняй
`--source-sha256` на старый r17a. Cloud проверил алгоритм на ancestor,
но не имеет байтов твоего r18a; native Open/Compile здесь обязательны.
При Illegal opening не возвращай старые алогруппы и не перебирай версии:
сохрани ошибку, открой резервную r18a и перенеси вычисленный C через
Script Editor штатно, сохраняя все прежние Variable Settings. Источники C
извлекаются `macro_mirrors(stage)[0][4:].decode('utf-16-be')`.

Проверь в текущем Main три заглушки «— А». В r17a они назывались
Text16002/16004/16006, QRect(648,133/201/269,44,18). Рядом частоты стоят
с x700; ниже роли. Ориентируйся на фактический r18a, сохрани стиль проекта.

Для каждого насоса добавь **read-only Numeric Display**:

| Насос | Значение, uint16 | Видимость значения | Когда показывать «— А» |
|---|---|---|---|
| 1 | LW960 | LW963=1 | LW963=0 |
| 2 | LW961 | LW964=1 | LW964=0 |
| 3 | LW962 | LW965=1 | LW965=0 |

Один десятичный знак: raw47 → **4.7 А**, raw0 при valid → **0.0 А**.
Не дели число ещё раз в C. Вместимость5 целых цифр/1 десятичная,
единица «А». Размести в прежней области без перекрытия частоты/ролей;
сохрани размер/цвет/шрифт соседних показаний. Если native Visibility
работает через бит, преобразуй LW963..965 в проверенные свободные LB
отдельным локальным присваиванием и задокументируй адреса; не используй
непроверенные типы WordBit и не добавляй PLC write bindings.
Invalid не показывать числом0: заглушка обязательна.

Обнови устаревшую надпись Screen4 «Токи двигателей появятся после
добавления их опроса в ПЛК» (в ancestor Text5234). Допустимо: «Ток:
выходной ток ПЧ, А. При недостоверных данных — прочерк».
Основные частоты/шкалы оставь на R2500..2 с R2510..12. Состояния и
вентиляторы остаются LW900..908. Новый зонд должен показывать **27134**.

Новый PLC marker R2509=27133; R2504..6 несут ток. Всё приходит внутри
прежнего **Batch16 R2500/26 bytes**. Не добавляй scalar R-inputs,
не двигай pVar вручную и BootAckW из последней строки. Не меняй
reset-frame/STOP guard, карту32, NativeFault27120/Reset27131, звук/mute,
навигацию, Screen14 logo/startup, LB810 ручного окна, LB811/автопоказ
РКФ, её native ID3,17страниц/7групп и согласованный PNG.

Это согласованная новая пара PLC/HMI. R2509 входит в retain и сам по
себе не доказывает версию после отката PLC: на стенде сверяй также живой
build R2861=27133. Старая r15 пишет туда27114. Откат выполняй комплектом,
не оставляя новую HMI над старым PLC с сохранёнными словами тока.

Сохрани итог новым `pump_station_3p_babanov_r19_telemetry_native.skm`,
штатно Compile AlarmSound (HMI/local) **и всего HMI**, Save/reopen.
Не выдавай успех одного скрипта за отдельный результат всего проекта.

Проверь native rendering управляемыми локальными выходами макроса:
в тестовой копии после обычного PumpAnimation по очереди задай LW960..962

канала. Ожидаются1.7/20.4/38.9А,0.0А и прочерк только в выбранном
канале; поле не перекрывает частоту/единицу/статус. Для кадра трёх RUN
и шкал допустимо только в TEST_ONLY переназначить частоты/шкалы на
LW920..922 и quality LW923..925 и подать F150/300/500,Q2; анимационные
выходы LW900..902 циклически1..4 и статусы LW903..905=2. Потом один
канал unknown. Это проверка потребителей/рендеринга, **не Modbus**.
Реальная функция уже проверена host115cases; native synthetic screen
не заменяет её и не доказывает физический обмен.

Вернись к финальному native без TEST_ONLY: проверь отсутствие временных

## 4. Позднее: ПЛК + панель + один ПЧ

Подготовь короткий протокол, сейчас подключение не требуется. Для первого
настоящего теста достаточно одного ПЧ нужной модели и штатных линий
HMI↔PLC/PLC↔ПЧ. Использовать настоящий последовательный порт/модуль,
заложенный проектом, и те же настройки RS485. Не запускать конкурирующий
Modbus master. Сохранить исходные параметры тестового ПЧ.

Один ПЧ проверить последовательно со slave1/2/3. Два отсутствующих ПЧ
должны показывать unknown; не подставлять им фиктивную связь/готовность.
Сравнить raw F/I/качество с дисплеем ПЧ и зондом HMI, marker27133/27134,
работу шкалы/вентилятора/статуса и независимость каналов. Без двигателя
нормальный0.0А проверяет нулевое значение; ненулевое сравнение потребует
подходящего двигателя/нагрузки. Компьютерная имитация — отдельный результат.
Запиши период собственного обновления и тайм-ауты двух отсутствующих
адресов: стенд с одним ПЧ не доказывает время полного обмена с тремя.
READY и работа должны подтверждаться реальными сигналами; без них
остановленный вентилятор при исправном чтении не считать дефектом.

При потере собственного ответа/тайм-ауте показания должны стать unknown,
зелёный вентилятор остановиться; восстановление — только со свежим снимком.
Ошибку постороннего запроса при успешном собственном снимке воспроизвести
изолированной имитацией ответов или реальным поддерживаемым сценарием;
если не воспроизведена, так и записать. Два отсутствующих slave сами по
себе не доказывают этот сценарий. Не увеличивать watchdog ради зелёного.
Текущий offline-task не отправляет RUN/reset/Force/Download; загрузка
копий на отдельный стенд — действие пользователя при подключении стенда.

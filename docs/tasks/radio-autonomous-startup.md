# Радио: автоматическая фоновая работа на стенде

Пользователь повторил требование03.11: запуск при включении ПК/программы без
ручного PowerShell, предпочтительно через SCADA. Ориентир —
[radio-runtime](../radio-runtime-integration-2026-10-30.md). Данное задание —
следующий этап после [диагностики публикации02](radio02-publish-readonly-check.md).
Локальная UI-правка продолжается; не заменять её повторной настройкой радио.

## Результат для оператора

При старте Windows автоматически работает один фоновый сборщик реальной
станции, без консольного окна/повторного ввода паролей. Перезапуск SCADA не
прерывает сбор. В SCADA видны параметры модема, состояние/свежесть/причина
отказа. Недоступные данные не подменяются нулями. При обычном сетевом обрыве
сборщик восстанавливается с задержкой; конфликт облачной сессии не вызывает
бесконечную конкуренцию с другим клиентом.

## Реализация первого этапа

1. AGENTS/HANDOFF/Git/local changes; сначала получить диагноз и исправление
   причины ошибки публикации02. Не маскировать её автоматическими рестартами.
   Сохранить02/конфигурацию/данные/путь возврата, не держать двух писателей.
2. Подготовить в Git воспроизводимый отдельный пакет unattended-версии,
   установщик/проверку/удаление и проверки на синтетических данных. Код02
   и рабочие проекты не перезаписывать. Сохранить stationID/ARADIO1/отдельный
   Service-канал, не обращаться к Main50008/USB/ПЛК и не добавлять команды.
3. Для стенда выбрать одну задачу штатного Планировщика Windows с триггером
   старта ПК, без требования входа оператора. Контролируемый запуск от SYSTEM
   требует закрытого от записи обычными пользователями каталога исполняемого
   кода/конфигурации и защищённого credential-store. SCADA должна иметь только
   необходимый доступ к публикуемым данным. Установщик проверяет ACL/пути/
   наличие старого запуска до активации. Задачу не выдавать за SCM-службу.
4. Радиопароли вводятся один раз локально, не в чате/аргументах/JSON открытым
   текстом. Подготовить DPAPI-хранилище, совместимое с выбранным Windows-
   контекстом запуска; для LocalMachine ciphertext ограничить SYSTEM/Admin
   ACL. Пароль оператора SCADA не является паролем M2M24/модема. Не вводить
   новые временные пароли ради переноса, если известны действующие.
5. Один экземпляр/писатель на станцию и одна сессия на группу. Старт задачи
   не должен вытеснять работающий02: установить владельца/возврат, переключить
   штатно после готовности пакета. Понятная диагностика lock/публикации/
   authentication/network, без вывода секретов. CLOUD_SESSION_REPLACED
   останавливает конкуренцию; общий watchdog не должен обходить эту остановку.
6. Синхронный TCP-loop не переносить в OnTimer SCADA. Для оператора использовать
   существующий читатель/индикацию состояния и свежести. Если потребуется
   действие запуска из приложения, вызывать зарегистрированную задачу через
   проверенный неблокирующий механизм, не запускать новые копии по таймеру.
   Native API для такого действия сначала подтвердить; не выдумывать функции.
7. Локальный CLI проверяет упаковку/ACL/credential read под фактической учётной
   записью, старт без окна/ввода, один PID и рост seq, обычный обрыв/восстановление,
   отсутствие модема/устаревание, конфликт второй Service-сессии, перезапуск
   SCADA и обратимое удаление. Boot без входа проверить после сохранения
   открытых проектов/готовности возврата. Пропущенное записать, не считать PASS.
8. Codex сам обновляет отчёт/HANDOFF: версия/SHA/имя задачи/пути, фактическая
   identity/состояние/seq/возраст, результаты и ограничения. В Git только код/
   шаблоны/публичный отчёт; credential blobs/личные конфиги/архив не публиковать.

Этот этап предназначен для одной фактической станции. Будущее расширение —
единый транспорт/очереди/маршрутизация нескольких станций по прежнему контракту;
не размножать синхронный02 по одному процессу на станцию общей cloud-группы.
Установка задачи, хранилище и boot-приёмка пока не выполнены.

# Локально: найти причину «Нет данных» у насосов 2 и 3

Продолжение r10, без замены задания каскада:
https://raw.githubusercontent.com/wizard8806-oss/test/0e59fc17dfa24b85377eed33e6b0f779c94069ec/docs/tasks/station002-cascade-r10-local-delivery.md

Пользователь прислал фото1000298229/1000298230 настоящей панели и явно
уточнил: **это ещё прежние проекты**, не результат загрузки r10.
В AUTO ведущий1:50Гц, ведомым2/3 показано25Гц, команды RUN включены,
счётчик ведомых2. В MANUAL у всех25Гц/команды RUN, но зелёная крыльчатка
и статус «Работа» только у1; у2/3 — «Нет данных». Датчики давления у2/3
не подключены. По фото нельзя установить SHA загруженных PLC/HMI или
подтвердить работу двигателей. 25Гц справа — в известном файле R2501/2502,
сохранённая фактическая частота; без качества её актуальность не доказана.

Задача — получить конкретное место отказа, затем узко исправить отдельную
копию. Не менять управление/защиты, не подставлять уставку или RUN вместо
фактической частоты, не увеличивать watchdog без измерения интервалов.

## 1. Установить, что исследуется

Указать пути/SHA текущих открытых PDW/SKM и кандидата r10. Текущие/native
сохранения оставить. Завершить предусмотренные файловые сборки/F8/Compile
r10 по прежнему заданию, но не объявлять новые фото проверкой r10.
Для диагностики не требуется самостоятельно загружать r10 в оборудование.
Если редактор имеет несохранённые изменения — сохранить отдельную копию.

## 2. Снять живые значения в существующем read-only сеансе

| Насос | Фактическая частота | Качество | Признак свежего кэша | Сырой буфер частоты | Ротор / статус HMI |
|---|---|---|---|---|---|
| 1 | R2500 | R2510 | M1748 | R2803 | LW900 / LW903 |
| 2 | R2501 | R2511 | M1749 | R2811 | LW901 / LW904 |
| 3 | R2502 | R2512 | M1750 | R2819 | LW902 / LW905 |

Дополнительно: R2550/R2554, X1..X3, M610..M612; при доступном наблюдении
M602/M601, D300/D301, импульсы M1744..1746 и T92..T94. Нужна временная
привязка и наблюдение не менее15с, а не только разовый снимок констант.
Значения качества:0 — неизвестно,1 — достоверный останов при0Гц,
2 — достоверная положительная частота. Включённая команда сама это не доказывает.

ПК и HMI используют общий Port0. Не переподключать кабели самостоятельно,
не запускать конкурирующий мастер/сканер, не выдавать последовательные
наблюдения PLC и HMI за одновременные. Если текущего online-доступа нет,
подготовить отдельную Status Page с перечисленными адресами и сообщить,
какой конкретный снимок/сеанс остаётся получить. Недоступность live-сеанса
не мешает завершить файловую сборку и native Compile.

## 3. Разделить причины по данным

- Если R2511/2512=0, локализовать формирование качества в ПЛК. Проверить,
  появляются ли успешные частотные выборки и не истекают ли5с до следующей.
  Если ошибки приходят от других строк того же ПЧ, указать точные D300/D301
  и момент сброса кэша. Не объявлять причиной отсутствие датчика по совпадению.
- Если качество2, частота положительная в диапазоне и READY/link исправны,
  а макрос выдаёт LW904/905=0 — сверить значения, реально прочитанные HMI,
  порядок/длины native переменных и generated MacroInit/VarSetting.
- Если LW904/905=2 и LW901/902 меняются1..4, а на экране серый ротор/
  «Нет данных» — проверить привязки/state tables именно скомпилированного
  проекта. Не пересобирать PLC ради такой ошибки отображения.

В известном r10 нормальная таблица содержит14 запросов. Частотные строки:
насос1 —0, насос2 —3, насос3 —13; D301 соответственно0x0103/0x0203/0x0303.
Это подтверждено структурой файла, а не живой трассой FUN150.
FATEK описывает WR+0 как low byte номера транзакции и high byte результата;
WR+1 — high byte адреса станции / low byte кода функции. При интерпретации
ошибки нельзя принимать весь D300 за чистый номер строки. Режим выполнения
и актуальность WR также проверять по реальной конфигурации, не менять наугад.

Источник описания: FATEK FBs Advanced Application, Chapter13, printed13-46:
https://www.esea.cz/support/fatek/FBs_Manual/Manual_2/Chapter_13.pdf
Vendor PDF/декомпилированные материалы в публичныйGit не добавлять.

## 4. Проверить native макрос

Оба source mirror известной r8/r10 совпадают с
`assets/hmi/panel-services-r8/panel_services.c`, но неизвестный native-save
нельзя считать тем же файлом. После штатного Compile проверить реально
сгенерированные объявления PumpAnimTelemetry (R2500,26bytes/13WORD),
PumpAnimRoles (R2320,14), PumpAnimManual (R2380,6), PumpAnimLeader (R2304).
Доступы частоты[0..2], качества[10..12], MapVersion=AlarmWords[4] отR2550.
Смещения не сочинять и не переносить из синтетического host IN.

В C данные давления не входят в условие анимации. Условия общие для трёх:
нормальная связьHMI, карта32, отсутствие бита потери связи ПЧ, согласованные
частота/качество и READY. Глобальный сбой карты обычно затрагивал бы и1.
Компонентные host-проверки уже прошли; их повторение не заменяет live-данные.

Выдать компактный отчёт: значения с временем, найденная ветка, точные
исправленные файлы/сети/объекты, результат native проверки и оставшиеся
непроверенными пункты. Если причины ещё нет — так и указать, без заявления
«анимация исправлена». При исправлении сохранить исходники и независимые
таймеры r10, включая разрешение равной/меньшей второй задержки.

Не выполнять аппаратные Download/Force/RUN или изменение параметровПЧ.
Для виртуальной Simulation действуют разрешения прежнего задания.
Публично сохранять только проверенные собственные helpers и краткую сводку,
без полных native-проектов/сырых логов/фото.

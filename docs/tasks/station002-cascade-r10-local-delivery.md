# Локальная пара r10: независимые задержки, быстрое снятие ведомых, таблица аварий

Создай готовые новые PDW/SKM по manifest этого pinned-коммита. База — рабочие
r8 HMI + manual-no-sensor-r3 PLC. Пользователь подтвердил ручной пуск без
датчиков/автопереход. AUTO заработал после изменения R2110 с0 на допустимое
значение на главном экране. Не менять guard R2110 и не пересоздавать старые
проекты вместо подготовки этой новой пары.

Уточнение пользователя имеет приоритет: **не проверять, что задержка второго
больше первой**. Обе независимы: равная/меньшая вторая разрешена. Начальное
значение второй30с; существующая первая сохраняется. Не возвращать ранее
рассмотренное сравнение и автоматическое увеличение второй.

1. Получи `artifacts/station002-cascade-r10/delivery-manifest.json` из того
   же pinned-коммита. Скачай его files[] по rawBase, проверь размер/SHA каждого.
   Нужны5 Python helpers и interface; достаточно Python3stdlib. Не ставить
   новые редакторы, Wine, DLL, глобальные Python dependencies или шрифты.
2. Создай новую обычную папку
   `C:\Users\user\CodexProjects\pump-station\.worktrees\station002-cascade-local-10\`.
   Не затирай исходники, предыдущие кандидаты, native-save или пользовательские
   несохранённые изменения. Точная текущая база обычно здесь:
   `C:\Users\user\CodexProjects\pump-station\.worktrees\station002-panel-services-local-08\`.
   Найди по прежнему отчёту оба точных источника:
   - `station_3p_24MC_HP_countdown_manual_no_sensor_r3.pdw`,185409байт,
     SHA3b1ffdac9646a525b3e2113bc60c93bdaa3efc3b48ada20ee3b5246d5ca6ad9c;
   - `pump_station_3p_services_r8_candidate.skm`,1272222байта,
     SHA587038bbe7f0bb59299e37fac092a6dd4ec484b9529bec2e8f78c05f69339280.
   Если другой SHA — сохранить его и найти точный кандидат, не ослаблять guard
   и не терять дополнительные native-правки. Fallback manifest r8 указан в
   manifest r10: воспроизведение из прежних точных источников разрешено, но
   не выдавать такое воспроизведение за сегодняшнее новое исправление.
3. В новой папке, сохраняя структуру tools, выполнить три сборки:

```text
python -S -B tools/repair_alarm_table_r9.py --source "ПОЛНЫЙ_ПУТЬ_К_R8.skm" --out pump_station_3p_alarm_table_r9_candidate.skm --report hmi-r9-build.json
python -S -B tools/build_cascade_r10.py --source "ПОЛНЫЙ_ПУТЬ_К_MANUAL_R3.pdw" --out station_3p_24MC_cascade_r10_candidate.pdw --report plc-r10-build.json
python -S -B tools/build_cascade_hmi_r10.py --source pump_station_3p_alarm_table_r9_candidate.skm --out pump_station_3p_cascade_r10_candidate.skm --report hmi-r10-build.json
```

4. Доведи до готовой пары и проверь:
   - PDW187549байт,SHA b5de31e3fddd45041c8f11b97be94eb55cf13f7aad7b63f3467707227c192a8b;
   - SKM1287912байт,SHA e7752b52bfbbc9e74f04391aa0aa9ffc09e9437cc189d55632a41401495c76f4.
   Собственная файловая сборка/хеши не являются native-приёмкой.
5. Через установленный WinProLadder открыть именно новый r10. Проверить CPU
   FBs-24MC/retain и F8. До загрузки сверить R2884..2898 в исходном manual-r3
   через F7: новый диапазон не должен пересекать прежние внешние привязки.
   Статически explicit-ссылок/9таблиц/буферов в этом диапазоне не было,
   источник имеет RetainR0..R2999. Ошибки F8 разбирать по точным сетям новой
   копии. Прежние duplicated-coil warnings не считать автоматически новым
   отказом: записать error/warning counts и реальные новые сообщения.
6. Открыть конечную HMI-r10 через File→Open в установленном SKTool, Compile,
   затем Offline Simulator без связи с оборудованием. Сохранение нативного
   результата — под отдельным *_native.skm, не поверх exact-кандидата.
   Проверить «Каскад»:8ровных строк, задержки1-го/2-го и «Быстрый останов
   ведомых ниже, Гц», нет наложений; баннер/кнопки/footer помещаются800×480.
   Значения 1-й/2-й могут совпадать или быть в обратном порядке.
   Новые inputs требуют R2886=27116 и старый STOP/edit enable M1464;
   без ПЛК offline редактирование закономерно заблокировано.
7. ОБЯЗАТЕЛЬНО открыть «Аварии»: даже при0 и без связи должны быть видны
   рамка/заголовки/сетка HAD8288; весь текст по ширине. r8 ошибочно меняла
   служебный QString36на24; r9 возвращает36, r10 сохраняет это исправление.
   Его точная семантика как headerheight не доказана. Не выдавать Compile,
   directory или SHA за наблюдение таблицы. Если сетки нет — зафиксировать
   точные свойства HAD8288 и фактический результат, не объявлять успех.
8. Анимация остаётся отдельной диагностикой. Пользователь: P1 вращается с
   задержкой, P2/P3 в MANUAL показывают «Нет данных», шкалы меняются ступенями;
   давления у2/3нет. Отсутствие датчиков не входит в условие анимации частоты
   ни в точном C, ни в PLC quality. Все3ротора/BG имеют отдельные bindings;
   21 C/50 PLC host checks не подтверждают живую телеметрию.
   После native Compile проверить generated MacroInit.h/IN: PumpAnimTelemetry
   отR2500 — Batch26bytes/13WORD, индексы0..2частота/10..12качество; Roles14,
   Manual6, MapVersion=AlarmWords[4] отR2550. Не публиковать полный generated
   vendor header, достаточно результата сверки смещений/типов.
   Если доступен уже существующий read-only online-сеанс, без нового опросчика
   и без изменения оборудования получить фактические R2500..2502,
   R2510..2512, R2550/R2554, X1..X3/M610..612 и соответствующие LW900..905
   при работе2/3. Иначе подготовить эти адреса в отдельной Status Page и
   указать конкретный оставшийся снимок. Компьютер и HMI используют общий
   Port0 — не переключать его самостоятельно и не заявлять одновременно
   измеренные PLC/HMI значения без временнóй привязки.
   Рисовать вращение по RUN/уставке вместо достоверной частоты нельзя.
   Живые stale/link/quality ошибки не маскировать увеличением watchdog.
9. Каскадная приёмка в доступной native Simulation: ведущий+2ведомых;
   остановка/частота ниже порога снимает оба, на равенстве быстрое снятие
   не срабатывает; ведущий стартует с0без блокировки. При восстановлении
   повторное добавление проходит заново через независимые выдержки.
   Показать примеры10/30,30/30,30/5с: все допустимы, счётчики не наследуют
   время друг друга, отмена запроса сбрасывает отсчёт. Сухой ход/питание/
   HP/аварстоп/ручное без датчиков остаются. Это второй ведомый по порядку,
   а не физический насос2; ведущий может быть любым. Если Simulation
   недоступна — честно отметить, не подменять её Python/дизассемблированием.
10. Обновить локальный HANDOFF/краткий отчёт: абсолютные Windows-пути готовых
    PDW/SKM/отчётов, SHA/размер, F8, Compile, фактический осмотр8строк и сетки,
    результат сверки native MacroInit и что осталось по живой анимации.
    Если GUI недоступен, файлы всё равно довести до готовой пары и назвать
    конкретно недоступные проверки. Старый CLI-start с Tips/закрытием
    Simulator не повторять, чужие окна/процессы не закрывать.

В реальное оборудование автоматически не загружать; аппаратные
Download/Force/RUN и параметрыПЧ не выполнять этим заданием. В явно
отключённой от оборудования Simulation разрешены необходимые действия
с виртуальной CPU/входами для перечисленных сценариев. Предыдущая рабочая пара сохраняется.
Полные native-проекты, vendor binaries, сырые desktop/logs в публичныйGit
не добавлять. Краткая сводка и собственные проверенные helpers — можно.

# Добавить в HMI «Бабанов» памятку CHINT XJ3-D

16.11.2026. Пользователь попросил инструкцию в картинках к «Аварии питания»
и сообщил модель **CHINT XJ3-D AC 380**. Разрешена подготовка отдельной
HMI-копии. В облаке готов макет/проверены значения по руководству, native
HMI с памяткой ещё нет. Сборку и упаковку старого комплекта не повторять.

Прочитай `docs/ui/station002-rkf-help.md`: там источник, тексты и приёмка.
Для этой задачи используются только HMI и графика; программу ПЛК не менять.

## Перенос в SKTool 7.1

1. Создай отдельную приватную папку, например
   `_release_private\Бабанов_R18_РКФ_2026-11-16`, скопируй туда PNG.
   Открой r17a в SKTool и сохрани **новым** именем
   `pump_station_3p_babanov_r18_rkf_help_native.skm` в этой папке.
   Native/SKM/JPEG и итоговый архив в Git не добавлять.
2. Создай штатными средствами редактора новую полноэкранную страницу
   **Screen17**, 800×480, заголовок «Памятка РКФ». Пусть SKTool сам расширит
   все служебные таблицы страниц. Не собирать бинарные page/alarm-структуры
   по старым генераторам r15: прежние Illegal opening уже устранялись.
3. Размести PNG как Static Picture, вписав в 800×480. Это памятка с четырьмя
   примерами, не текущие показания ламп. Не связывай кружки с X7/таймером/
   общим битом аварии. Лампы слева направо: PHASE FAILURE / OVERVOLTAGE /
   UNDERVOLTAGE. Все погасшие при наличии аварии не означают «норму».
4. Нижние картинки кнопок перекрой настоящими Screen Button в привычном
   стиле, с областями высотой не менее 44 px: слева «Назад к авариям»,
   справа «На главный экран». Правая открывает Screen1; левая — существующий
   экран «Аварии и история», его номер установи по открытому проекту.
   Не угадывай номер по старым инструкциям. Не привязывай скрипты/команды.
5. На существующем экране «Аварии и история» добавь в свободном месте
   кнопку **«РКФ: что делать?»**, открывающую Screen17. Сохрани размеры
   журнала, его колонки и остальные действия. При необходимости используй
   свободную область рядом с навигацией, проверив отсутствие перекрытий.
   Кнопка доступна и для чтения прошлой аварии. Не открывай справку
   автоматически, не меняй текст/условие/подтверждение старой alarm-группы.
6. Сохрани новый r18, закрой/открой его заново. Проверь Compile всего
   проекта, затем Offline Simulator: журнал → памятка → оба возврата.
   Не принимай сохранённый номер в диалоге за проверку перехода; ранее
   поля Screen Button откатывались, нужен наблюдаемый результат.
7. Проверь читаемость всех четырёх строк на 800×480, соответствие рисунка
   левому/среднему/правому индикатору, отсутствие перекрытий, работающие
   native-кнопки. Зафиксируй реальный результат Compile/Simulator.

До/после сверь сохранность 7 alarm-групп/268 привязок, обеих таблиц макроса
и C-исходника (SHA256 C:
`e02de39aca683e81fedf743b3de9e434404605c47301f0d441d30ae572ce61e5`).
Остальные экраны и действующие настройки сохранить: Main Diagnostics →4,
зонд13, logo14, коды/сброс15, запуски16; загрузочный логотип4с и заставку1мин.
Новые цели помощи — Screen17; номера и назначение старых страниц не менять.
Общий скрипт/опрашиваемые адреса/FC06/STOP guard/таймеры и PLC r15 прежние.

Если автоматизация не видит редактор, установи реальный доступный UI,
зафиксируй конкретный блокер и оставь копию/PNG/краткие оставшиеся действия.
Не выдавай PNG или создание файла за готовый native r18 и не начинай
повторный цикл старых Open-тестов, переустановок и пересборок r15.

## Результат

Выдай полный Windows-путь к реально созданному r18, размер/SHA и статус
повторного Open, Compile, Simulator. Приложи снимок страницы в симуляторе.
Запиши отчёт/HANDOFF и опубликуй только относящиеся документы по порядку
проекта. При успешной проверке положи неизменённый PLC r15 и оригинальный
JPEG вместе с новым HMI/PNG/README в отдельный комплект «Бабанов R18 РКФ»;
старый r15+r17a ZIP сохранить. В README отличай native-проверку справки
от ещё не выполненной проверки оборудования. Загрузки в шкаф здесь нет.

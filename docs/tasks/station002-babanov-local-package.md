# Локальный комплект «Бабанов»: собрать папку и ZIP, выдать полный путь

Пользователь не может скачать облачный архив и поручил собрать такой же
комплект на ноутбуке. Выполни упаковку из уже существующих локальных файлов
до готового ZIP. В конце покажи **фактические полные Windows-пути к ZIP и
папке комплекта**. Одного плана или предполагаемого пути недостаточно.

## Исходники

Сначала проверь рабочую папку:

```text
C:\Users\user\CodexProjects\pump-station\.worktrees\station002-fault-reset-local-15
```

Нужна окончательная native-пара, переданная пользователем в облако:

| Файл | Байты | SHA256 |
| --- | ---: | --- |
| station_3p_reset_r15_native.pdw | 206320 | d45ada8b0781175cf5c4a91e14a2f4bf23d9c037957ce830da44c1daca2e58ae |
| pump_station_3p_native7_r17a_diagnostics.skm | 1479870 | 3fa5c20f4ab9c4568853648a654070bc2872f60356033088cd8323001dea00e1 |

Если файла нет рядом, найди его по имени/размеру среди локальных копий
проекта, сохранений и Downloads/Documents/Desktop пользователя. Сверяй
хеш подходящих файлов; не проси пользователя вспоминать путь. Не заменяй
окончательный PDW старым `*_candidate.pdw`, а HMI — r17/r15 или ранним r17a.
Существующие более новые правки не перезаписывай. Если точного исходника
не нашлось, укажи конкретный отсутствующий файл и найденные отличия;
не выдавай другой файл за принятую пару.

Оригинальный JPEG логотипа ищи по фактическому пути:

```text
C:\Users\user\Documents\HMI\Samkoon\Automatika визитка print.jpg
```

Если там его нет, проверь сохранённую копию `assets\automatikakg.jpg` в
worktree15 и прежних локальных сохранениях. Используй оригинальные байты,
не скриншот и не перерисовку. Если оригинал отсутствует во всех этих местах,
собери комплект из двух проектов, явно отметив отсутствие внешнего JPEG.
Не задерживай сам ZIP из-за этой дополнительной зависимости.

## Что сделать

1. Прочитай актуальные верхние записи AGENTS/HANDOFF, сохрани чужие местные
   изменения. Старые задания Open/SaveAs/Compile уже завершены и не являются
   частью этой упаковки. Скачивать native-файлы из Git/облака не требуется.
2. Создай отдельный приватный каталог внутри известного worktree15:

   ```text
   _release_private\Бабанов_2026-11-13_PLC_r15_HMI_r17a
   ```

   До копирования исключи `/_release_private/` локально через git exclude
   (путь получи штатно через `git rev-parse --git-path info/exclude`, учитывая
   worktree). Не меняй глобальные настройки Git. Готовые проекты, JPEG и ZIP
   не добавляй в индекс и не публикуй в Git.
3. Скопируй оба точных native-файла в корень каталога, не меняя их содержимое
   и имена. Если JPEG найден, положи его в `assets` и запиши его размер/SHA.
   Исходники на месте оставь без изменений. При совпадении существующего
   комплекта можно его использовать; при отличиях создай новый каталог
   с суффиксом времени, не затирай прежние результаты.
4. Добавь UTF-8 `README.txt` и `manifest.json`: метка **«Бабанов»**, buildID
   `babanov-20261113-plc-r15-hmi-r17a`, дата упаковки, имена/размеры/SHA
   вложений, статус JPEG и абсолютный исходный путь к логотипу. В README
   укажи: PLC r15 native + HMI r17a с исправленной главной «Диагностикой»
   на Screen4; WinProLadder Syntax Check — 0 ошибок / 25 прежних W85;
   аппаратная приёмка сброса ещё впереди. Упаковка не меняет программы.
5. Сохрани существующую ссылку SKM на JPEG в Documents. Наличие копии в
   `assets` служит резервом и само по себе не делает ссылку относительной.
   Для другого ПК README должен объяснять: восстановить исходный путь
   либо позднее перепривязать оригинал в SKTool с отдельной проверкой.
6. Создай ZIP **рядом с папкой комплекта**, не внутри неё:

   ```text
   _release_private\Бабанов_PLC_r15_HMI_r17a_2026-11-13.zip
   ```

   Используй имеющийся Python/PowerShell, без установки ПО. Архив должен
   содержать два проекта, README/manifest и JPEG, если найден. Не включай
   сам ZIP, посторонние исходники, настройки пользователя и старые сборки.
   При занятом имени сохрани существующий архив и используй суффикс времени.
7. Проверь размер/SHA копий проектов по таблице, целостность ZIP и совпадение
   прочитанных из ZIP байтов с файлами комплекта. Запиши фактический SHA ZIP
   вне архива, например рядом в `.sha256.txt`. Его SHA не обязан совпадать
   с облачным: здесь могут отличаться JPEG, README и ZIP-время.
8. Запиши результат и реальные пути в короткий локальный отчёт/HANDOFF.
   По порядку репозитория публикуй только относящиеся документы, без
   native/JPEG/ZIP и без изменения main. Публикация отчёта не заменяет ZIP
   на ноутбуке. Повторные Open/SaveAs/Compile/Simulator и общие тесты кода
   для побайтного копирования не нужны; к оборудованию не подключаться.

## Финальный ответ локального

Проверь существование обоих путей и выдай их полностью, без сокращений:

- **ZIP:** `C:\…\Бабанов_PLC_r15_HMI_r17a_2026-11-13.zip`
- **Папка комплекта:** `C:\…\Бабанов_2026-11-13_PLC_r15_HMI_r17a`
- Список вложений; совпадение двух project-SHA; JPEG включён либо отсутствует.

Вместо многоточий должны быть настоящие абсолютные пути на этом ПК,
с учётом фактически выбранных суффиксов. Не выдавай облачный `/workspace`
или путь к файлу задания за путь к готовому комплекту.

# Точный нативный эталон группы R3056/80 в SKTool 7.1

Полная HMI пока не принята: после r15d пользователь снова показал
«Illegal opening of configuration file!». Локальный af1c121 подтвердил
создание exact r15d, но собственного native Open не выполнил.

Оператор теперь подтвердил **успешное открытие C_native_alarm_sample.skm**.
Он содержит исходную «События станции» и Digital Alarm Login1/LB1/Size1/TEST.
Повторять его изготовление и старые CONTROL/A/B/C/r15c/r15d не требуется.
Этот эталон подтвердил общий формат двух групп и внутреннего бита. Для
рабочих аварий используются слова ПЛК с 80 битами: нужна именно такая
штатная запись, чтобы сравнить её с генератором.

## Создать один эталон штатным редактором

1. В уже открывающемся **C_native_alarm_sample.skm** выполнить File→Save As
   в отдельный **C_native_R80_sample.skm**. Исходный образец сохранить.
2. В Alarm Login открыть **Digital Alarm Login1**, содержащую TEST.
   Выбрать Type **Continuous Bit of Word** — последовательные биты слов.
   Read Address: **R3056**, с тем же подключением Fatek FB Series/станцией,
   что у существующей «События станции»/R2550. Параметры самой исходной
   группы R2550 не менять. Size: **80**. Первое сообщение оставить **TEST**,
   новые строки — штатные. Имя новой группы можно оставить прежним.
3. Сохранить, закрыть и снова открыть **C_native_R80_sample.skm**. Зафиксировать
   реальный результат открытия. Если адрес/размер/тип не принимается,
   сохранить точный текст отказа/снимок полей; не подменять их бинарной правкой.
4. Дать оператору полный путь для приватного прикрепления нового SKM в чат.
   В публичный отчёт — размер/SHA и результат Open. Native SKM, vendor и
   оригинальные изображения в Git не добавлять.

Выполнить через доступный GUI локальному либо дать оператору эти конкретные
шаги. Отсутствие окна в агентском сеансе не означает, что его нет у оператора:
тот уже показал редактор и подтвердил открытие нативного образца. Не
останавливаться на циклах Tips/CtrlO, не менять модель и не угадывать тип
адреса. В этом эталоне не нужны Compile, Simulator, PLC или аппаратные команды.

Оригинальный образец ранее сохранён здесь (путь подтверждён метаданными):

```text
C:\Users\user\CodexProjects\pump-station\.worktrees\station002-open-isolation-local-15b\open-tests\C_native_alarm_sample.skm
```

Если файл фактически перенесён, найти по SHA256
`0ecac7d67dcfc42648f8f468098fadb7b84b782ae4fd6f70f944195ca0947c3f`,
1298542 байта. Не изменять исходник. Пользовательский ответ Open PASS уже
принят и не должен снова превращаться в pending.

## Параллельная подготовка диагностических копий

`prepare_alarm_open_differential.py` делает три **OPEN-ONLY** копии из
трёх fingerprint-locked источников: accepted3599, full r15d9a и native0ec.
Их можно подготовить без GUI, пока оператор сохраняет R80-эталон. Это не
новая production-прошивка и не основание объявить отказ исправленным.
Пакет описан в `artifacts/station002-r15d-open-differential/delivery-manifest.json`;
код/размеры/SHA брать из этого manifest, инструменты только Python stdlib.

Скачать пять files[] в отдельную подпапку tools в `open-check-r15d`.
Source accepted — уже найденный «бабанов байтик.skm»,
1273673 байта/SHA359906…b4c. Полная r15d находится в прежнем пакете15,
1480005 байт/SHA9a4829…8bb. Native образец указан выше.

```text
python -S -B tools/prepare_alarm_open_differential.py --accepted "ПУТЬ_К_accepted.skm" --full-r15d "ПУТЬ_К_pump_station_3p_fault_reset_r15d.skm" --native-sample "ПУТЬ_К_C_native_alarm_sample.skm" --out-dir probes
```

Выходная папка должна быть новой. Скрипт выводит **полные пути**:

- OPEN_NATIVE_ONE_R80_GROUP.skm — нативная основа с исходной R2550 и
  одной сгенерированной группой R3056/80; число групп остаётся два.
- OPEN_ONLY_ALARMS_7.skm — рабочая исходная HMI с семью новыми группами,
  без остальных доработок r15d.
- OPEN_FULL_WITH_ORIGINAL_ALARMS.skm — вся r15d с исходной одной группой;
  это восстановление ранее недоступного оператору D в новой явной папке.

Сверить каждый итог с outputs[] manifest, сохранить sources. Не сообщать
только имена файлов и затем просить оператора искать отсутствующий путь.
При ещё не полученном R80-эталоне допустим один первый Open
OPEN_NATIVE_ONE_R80_GROUP; при отказе оставить остальные пробы до сравнения
нативного R80. По эталону решить, какие из оставшихся Open действительно
нужны; не назначать все три повторно без нового основания.

После получения нового native SKM сравнить точные поля/границы его R-группы,
контролировать языки/флаги/тип/количество, затем исправлять проверенный
дефект и пересобирать полный результат. Сохранить C/Batch16/BootAck,
пользовательскую раскладку и HAD. ПЛК и условия reset в этом шаге не менять.
Обновить HANDOFF и компактный отчёт в handoff-ветке. Main не менять.

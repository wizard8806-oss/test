подтвердил подготовку копии/измерение размеров/Compile/Save, запуск на Server

вывода Client. Нового запуска сборщика/компиляции без изменений не требуется.
Пользователь предложил открывать окна и снимать их; использовать эту помощь
с конкретным указанием вместо ещё одного цикла без визуального результата.
Он также разрешил отправлять запросы в уже настроенный Telegram: использовать
существующий локальный механизм оповещений/чат оператора, без повторной
настройки бота, публикации токенов или выбора новых получателей. Проверить
доступность механизма локально и не объявлять доставку без результата отправки.
Если механизма нет в текущем сеансе, запрос дать в текущем чате и продолжать
независимую работу. Облачный Codex сам Telegram-канал не проверял.

1. AGENTS/HANDOFF → статус Git/местные изменения → актуальная ветка без потерь.
   Найти подготовленный layout-кандидат/манифест/локальный отчёт и сохранённые
   размеры. В публичном итоге8294d29 этих значений нет; сохранить в следующем
   отчёте допустимые metadata: имя копии, SHA Pages/Scripts, измеренные размеры/
   DPI, версию Editor/Client. Не публиковать private-профили/лицензии/пароли.
   Сверить готовую копию с манифестом; исходные11/10 не заменять. Не выбирать
   UNVERIFIED/event-probe/первый попавшийся похожий каталог.
2. Использовать уже допущенный штатный режим GUI вне sandbox. В этом контексте
   установить монитор Client и bounds виртуального экрана, client-to-screen
   координаты, DPI. На втором мониторе X/Y могут быть отрицательными, origin
   клиентской области не равен origin монитора. Не использовать старые HWND/
   PID/позицию1366×768 как текущие измерения. Два монитора сами по себе не
   объясняют отсутствие окон в EnumWindows или все отказы PrintWindow.
3. Штатно показать Client готовой layout-копии и подтвердить совпадение с

   Client на основном экране и назвать вкладку («Обзор станций», затем

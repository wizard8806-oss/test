# SCADA R2 и радио03: единое локальное продолжение

Основание — поручение пользователя объединить следующую задачу с последним
заданием по радио. База приёма45f812e; код пакета/исправленной карточки из
dfdd4cb уже включён. [Последний результат](../reports/station11-card-composition-r2-progress-20261103.md):
R2 Compile/Save и активная карточка в Client подтверждены, OnClick/радио/
автозапуск ещё не проверены. Это задание не повторяет создание R2.

## Приём и оставшиеся UI-проверки

1. Прочитать AGENTS/HANDOFF; branch/HEAD/status/index/untracked, получить
   handoff-ветку с сохранением всех местных изменений/коммитов. При грязной
   папке использовать изолированный worktree, без reset/clean/авто-stash.
2. Продолжить существующую `codex_diag_11_review_station_card_r2_20261103`.
   Найти её по локальным манифестам/Projects/CodexCandidates, самому записать
   фактический путь, SHA Pages/Scripts/ресурсов и кодовую версию. Не просить
   у пользователя хеши, не брать старые174000z SHA, не пересоздавать/Compile
   заново без изменения кода. Старое требование «сначала показать R2» закрыто.
3. Проверить верхние вкладки и оставшиеся безопасные действия: отдельное окно,
   +/−/Отмена с возвратом черновика без Apply, открытие аварий/истории/графиков.
   Отделять реально работающую функцию от понятного сообщения о ненастроенной
   группе. Не подтверждать/очищать аварии ради этой проверки. Проверить
   длинные подписи/доступные размеры; кадр просить только для нового состояния/
   нерассмотренной страницы. Оператор уже предложил помощь и разрешил запрос
   через существующий Telegram-notifier. Настройки бота/секреты не публиковать.
   Держать один управляющий SCADA-проект. Уставку/пуск/сброс/режим оборудования
   ради UI не менять. При необходимой UI-правке сохранить R2 и работать в копии.

## Причина ошибки публикации радио

4. Выполнить [радио02: чтение](radio02-publish-readonly-check.md): source SHA,
   PID существующего писателя, конфигурация Service9336, файлы/атрибуты/права,
   run/seq/возраст в двух наблюдениях. Не запускать второй02/03, не удалять
   collector.lock и не завершать все PowerShell. Старый HResult недоступен:
   дочерний powershell.exe завершился; Error родителя этого не восстановит.
5. Назвать доказанную причину/владельца препятствия. Если нужен probe совместного
   доступа Windows — допускается OPEN_EXISTING существующего radio.txt с
   запросом DELETE-access и share READ|WRITE|DELETE, затем закрытие handle:
   **без DeleteFile, FILE_DELETE_ON_CLOSE, записи, переименования или удаления**.
   Это позволяет проверить отказ sharing/доступа, но не заменяет полный диагноз
   прежней ошибки. Записать фактически полученный Win32Error/type/HResult,
   не текст исключения с приватными данными. Если причина не установлена,
   прямо записать ограничение, не называть IO исправленным.
6. После установления причины выполнить конкретное обратимое исправление
   только необходимого файла/процесса/доступа. Эта фаза расширяет прежнее
   задание «только чтение» в рамках порученного исправления/автономизации:
   не останавливаться на плане и не просить новое общее согласие. Не давать
   Everyone FullControl, не править рабочие SCADA/ПЛК/HMI вслепую. Если виноват
   reader SCADA, исправить воспроизводимый source в отдельной копии R2 и
   подтвердить native Compile/Save. Сохранить рабочее состояние/путь возврата.

## Подготовка и активация автоматического запуска

7. Прочитать [пакет03](../../artifacts/radio-autostart-03/README.md) и
   [технический порядок](radio-autonomous-startup.md). Проверить hashes/source/
   Windows PowerShell5.1 x64 и необходимые права. Выполнить Manage Prepare:
   код/конфигурация/DPAPI LocalMachine в закрытом SYSTEM/Admin ProgramFiles,
   зарегистрированная задача пока отключена. При существующих каталоге/задаче
   проверить происхождение и продолжить сохранённую установку; не перетирать
   её и не вводить ключи заново без причины. Действующие ключи M2M24/модема
   вводятся один раз в локальном окне; пароль оператора SCADA им не замена.
8. Проверить action/principal/ACL/учётную запись, source/config/credential
   integrity и исправную публикацию. Сначала штатно освободить только
   установленного старого писателя; сохранить02 и конфигурацию для возврата.
   После успешных проверок выполнить отдельный Enable -PublicationVerified.
   Один PID/писатель/сессия на группу. START_REQUESTED не является PASS:
   проверить реальный SYSTEM process, run/seq/sample/publication age,
   STATUS и состояние радио в SCADA, отсутствие окна/Read-Host.
9. Проверить повторный старт без дубля, обычное восстановление сети,
   устаревание/недоступность радио и сохранность UI/Main/ПЛК. Для
   CLOUD_SESSION_REPLACED подтвердить останов конкуренции; exit0/TaskResult0
   не считать здоровьем радио. Перед любым воздействием на общую сеть
   проверить границы: не отключать весь ноутбук/канал ПЛК ради радио-теста.
   Boot без входа проводить только после сохранения открытых проектов и
   согласования момента с оператором; иначе записать boot not tested и
   закончить остальные проверки. Не объявлять полную boot-приёмку заранее.
10. Если новый запуск не прошёл — отключить именно свою задачу, штатно
    восстановить проверенного писателя/конфигурацию, зафиксировать PID/путь/
    состояние. Не оставлять скрытый цикл повторных сессий или две копии.

## Отчёт и передача

Codex сам обновляет отчёт/HANDOFF, сохраняет согласованные изменения в
handoff-ветке и проверяет remote SHA. Указать версию/пути/SHA/UI-действия,
диагноз IO и исправление, task/principal/ACL, run/seq/возраст, credential
read под фактической учётной записью, пройденное/пропущенное и активное
состояние после опыта. Публиковать только код/шаблоны/обезличенный отчёт;
не включать credentials/blobs/приватные конфиги/архив/полные command lines.
Формы/inline-графики/полное соответствие макету остаются отдельной незакрытой
частью: открытие native истории не выдавать за уже встроенный график.

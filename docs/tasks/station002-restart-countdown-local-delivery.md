# Доставить PLC/HMI с отсчётом автоперезапуска

Пользователь подтвердил завершение предыдущей локальной трёхнасосной
сборки, открытие файла и выполнение F8. Не повторять это задание вместо
нового требования: теперь нужны **два новых файла** с индикацией отсчёта.
Оригиналы и пользовательские native-save сохранить. В PLC/HMI/ПЧ ничего
не загружать, к действующей SCADA не подключаться и её не менять.

## Создать готовые файлы

Manifest `artifacts/station002-restart-countdown-01/delivery-manifest.json`
взять из того же закреплённого коммита, что и это задание. Все files[] скачать
по указанному rawBase с проверкой размера/SHA, сохранив относительные пути.
Python3stdlib достаточно, GUI/DLL/pip/git fetch для генерации не нужны.

1. Новая доступная папка: `.worktrees/station002-countdown-local-01/` либо
   аналогичная без перезаписи. Не создавать worktree ради этой операции.
2. PLC-source: ранее полученный `station_3p_24MC_HP_auto_r1.pdw`,184126байт,
   SHA256 `a6e9c5c057ad324635c10e73b61f25ceb08604c4651eaaf943880f2dc176c745`.
   Сначала проверить `.worktrees/station002-three-pump-local-01/` и его отчёт.
   При изменённом native-save сохранить его; точную генераторную копию можно
   воспроизвести по уже выполненному заданию a6b977d из точной HP-r2 в новой
   подпапке. Guards не ослаблять и свежий native-save не подменять старым.
3. HMI-source: принятую `pump_station_unified_2-4_layout_r1.skm`, SHA
   `d9f089f09b87fff4cb347664457fbfa171f297defd96a2fd713b65da23f43175`,
   либо сохранённый исходный `pump_station_unified_2-4_draft.skm`, SHA
   `7484c9475391201b37d408a68e63233b970a7d33c77e276cdbf7376539a2e5e7`.
   Оба1321783байта. Проверить прежний HMI-layout-report/source-lock/папку
   HMI-проекта; не искать заново редакторы/desktop. Draft генератор сам
   переводит в тот же принятый r1 по включённому проверенному рецепту.
   Изменённый native-SKM с другим SHA не патчить вслепую и не перезаписывать.
4. Выполнить из новой папки:

```text
python tools/build_restart_countdown_pdw.py --source "ПОЛНЫЙ_ПУТЬ_К_3P-r1.pdw" --out station_3p_24MC_HP_countdown_r2.pdw --report countdown-local-plc-build.json
python tools/build_restart_countdown_hmi.py --source "ПОЛНЫЙ_ПУТЬ_К_ПРИНЯТОЙ_HMI.skm" --recipe artifacts/station002-hmi-layout-01/layout-recipe.json --out pump_station_3p_countdown_r2.skm --report countdown-local-hmi-build.json
```

5. Проверить точные размеры/SHA выходов по manifest:
   PLC185409байт/SHA780267f8…791b73b,29сетей; HMI1321783байта/SHAee8c98b9…d86cc9,
   108типизированных изменений. Проверить неизменность обоих source.
6. Проверить внешнюю картинку ST0 по пути из HMI-отчёта:
   `C:/Users/user/Documents/HMI/Samkoon/Насоска HMI/pumps-3.png`.
   В пакете есть согласованный assets/hmi/vertical-pumps/pumps-3.png, SHA
   `9989d24f65b3868fca13b905ab8e9c99c2d9e15161c349900a21170de54957a1`.
   Если требуемого файла нет, скопировать его в используемую HMI-папку,
   сохранив существующие файлы. Если там другая картинка, её не заменять
   вслепую: сообщить конфликт и оставить новую картинку в пакете для выбора
   через штатное свойство ST0. Недоступность картинки не причина не создать
   два native-файла; назвать конкретный оставшийся шаг до компиляции HMI.
7. Сообщить **абсолютные Windows-пути обоих готовых файлов** и отчётов,
   размеры/SHA. Доставку довести до файлов, не только скачанных helpers.

## Нативная проверка и поведение

Открыть **новый** PDW и выполнить его F8, если GUI доступен; старый F8 r1
не переносить на r2. Обычные W85 пользователь отложил: не удалять цепи ради
их исчезновения. Открыть новый SKM в SKTool, выполнить доступную проверку/
Offline Simulator без соединения с оборудованием. Проверить3насоса, нижние
7кнопок, блок «ПУСК, с» справа, целые секунды до3602 и прочерк при неактивном
отсчёте. На странице пауз — оставшееся время в строках сухого хода/питания,
неизменённые поля задания и Apply. Не выдавать неподключённый Simulator
с нулевыми данными за проверку отсчёта во времени. Если GUI недоступен,
выдать готовые файлы и передать пользователю только эти конкретные проверки.

Отсчёт берётся из существующих PLC-таймеров. При обоих событиях ждём max,
а не сумму, плюс исходную проверку готовности2с. При действующей аварии или
других блокировках основной индикатор — прочерк/ожидание; обещания «0с» нет.
После окончания источник сам разрешает AUTO по прежним условиям.
Никаких новых команд запуска/сброса/изменений задержек не добавлено.

Интерфейс: R2528 общий, R2533 видимость0/1, R2532 причина0..7,
R2538/2539 строки настроек, R2537=27115. Все эти слова read-only с HMI.
Не изменять R2520..2523/R2540..2542, M330 или T96 ради теста на оборудовании.
Пути/SHA/результаты записать локально; полные PDW/SKM/журналы в Git не включать.

результата из пустой папки Python `-S`. Также проверены обе HMI-sourceветви,
отказ при неверном source/перезаписи,56snapshot-сценариев,29newgraph,
129регрессий трёхнасосной базы и51группа общего прогона. Это не native-
проверка пары на ноутбуке и не результат соединения с оборудованием.

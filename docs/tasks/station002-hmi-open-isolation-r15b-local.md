# Найти этап native OpenFAIL r15a: рабочий контроль и три отдельных блока

Пользователь подтвердил **новыйr15a**, а не Cancel у старогоr15. Ошибка
SKTool7.1: **Illegal opening of configuration file!**. Значит, точечный
ремонт заголовка был необходим, но всей приёмки не закрыл. Не повторять
прежние r15/r15a как готовую версию. Не запускать новый круг PLC/F8,
смену модели, переустановку редактора или общий поиск ресурсов.

## Изготовить конкретные файлы

Код закреплён на `77095048a60debd321d2aebe1fc82f83f85bb6c2`.
Скачатьmanifest `artifacts/station002-hmi-open-isolation-r15b/delivery-manifest.json`
из того же коммита, что задание. По rawBase скачать15files[], сверить
bytes/SHA, сохранить структуру в новой отдельной папке
`station002-open-isolation-local-15b`. При расхождении точный pin брать из
manifest, а не из предположений. Это stdlib/уже установленный Python.

Источник — **рабочий** `бабанов байтик.skm`, уже найденный в локальном6e5fa03:
1273673байт/SHA359906cfd85975b9d2955f6b03b8f996761a7612fcbf37a23b95c8e5ee6c0b4c.
Не использовать сломанный r15/r15a как source. Не пересохранять source.

```text
python -S -B tools/prepare_hmi_open_isolation_r15b.py --source "ТОЧНЫЙ_ПУТЬ_К_РАБОЧЕМУ_бабанов байтик.skm" --out-dir open-tests --extended
```

Будет8диагностическихSKM и `open-tests/open-isolation.json` с SHA/размерами.
Это **тесты открытия редактором**, не productionr15b. Не Download/неSimulator/
не Compile/не оборудование: частичные файлы намеренно содержат только
выбранные блоки. Оригинал и PLC неизменны. Полные native-файлы не публиковать.

## Нужны фактические открытия

В существующем SKTool7.1 закрыть Warning кнопкойOK, затем File→Open.
Сначала открыть по очереди следующие4файла. Для каждого записать точное
имя/SHA и **Open PASS** либо текст nativeошибки. Нельзя заменить этот шаг
повторным запуском наших Linux/Pythoncheckers.

| Копия | Что отличается от рабочей базы |
|---|---|
| OPEN_TEST_CONTROL_WORKING.skm | Ничего: byte-identical3599 |
| OPEN_TEST_A_PAGES_ONLY.skm | Только страницы15/16 с контролами и их учёт |
| OPEN_TEST_B_ALARMS_ONLY.skm | Только новые группы и тексты Alarm Login |
| OPEN_TEST_C_MACRO_ONLY.skm | Только C и оба списка макропеременных |

Не подменять вкладку Screen16 результатом открытия всего файла. Успех:
проект загружен и дерево экранов появилось без Warning; допустима отдельная
пометка о недоступной внешней картинке. Снимок с пустым деревом и ошибкой
означает OpenFAIL. Если GUI не виден локальному процессу, всё равно создать
файлы и дать оператору эти4пути для реального File→Open; не застревать в
Tips/CLIзапусках. Сейчас оператор показал настоящее окно SKTool.

Интерпретация и уже подготовленные уточнения:

- Если CONTROL не открывается — проверить оригинальный accepted3599 в том
  же экземпляре редактора. Тогда отказ не отделён от базы/среды; не обвинять
  новые блоки без этого контроля.
- Если A не открывается, открыть `OPEN_TEST_G_EMPTY_PAGES_ONLY.skm`:
  там только две **пустые** страницы. Это отделяет обрамление страниц от
  новых контролов. После результата понадобится точечный разбор/native
  сохранение минимального элемента соответствующего типа в SKTool7.1.
- Если B не открывается — нужен минимальный пример, штатно сохранённый
  SKTool7.1 с одной дополнительной группой Alarm Login. Схема cached7.0/ELF
  не считается доказательством формата7.1; по непроверенной догадке trailing
  поля не дописывать.
- Если C не открывается — отдельно проверить нативный формат новых Batch
  записей/макроса; `OPEN_TEST_E_FULL_WITHOUT_MACRO.skm` даёт сравнение.
- Если все A/B/C открываются, но полный r15a нет, использовать уже готовые
  D_FULL_WITHOUT_ALARMS, E_FULL_WITHOUT_MACRO, F_FULL_WITHOUT_PAGES и сверить
  взаимодействие блоков/лимиты. Не выдавать одну удачную частичную копию
  за готовое исправление всего проекта.

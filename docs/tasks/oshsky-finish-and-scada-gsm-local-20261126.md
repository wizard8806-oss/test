## 1. Продолжить текущую копию, закончить четыре дефекта

Сохранить текущие RAM/несохранённые буферы, сверить Git/HANDOFF. Принять
дополнение без reset/clean/stash и отката на старую r3d. Если уже есть более
свежая native-копия/результат, использовать их после проверки, не переделывать.
Разрешения на автономные стендовые проверки и загрузку ПЛК после backup
прежние; повторного общего подтверждения не спрашивать. Фактическое подключение
кабелей после последнего сообщения пользователя пока не подтверждено.

Довести [текущее объединённое задание](oshsky-mode-stop4-and-animation-local-20261126.md):

1. Регулярная остановка ПЧ4 в MANUAL с ошибкой подготовки режима, без Err
   на приводе: первая неудачная транзакция/потеря допуска, минимальная правка
   доказанной причины. Если без четырёх M900G не воспроизводится, закончить
   рабочий native-захват первого события, оставить явный полевой остаток
   и продолжить остальные доступные проверки.
2. Оба активных AUTO-отсчёта: запуск/снятие, физический номер насоса и секунды
   из ПЛК. Проверенные числа задержек в STOP не заменяют этот тест.
3. Реальная смена кадров четырёх вентиляторов, без конфликтов LW.
4. Повтор звука после mute: общий PLC/CL50 generation и HMI, короткие новые
   биты между опросами. Финальное наблюдение 45–60 минут после последней
   загрузки при неизменных условиях; собственные загрузки/рестарты учитывать.

Не отключать защиты/аварии ради PASS. Один стендовый ACD AC590 380 В
питается от 220 В, без двигателя, RUN даёт Err09: силовой RUN не выполнять.
На объекте M900G. Отсутствующие три ПЧ/датчики не объявлять исправными и не
подавлять их аварии в релизе. CL50S отключена, её физический звук не проверен.

## 2. Подготовить фактическую цепочку GSM → OPC → SCADA

После доступных исправлений перейти к реальному runtime. Пока идёт стабильное
наблюдение mute, можно готовить копии/сверять файлы; намеренный обрыв GSM,
если он меняет условия аварий, проводить после этого наблюдения.

Зафиксировать установленные PLC/HMI и сохранённые файлы: путь, размер, SHA,
параметры до/после, версия экспорта. База — [локальный отчёт 12825d8](../reports/oshsky-live-bench-20261126.md)
и [физический STOP-check пользователя](../reports/oshsky-physical-hmi-user-check-20261126.md),
а не требование заново загрузить прежние файлы.

SCADA продолжать из сохранённой native UX r4:

```text
C:\Users\user\Documents\Simple-Scada 2\Projects\oshsky_scada_ux_r4\Project.spr
```

Сверить actual файлы с [отчётом r4](../reports/oshsky-scada-ux-r4-native-20261126.md).
Если уже есть новые доработки, сохранить и продолжить их. Четыре карточки
и привязки уже перенесены; перенос дизайна не повторять. До изменения runtime
сохранить actual SCADA/OPC/Server/архивную конфигурацию и путь возврата.

Установить маршрут: идентифицированный стендовый ПЛК → порт модема → GSM/M2M24
→ действующий Main-туннель → единственный MasterOPC → Simple-Server → Client.
Проектное назначение ПЧ Port3, модем Port4; USB-COM Windows не номер порта ПЛК.
Распиновку/режимы не менять по догадке. Сверить модем, локальный профиль,
stationID/адрес, назначение Main и фактическую очередь OPC. Общие маркеры
программы, имя station001 и TCP-порт сами по себе не идентифицируют «Ошский».
Секреты брать из действующего локального защищённого хранилища, в Git/чат/
командные строки их не выводить.

В существующей схеме Main TCP50008 опрашивает MasterOPC: второй raw-master
на канал не запускать. ServiceDiag9336 и ARADIO1 показывают модем отдельно;
успешная диагностика модема не доказывает связь с ПЛК. Не создавать второго
радиосборщика/писателя или конкурирующую cloud-сессию.
[Архитектура каналов](../radio-runtime-integration-2026-10-30.md).

«Client не запускался» — статус прошлого этапа. Теперь поручена фактическая
стендовая проверка: определить поддерживаемый способ запуска нужного проекта
с архивом. Обратимое переключение только идентифицированного стенда входит
в задачу. У общего Server было резервирование: не перезапускать общую систему
и не переключать чужие объекты ради картинки. Если отдельный запуск не
поддерживается и переключение затрагивает другие станции, закончить доступные
проверки и назвать точную зависимость. Не придумывать CLI/порты второго Server
и не выдавать Editor или тестовый приёмник за настоящий Client.

## 3. Проверить живые показания и обновление через GSM

Использовать [контракт](../interfaces/oshsky-scada-r3.md), [74 поля](../interfaces/oshsky-scada-r3-registers.csv)
и четыре RO-признака AUTO из r4. Новые items создавать только при отсутствии;
stationID/OPC prefix, порядок слов, архивные единицы и Map32/27110 сохранить.

Сопоставить минимум два последовательных среза прямого чтения ПЛК,
MasterOPC и SCADA с временем/качеством: R2554=32, R2329=27110,
R2509=27401, R3120=27402, движение R2840/R2508/R3125. Учесть оборот WORD
и задержку передачи; маркер/кэш GOOD без продвижения не являются PASS.
Проверить, что OPC items идут через GSM, а не прямой COM/старый кэш.
Не занимать линию HMI вторым master.

В Client проверить F/I/собственный Q, состояние/код ПЧ, RUN-команду, роль,
наработку unsigned32 минут → часы, возраст/причину отсутствия данных.
На этом стенде достоверные 0 Гц/0 А первого канала допустимы, прочерки
отсутствующих трёх ожидаемы. Потеря Q4 не скрывает достоверные остальные
каналы или свежую наработку4. Давление/sourceOK, уставка, режим, частота
ведомых и активные выдержки — отдельные данные. Нулевой ток AC590 без
двигателя не подтверждает ненулевой ток M900G под нагрузкой.

Отсчёт SCADA сверить с R3120..3125 и HMI: действие, физический номер,
секунды; при idle/STOP/MANUAL/несвежести скрывается. Реальное AUTO-ожидание
без насосов может быть недостижимо: отдельная явно помеченная TEST_ONLY-копия
без силовых команд допустима, но полный путь живого ожидания тогда остаётся
полевым пунктом. Подмену в релиз не включать.

Замерить фактический период обновления и задержки GSM. Если интервалы OPC
вызывают ложную несвежесть, установить причину и согласовать опрос с контрактом
по замерам. Не лечить это принудительным GOOD, обнулением возраста,
отключением guards или произвольным большим timeout.

## 4. Обрыв/возврат, Client, архив и существующая запись уставки

При станции в STOP оборвать только GSM-маршрут стенда, оставив ПЛК/HMI
работающими. Записать время и сравнить движущиеся локальные счётчики
с остановившимся удалённым потоком. Это проверяет маршрут, а не TCP-connect.
В Client старые числа должны получить честную потерю свежести, а не нули или
«аварий нет». После возврата дождаться новых ответов/счётчиков; команды не
повторяются, вручную остановленный насос не запускается. Перезапуск только
Client не должен менять ПЛК/опрос/радиосборщик.

Закрыть остаток actual Client r4: переходы из обзора, карточки, отдельное
окно/возврат, DPI/края кнопок; графики 1/6/24 ч, курсор и период по клиенту.
Прочитать архивные точки до/внутри/после потери качества, проверить viewer:
недостоверный интервал не соединяется как непрерывное достоверное измерение.
При нехватке истории проверить выбор периода на имеющихся точках, не
придумывать сутки наблюдения. На штатной стендовой аварии проверить
квитирование с фактическим временем в БД. Квитирование SCADA, mute
и сброс аварии ПЧ — разные операции.

После подтверждения адресата/STOP/backup проверить прежний путь R2100:
небольшое допустимое изменение и возврат исходной уставки, один Apply,
R2100/R2360 и новая обратная связь R2850..2856. Диапазон 10..1190 raw,
шаг10, ×0.01 бар; новых RW для пуска/сброса/частоты/каскада не создавать.
Смена контекста/владельца/режима отменяет черновик; потеря GSM запрещает
недостоверный Apply, возврат не досылает старую команду. OPC write-success,
принятие ПЛК и подтверждение записи ПЧ различать. Отклик AC590 не объявлять
проверенным PID M900G. Изменение рабочих режимов/обход ERR09 не нужны.

## 5. Выдать проверенный результат, сохранить остаток

Минимально исправить найденные ошибки SCADA/привязок/маршрута. Для изменённой
SCADA выполнить native Compile All/Save/reopen и затронутые Client-сценарии;
для изменённой PLC/HMI — проверки из основного задания.

Итоговый отчёт: actual пути/SHA установленных и выдаваемых PLC/HMI/SCADA/OPC,
обезличенный маршрут, таблица сравнений/возраста/обрыва/возврата, реальные
Client-кадры, архивные точки и подтверждения команд. Различить железо,
TEST_ONLY и остаток к выезду 27.11. Не закрывать непойманную остановку4
или отсутствующую физическую CL50 словами «всё готово».

Если файлы изменились, обновить отдельный исправленный Desktop-комплект,
README/manifest/SHA/ZIP: согласованная PLC/HMI-пара, проверенная SCADA/OPC
с зависимостями. Старый полный комплект/полевые параметры сохранить;
TEST_ONLY/bench data/секреты исключить. Указать полные Windows-пути.
Обновить HANDOFF, карточку объекта и лист выезда, опубликовать безопасный
протокол в handoff-ветке с проверкой remote SHA. Закрыть свои промежуточные
окна после сохранения; оставить только нужные итоговые. При физическом
блокере назвать одно конкретное подключение и продолжить независимую
работу, не спрашивая повторно общего разрешения.

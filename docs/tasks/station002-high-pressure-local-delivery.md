# Создать HP-кандидат локально без скачивания вложений из чата

Пользователь вновь не может получить PDW через чат и попросил PowerShell
или, предпочтительно, локального Codex. Это разрешение создать отдельный
локальный файл и отчёт в новой доступной папке. Ничего не загружать в
оборудование, не менять работающие проекты/SCADA, не публиковать PDW.

## Задача

Выполнить генератор до конца и сообщить полный путь к полученному PDW.
Для генерации не нужны интерактивные WinProLadder/SKTool, native F8,
vendor DLL, pip, git fetch или создание worktree. Используются Python3
и проверенные helper-файлы из manifest. Недоступность GUI не является
блокером именно этой операции создания файла.

Manifest: `artifacts/station002-high-pressure-01/delivery-manifest.json`
из того же закреплённого коммита, по которому получено это задание.
Он задаёт `rawBase` на неизменяемый be6c4b8, восемь файлов с SHA/размерами,
точные source/target SHA и имена. Не подставлять HEAD/main вместо rawBase.

1. Создать новую разрешённую папку, например
   `artifacts/station002-high-pressure-local-01`. Существующие файлы сохранить.
2. Найти сохранённый исходный PDW по SHA из manifest. Сначала проверить
   известную папку `candidate-copies/r2860-2879-review`, файл
   `station_MC_CM55_900G_2-4_24MC_candidate.pdw`. Ищем178400байт и SHA
   `96686b9948079d700d96e37483063b21de0cbef8f24a3e63785eed5be101abf5`.
   Другой native-save/старый05 не подменять под этот source-lock.
3. Получить каждый из восьми файлов по `rawBase + files[].path`, сохранив
   относительный каталог `tools/` внутри новой папки. Записывать исходные
   байты, проверить длину и SHA256 каждого. Нельзя конвертировать кодировку
   или окончания строк при скачивании. Скачивание/helper-папка не являются
   конечным результатом: продолжить запуск генератора.
4. Из новой папки выполнить установленным Python3:

```text
python tools/build_high_pressure_pdw_candidate.py --source ПОЛНЫЙ_ПУТЬ_К_СОВПАВШЕМУ_ИСХОДНИКУ --out station_MC_CM55_900G_24MC_HP_auto_candidate.pdw --report high-pressure-local-build.json
```

5. Проверить готовый результат:179579байт, SHA256
   `13da2180df15cf538e45bdb8a351c5713936f0b9b69fd8a109191e67c04c0263`,
   в отчёте29добавленных native-сетей. Проверить, что source не изменился.
6. Сообщить пользователю **абсолютный Windows-путь** к готовому PDW,
   размер/SHA и путь отчёта. Следующий пользовательский шаг — открыть
   именно новый изменённый файл в WinProLadder и выполнить F8. Если GUI
   локальному недоступен, создание PDW всё равно довести до результата,
   native-проверку явно оставить пользователю, не объявлять выполненной.

Если точного исходника нет, вывести фактические найденные пути/размеры/SHA
и конкретно сообщить отсутствие требуемой сохранённой копии. Guard не
ослаблять, файл не подменять, Access Denied не обходить. При иной ошибке
сохранить точную команду/сообщение; не повторять общий поиск программ
или ссылаться на GUI как на причину незапуска стандартного Python.

## Что создаётся

Это тот же offline-кандидат защиты: Δ2бар, останов при PV>SP+Δ,
автоматический сброс при достоверном PV≤SP, deadband удерживает состояние,
старый абсолютный предел12бар сохранён. Поля модели в кандидате24MC;
native-открытие/F8/Retain этой копии ещё предстоят. Новых команд пуска нет.
SKM и N2/3/4 ещё не реализованы этим файлом; R2868..79 заняты защитой.

Cloud проверил доставку: восемь файлов получены из pinned GitHub raw,
все размеры/SHA совпали, запуск из пустой временной папки Python `-S`
без site-packages дал точный target SHA. Повторный запуск отказался
перезаписывать существующий результат. Это проверка доставки/воспроизведения,
не Windows-исполнение или native F8 на ноутбуке пользователя.

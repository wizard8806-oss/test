## Конкретная проверка адресов, затем PLC-копия

Кандидат — блок R2860..R2879, распределение в workpack. В точном05 не
найдено совпадений соответствующих16-битных операндов; девять сохранённых
таблиц/их R-буферы блок не перекрывают. Native-статистика и retentive исходника
теперь подтверждены снимками выше. Продолжить выделение по workpack в
отдельной offline-копии, сверив многословные/косвенные диапазоны и доступные
внешние HMI/SCADA-привязки. Недоступные внешние/native-проверки перечислить
перед испытаниями; они не препятствуют созданию изолированных кандидатов.
R2180..R2183 уже заняты заданиями ручной частоты — не брать под количество.

Важная граница старого аудита: комментарий PDW не равен одной цепи.
Например, `70.01–70.04` содержит четыре, а `65.00` начинается с OPEN перед
реальным FUN150P.M-BUS. Один успешный вызов старого formatter не доказывает
полноту покрытия. Экспериментальный GetNetLen не принят как decoder
машинного кода: он обрезает часть FUN150. Не использовать такой вывод
для объявления диапазона свободным. Запрошенные native-статистика и
retentive-граница исходника уже получены; повторять этот запрос не нужно.
После изменения целевого CPU проверить его настройки отдельно.

После подтверждения выделения блока реализовать:

1. Подтверждённый N, черновик, статус, маску установленного состава,
   признак валидности и ревизию. Неинициализированная конфигурация не
   превращается в N=4; запуск запрещён до настройки в STOP. Сохранённый
   валидный N переживает перезапуск без команды применения/пуска.
2. Расширить имеющуюся STOP-транзакцию M1460/1461/1462: начало копирует N,
   отмена ничего не меняет; применение проверяет2/3/4, STOP, отсутствие RUN,
   свежие подтверждения останова установленных ПЧ и свободные очереди.
   При выходе из STOP черновик не применяется позднее автоматически.
   Фиксировать принятие/отказ. Одновременные противоречивые команды отклонять.
3. Разделить физическое присутствие `i<=N` и допуск AUTO R720..R723.
   При уменьшении N очистить допуск отсутствующих слотов; при увеличении
   не включать новый насос в AUTO автоматически. Счётчики наработки и
   четыре адресных слота сохранить. Само применение не создаёт RUN.
4. Применить присутствие во всех перечисленных changeAnchors: доступность,
   ротация/лидер, давление, ручной режим, все очереди, останов/алармы и
   физические выходы. Одного ограничения выходов или маски AUTO недостаточно.
5. Для обычного опроса выбирать расписание из полного R5000:11/14/18 строк
   для N=2/3/4. Это фильтр по Slave, не первые11/14 строк! Сменить расписание
   только при свободном worker; не переносить ответ старого задания в новый
   слот. У отсутствующих ПЧ нет опросов, таймаутов, записей или alarm.
6. Все восемь одноразовых таблиц используют захваченный адресат задания.
   Проверять `1<=target<=N` при приёме и перед отправкой, сохранять его до
   завершения; ответ/ошибку связывать именно с ним. Проверить барьеры между
   normal poll, mode, frequency, PI, stop probe; не запускать второй master.
7. Добавить версию расширения и совместимый экспорт N/valid/revision для
   HMI/SCADA. Не менять32 на другое число без совместимого потребителя:
   текущая SCADA имеет guard карты32. Уставка остаётся R2100, зеркало R2360.
   Отдельно проверить CPU FBs-24MCR2-AC/CM55; Y9 — AUTO LED, не сирена.

## HMI-копия от r1

Добавить в настройки «Установлено насосов» со значениями2/3/4, подтверждённое
значение и результат применения. Пользователь меняет черновик; HMI не пишет
циклически ни подтверждённый N, ни уставку. Использовать PLC STOP-транзакцию.
Привязки включать только после выделения адресов и согласования producer.

Для фона — штатный Picture Display с тремя состояниями и индексом
0/1/2 для N=2/3/4; индекс вычисляет ПЛК только при валидном N. Под ним
положить непрозрачную нейтральную подложку, перекрывающую прежний фон4.
При неизвестном N показать «Конфигурация не подтверждена», скрыть насосную
картинку/слотовые команды, не подставлять сохранённую картинку4 как истину.
Проверить, что состояния выбираются по индексу, а не прямому N=2/3/4.

Подписи/шкалы/значения размещать под соответствующими насосами для каждого
варианта; фиксированные четыре позиции r1 не подходят к двум и трём.
Ориентиры X для холста800x480:2 — [326,476],3 — [278,402,526];
4 оставить принятые [239,347,457,565]. Проверить визуально в Simulator.
При необходимости использовать отдельные группы элементов с одинаковыми
привязками и условиями N, а не новые независимые копии значений в памяти.
Правая колонка скрывает отсутствующие слоты. Подписи насосов сделать
контрастными. Существующие семь переходов/их адресаты сохранить.

Сразу подготовить и проверить три visual-состояния в отдельной offline-
копии с внутренним тестовым селектором, если выделение PLC-памяти пока
зависит от native-чтения. Селектор не подключать к внешней записи; такую
проверку назвать HMI-прототипом, не реализацией PLC. После получения N
заменить тестовый источник на подтверждённый PLC producer.

## Проверка и результат

Проверить N=2/3/4; недопустимые0/1/5; уменьшение4→2 и увеличение2→4;
отмена; выход из STOP; занятый worker; задержанный ответ; запрос к
отсутствующему насосу; потеря/возврат связи и сохранение N после перезапуска.
Во всех случаях отдельно проверить отсутствие самопуска, ложных аварий
отсутствующих ПЧ и смешения станций. Статический тест и Python reference
не являются испытанием исполнения native ladder.

Предоставить реальные изменённые PLC/HMI-копии, назначенную карту и
результат F8/Simulator либо точный блокер. При недоступности native GUI
продолжить доступную реализацию/подготовку файлов; ограничение не обходить,
тот же обход desktop не повторять. Полные private проекты и журналы
остаются локально. SCADA затем читает N своего ПЛК с сохранением готового
графика и отдельных контекстов двух станций. Публично — краткая сводка
и обезличенные исходники; main сохранять.

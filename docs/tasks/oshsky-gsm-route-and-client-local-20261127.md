# Ошский: физическая HMI и SCADA через GSM

**Дополнение27.11 — SCADA раньше открывалась на втором мониторе.**
Пользователь поручил проверить, мешает ли это локальному, и при необходимости
перенести окна. Выполнить раздел0 перед UI-проверкой SCADA, не прерывая
текущий PLC/HMI/sound этап. Перенос нужных окон уже разрешён этим поручением.

Сначала закончить текущий этап [живых данных/native fault/звука](oshsky-live-pump1-data-and-native-fault-local-20261127.md),
затем выполнить оставшуюся GSM-приёмку ниже. Актуальные версии брать из
основного task и [отчёта582bca4](../reports/oshsky-live-native-fault-windows-20261127.md):
PLC r3g установлена, physical TRACE_r3h, HMI r3i подготовлена. К началу
GSM-этапа могли появиться более свежие исправления — не откатывать их.
SCADA продолжать из сохранённой `oshsky_scada_ux_r4a_gsm`.
Сохранить текущие буферы/новые результаты и прежние версии, не откатываться
к r3d/r4. Разрешения автономного стенда/backup/необходимых загрузок прежние.

## 0. Проверить доступ к SCADA на двух мониторах

Установить actual PID/HWND/проект нужных Client/Editor/Server и открытых
модальных окон. Определить мониторы/virtual-screen bounds, включая возможные
отрицательные координаты, рабочие области и DPI. Проверить текущий канал:
может ли локальный прочитать содержимое, получить кадр нужного окна целиком
и выполнить безопасный UI-переход, например к информационной вкладке.
Проверять реальное окно, а не считать его отсутствующим по кадру только
первого монитора. Выбор проекта/свежесть данных подтверждаются отдельно.

Если второй экран полностью доступен, оставить расположение и отметить
это в отчёте. Если окно вне области capture/input или координаты/DPI мешают
управлению, штатно перенести **существующее** окно на доступный основной
экран. Перед изменением сохранить его bounds/state для возврата; при нужде
восстановить из maximized, перенести и задать размер в рабочей области.
Проверить также относящиеся к нему диалоги входа/графиков. Не закрывать
проект/терять буферы и не запускать вторую копию приложения ради переноса.

Использовать поддерживаемый локальный доступ к окнам. [Get-ScadaUiContext](../../tools/Get-ScadaUiContext.ps1)
и [предыдущий фактический опыт](../reports/station11-supported-desktop-access-20261102.md)
могут помочь идентификации; это не доказательство нынешней конфигурации.
В прежнем опыте EnumWindows работал из Default, а из CodexSandboxDesktop
не давал нужного доступа: отличать этот случай от геометрии мониторов.
При недоступности самого desktop не повторять слепые клики/перезапуски.

После переноса подтвердить новым кадром и безопасным действием доступность
того же HWND/проекта, читаемость и попадание ввода в нужный элемент. Это
проверка доступа к окнам, не приёмка PLC/GSM. Глобальное расположение дисплеев,
их масштаб/разрешение и посторонние окна пользователя не менять ради удобства теста;
для этой задачи достаточно нужных SCADA-окон. В отчёте указать, мешал ли
второй экран, какой монитор/окна использованы и что именно перенесено.

## 1. Подтвердить текущую пару PLC/HMI после основных исправлений

Состояние до582bca4 уже описано в отчётах; исходный разбор r3f/карты0
не повторять вместо проверки актуальной пары. По основному task подтвердить
реальные версии, marker/heartbeat/собственные качества, стабильный Main,
native fault и доставку physicalmute. Не выдавать TEST_ONLY/Simulator за
физическую панель. На стенде один AC590380/220/Err09 без двигателя,
реле/давление не подключены; силовойRUN не нужен, CL50S физически не принята.
Если требуется переставить общий программный кабель, назвать конкретное
необходимое подключение и продолжить независимые проверки. Двухmaster
на одну линию не подключать.

## 2. Восстановить существующий Main Gateway

В предыдущем опыте 127.0.0.1:50008 никто не слушал. Это отдельный локальный
блокер Gateway, а не доказательство неисправности модема/кабеля Port4.
Найти установленного владельца Main: программу/службу/задачу автозапуска,
профиль/binding/адрес прослушивания и причину остановки. В истории Main —
группа7058, ServiceDiag —9336; подтвердить actual назначения. Не подменять
Main сервисным сборщиком и не создавать новый туннель.

По локальным настройкам/доступным средствам идентифицировать стендовый
модем/маршрут/линию Port4. Сверить native контракт Port4 и модем/OPC;
FATEK9600 7E1 программирования COM28 не переносить на Modbus автоматически.
station-001 и общие маркеры программы не доказывают идентичность объекта.
Секреты брать только из разрешённого локального хранилища, не публиковать.

Сохранить настройки. Штатно восстановить Main для идентифицированного
стенда: listener/владелец, затем удалённые ответы PLC и движение heartbeat
через единственный MasterOPC. Новый raw-Modbus клиент на50008, второй
радиосборщик/писатель или конкурирующую сессию не запускать. Если listener
появился, но ответов нет, разбирать следующий участок GSM→модем→Port4 по
фактической ошибке, не пересобирать HMI. Service radio.txt — отдельный канал.

## 3. Целевые OPC-привязки и вход в нужный Client

Активный узел имел22позиции/26отклонённых DA-имён; review-profile —76позиций.
Сверить actual имена/типы/префиксы, адрес/scale/порядок слов/RW-whitelist
по [контракту](../interfaces/oshsky-scada-r3.md). После подтверждения адресата
добавить/исправить только целевые items действующего профиля; чужие станции
и настройки сохранить, весь общий профиль review-файлом не заменять.
Сверить состав других узлов до/после и выполнить нужный штатный reload,
учтя область действия. Второй OPC на том же Main не запускать.

В каталоге SCADA сверить binding нужной станции. ExpectedMap31 менять на32
только у подтверждённой записи стенда после R2554=32; не менять все станции/
проверку карты глобально.104подписки Server не означают104достоверных items.

Запустить сохранённую r4a/настоящий Client с действующей учётной записью
именно этого проекта. Пароли не подбирать/не сбрасывать. Если входа нет
в доступном локальном хранилище, оставить правильное окно пользователю и
продолжить OPC/GSM. Кадр «Запуск проекта / подключение к Server» не PASS.

## 4. Завершить приёмку

В STOP сопоставить PLC/физическую HMI/OPC/Client по времени и новым counter,
учитывая доступность отдельного порта прямого чтения. Первый ПЧ0А/0Гц и три
unknown допустимы. Проверить четыре Q/F/I/наработки, давление/sourceOK,
режим/уставку/выдержки. Новых RW для пуска/частоты/сброса не добавлять.

При работающих PLC/HMI оборвать только подтверждённый GSM-маршрут стенда,
получить честную несвежесть, вернуть связь/новые ответы без replay. Затем
Client-переходы/окно/графики1–6–24ч/курсор, точки вокруг BAD-интервала,
квитирование с временем в БД и прежний ApplyR2100/R2360/R2850…2856 с возвратом
исходной уставки по общему заданию. TEST_ONLY не заменяет живой AUTO.

Минимально исправить найденные ошибки в копиях. Выдать фактические срезы,
Client-кадр с живыми данными, native проверки изменений, пути/SHA и итоговое
состояние. Комплект обновлять только при изменении файлов; старыйZIP/полевые
параметры сохранить. Снять конкретный блокер вместо нового общего разрешения.
HANDOFF/карточку/лист выезда дополнить явным остатком по M900G/CL50, отчёт
опубликовать. Свои промежуточные окна закрыть после сохранения.

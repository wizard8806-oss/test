## 1. Выбрать способ смены по фактическому доступу

Не ждать очередного ввода прежнего пароля. Если сохранилась действующая
административная SQL-сессия/штатное подключение Workbench, после резервирования
выполнить смену через неё. Иначе перейти к процедуре init-file ниже.
Подтвердить экземпляр/службу/конфигурацию и целевую локальную учётку; при наличии
санитарного текста1045 имя/host можно читать без пароля/строки подключения.
Если прежнее приватное окно всё ещё ждёт ввод и больше не нужно, отменить
только этот подтверждённый helper, не Editor/Server и не процесс по старому PID.

Разрешено использовать уже доступное штатное локальное административное
подключение MySQL/Workbench; чужие секреты/профили не извлекать. Не подбирать
пароли и не переносить пароль Client SCADA на root. Доступная админ-сессия
позволяет выполнить разрешённую смену без recovery-паузы MySQL.

## 2. Полномочия и временные секреты

Разрешены необходимые административные действия **на этом ноутбуке и этом
MySQL80**: создание локальной архивной/при необходимости временной служебной
учётки, назначение ей сильного случайного пароля, выдача нужных прав,
штатное повышение через UAC. Фактический запрос ОС может требовать действия
оператора; не обходить UAC/контроль инструментов, не менять общую защиту ОС.

Административная учётка может выполнять нужные CREATE USER/CREATE/GRANT
для подготовки. Архивной `scadaarchive10@localhost` разрешены все нужные
права на **свою выделенную схему**; при реальной необходимости —
ALL PRIVILEGES на эту схему без GRANT OPTION. Приложение не переводить на
root и не выдавать удалённый `%`-доступ для решения локальной задачи.

Новые временные пароли агент может назначать самостоятельно; не использовать
пустые/общеизвестные тестовые значения. Разрешено хранить новые секреты в
Windows Credential Manager или DPAPI под текущей учёткой, приватно вне Git,
с ACL только владелец/SYSTEM. Разрешены пароль в памяти и штатные настройки10.
Это новое разрешение пользователя уточняет прежнее ограничение «только память»;
не писать секреты в stdout/логи/аргументы/отчёты или незашифрованные постоянные
файлы. В отчёте указать только защищённое место/способ доступа, без значения.

Временную подготовительную учётку после завершения работ отключить/удалить,
если она больше не нужна и создана именно в этом проходе. Архивный пароль
не отключать по таймеру с разрывом архивирования: заменять согласованно вместе
с параметрами10, проверить соединение после замены. Пароль/его временный статус
и необходимость дальнейшей замены отразить без значения.

## 3. Выполнить выбранную смену/восстановление

Смена прямо поручена пользователем. При доступной админ-сессии сначала
приватно резервировать относящиеся данные/конфигурацию/учётные метаданные,
затем штатный ALTER USER и проверка нового входа. При отсутствии такой
сессии разрешена следующая Windows-процедура с паузой MySQL80 и cold backup.
Это только локальный MySQL8.0.40/MySQL80; не менять Windows-пароли,
SQL Server/SQLEXPRESS или другие экземпляры. Сгенерировать сильный новый
временный секрет самостоятельно и сохранить защищённо, не в чат/аргументы.

Следовать [официальному способу Windows для MySQL8.0](https://dev.mysql.com/doc/refman/8.0/en/resetting-permissions.html#resetting-permissions-windows):

1. Зафиксировать точные EXE/службу/учётку запуска/обычный defaults-file/datadir
   и необходимые внешние файлы ключей. Проверить зависимости/текущих клиентов.
   При обнаружении неизвестной производственной нагрузки уточнить воздействие
   до паузы; не останавливать её молча. MySQL80 можно штатно остановить и
   вернуть в работу для необходимого восстановления, не другие службы/Server.
2. Без SQL-пароля создать приватную восстанавливаемую холодную копию полного
   datadir/конфигурации/нужных ключей **после чистой остановки** этого mysqld,
   проверить состав/хеши/ACL. Не считать Robocopy работающего InnoDB полноценным
   cold backup. Не переинициализировать сервер и не удалять базы/службу.
3. По официальной процедуре init-file назначить новый сильный временный
   пароль целевой локальной административной учётке. Для root@localhost
   это прямое выполнение нового поручения после резервирования.
   Другие аккаунты/пароли
   сохраняются. Если целевая учётка не определена — не менять похожую наугад.
4. Файл init SQL с новым секретом допускается как краткоживущий приватный
   служебный файл вне Git, доступный только нужным локальным принципалам;
   не печатать его и не передавать секрет в аргументах. Использовать тот же
   подтверждённый defaults-file/datadir; не менять постоянный ImagePath службы.
   После выполнения удалить init-файл и вернуть обычный режим запуска.
   Способ `--skip-grant-tables`, отключение проверки прав/TLS/firewall или
   открытие SQL в сеть для этой задачи не использовать.
5. Проверить нормальный запуск MySQL80 без init-file, локальный вход новым
   секретом и сохранность существующих схем/учёток/данных. Перед продолжением
   сохранить новый административный секрет защищённо, чтобы не потерять доступ.
   Переход обратно к стандартному запуску не отменяет новый пароль; отчёт
   должен явно отражать факт смены без публикации значения.

Новую архивную учётку10 создать с отдельным секретом; если она уже существует,
перед сменой проверить её принадлежность10 и согласованно обновить параметры
этого проекта. Не сбрасывать неизвестную чужую учётку из-за совпадения имени.
Указать оператору локальный защищённый способ получения новых секретов;
не потерять пароль после закрытия helper. Не возвращать слабый общий пароль
и не назначать автоматическое истечение, обрывающее действующий архив.

После входа продолжить этапы2–6 основного задания до проверки архивирования.
Не повторять файловые проверки10 без новой причины. Состояние соединения,
создание схемы, параметры10, переключение SCADA и сохранённое сообщение
фиксировать отдельно; ни один этап не объявлять выполненным по разрешению.

Обновить отчёт/HANDOFF/статус, опубликовать только документы в прежнюю ветку.
Все приватные копии/секреты/временные SQL/helper-файлы остаются вне Git.
Полевые команды/Apply/уставка/режим/сброс, ПЛК/HMI/радиосборщик по-прежнему
не входят в это расширение. При техническом отказе инструмента записать его
точный предмет/причину и выполнить доступное без обхода ограничений.

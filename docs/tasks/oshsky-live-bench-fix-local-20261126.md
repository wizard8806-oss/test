# Локальному: исправить и проверить «Ошский» на настоящем стенде к 27.11

**Продолжение после выполненного bench-этапа:** пользователь подтвердил
физический STOP-check токов/задержек/переходов и уточнил регулярные остановки4
при ручной работе без Err на ПЧ. Следовать
[объединённому заданию](oshsky-mode-stop4-and-animation-local-20261126.md).
Выполненный исходный этап/загрузку PLC заново без причины не повторять.

26.11.2026, МСК. Пользователь сообщил о реальном стенде и поручил подготовить
исправленные проверенные версии для загрузки на объекте **завтра27.11.2026**.
Это новое основание для работы с подключённым стендом, сверх прежнего offline
анализа. Не заканчивать этап только чтением дискового PDW с `Close_232`.

## Подтверждённый пользователем состав и scope

- На столе ПЛК, GSM-модем, один ПЧ **ACD AC590**, номинал380В, питание220В,
  двигателя нет. При RUN возникает **Err09**.
- HMI физически есть; сейчас её порт занят кабелем программирования.
  До освобождения порта доступен SKTOOL. Модели стендовых PLC/HMI ещё нужно
  установить, не предполагать FBs-32MC/SK-102CE только по открытому проекту.
- На объекте стоят **M900G**, это пользователь подтвердил отдельно.
  Конфигурацию рабочего четырёхнасосного проекта не переделывать под AC590.

Разрешены необходимые действия на **идентифицированном изолированном стенде**:
подключение Online, чтение/backup, подготовка исправленных копий, их загрузка
в совместимые стендовые PLC/HMI, контролируемые проверки/настройки именно
стенда. Повторного общего согласия не спрашивать. Сначала сохранить программу,
данные/параметры и подтвердить адресат; не отправлять команды рабочим шкафам
через GSM/общие OPC-маршруты. Полевой Ошский/другие объекты/Бабанов и их
службы этим поручением не переключаются. Команды и результаты фиксировать.

Последнее прямое указание пользователя: **«считаем настройки одинаковыми.
разрешаю локальному загружать программу в контроллер»**. Загрузку стендового
ПЛК выполнять после backup и сверки совместимости, не запрашивать разрешение
снова. Одинаковые настройки принять как рабочее условие первого прогона,
сравнивая фактические ответы. Не превращать отсутствие точного руководства
AC590 в блокировку обычного чтения или проверки PLC/HMI.

### Err09 и различие приводов

Номинал380/питание220 подтверждены пользователем. Точное руководство/исполнение
ACD AC590 и допустимый параметр отключения Err09 пока **не подтверждены**.
У похожих семейств код9 связан с undervoltage, но нельзя выдавать каталог
M900G/EACON EC590/Inovance за инструкцию именно этого ACD.

Сначала зафиксировать полную маркировку/версию, код и доступное показание
питания/DC-звена, найти соответствующую первичную инструкцию. Если изготовитель
описывает допустимый тестовый режим без двигателя — записать параметр, исходное
значение, основание, границы и восстановление после опыта. Не подбирать
factory/service параметры или отключения защиты по похожей серии. Изменение
паспортного параметра двигателя не создаёт недостающее входное напряжение.
RUN допустим только при подтверждённом изготовителем режиме/питании для этого
исполнения. Отсутствие такого допуска ограничивает силовой тест, а не чтение
PLC/свежести/HMI. Поиск обхода Err09 не должен блокировать первичную диагностику.

## 1. Сначала получить живой исходный срез

Прочитать [описание дефекта](oshsky-first-start-current-cascade-local-20261126.md) и
[последний разбор r3](../reports/oshsky-first-start-r3-readonly-local-20261126.md).
Установить реальные COM/USB/интерфейсы и модель контроллера; существующие
Port3→ПЧ/Port4→модем — проектное назначение, USB-COM Windows не тот же номер.
Подтвердить реально подключённый bench controller и изолированный маршрут.
ОбщийTCP50008 опрашивает только прежний MasterOPC; второго master на тот же
RTU-канал не запускать. Секреты/профили/лицензии в публичный отчёт не выводить.

Сохранить текущую bench программу и данные, затем два/несколько **живых**
срезов через2–3с с временем: R2840, R2508/2509, R3120/3125, R2329/2554,
R2504..2507, R2510..2513, R2884..2888. Для токов из приёмных буферов —
R2806/2814/2822/2830. Зафиксировать RUN/STOP и actual Online-признак.
Если сначала в bench иной проект, так и пометить срез; это не причина
полевого сбоя. После backup при совместимом target загрузить отдельную
стендовую копию проверенной r3 и повторить. Не менять CPU-модель ради
подгонки проекта и не выдавать несовместимый target за проверенный field-файл.

Ожидания r3: Map32/schema27110, marker27401 и27402, продвижение всех трёх
счётчиков. Retained marker без движения не принимается. Измерить реальную
периодичность, не расширять прежний timeout для зелёного результата.

## 2. Проверить настоящую HMI и локализовать корень

После необходимых действий программирования освободить занятый порт и
подключить HMI штатно. Когда нужна физическая перестановка, подготовить
точный шаг и запросить его один раз. Не держать двух ведущих на одной линии.
Совместимость модели/разрешения проверить **до** загрузки field SKM; другой
стендовый экран не делает проверенным SK-102CE1024×600.

Если физическая HMI ещё не подключена, выполнять остальные чтения и при
наличии штатного Online Simulator SKTOOL проверить его с живой PLC-связью.
Название/режим подтвердить UI, не выдумывать поддержку. Offline Simulator
не заменяет этот этап; реальная панель остаётся отдельным обязательным пунктом.

Подготовить [диагностическую r3a](oshsky-r3a-diagnostic-hmi-local-20261126.md):
direct PLC reads рядом с фактическими macro aliases, RTC, свежестью и счётчиком
capture. В рамках нового стендового поручения её загрузка/проверка на
совместимой bench HMI разрешена; прежний запрет загрузки относился к полю.
Снять живое поведение до/после, не подставлять число в local valid-биты.
Если штатный инструмент уже даёт эти живые значения и причина воспроизведена,
сначала исправить и проверить её; расширенная диагностика не должна задерживать
готовую рабочую пару. В таком случае в отчёте указать использованный инструмент
и какие диагностические страницы фактически включены в выход.

По исходному срезу пройти PLC→wire/native read→macro value→gate→display:
если экспорта нет в PLC — разбирать программу/выполнение; если в PLC есть,
а в alias нет — driver/batch/ABI; если alias верен — clock/cadence/guard/
visibility. Действующие новые задержки должны читаться в MANUAL/STOP без
активного countdown. Исправить **найденную** причину минимальным изменением
копии. Подтверждённый MD5070/R2166 полный ACK безLB2110 исправить отдельно,
сохраняя сообщения ошибок и прежние транзакции. Current/timer guards не снимать.

## 3. AC590, ноль тока и четыре канала

Первый прогон провести с одинаковыми проектными настройками, как поручил
пользователь. Зафиксировать реальные запросы/ответы и результат чтения,
сопоставить доступную документацию без остановки остальной проверки.
Несовпадение адреса/масштаба или exception записать отдельно; конфигурацию
выпускаемого M900G-проекта не переделывать ради AC590. Ответ AC590 на запрос
подтверждает только этот фактический тест. Native ошибка этого привода и
ошибка режимной транзакции M900G — разные факты.

Начать без RUN. При достоверном совместимом STOP-снимке ток должен быть
**0.0А**, отсутствие источника остаётся прочерком. Это важный полевой
regression. Двигателя нет: ненулевой измеренный ток нагрузки этот стенд
не подтверждает. Остальные3физических привода отсутствуют; их link/fault
не считать неожиданным дефектом и не убирать из field-конфигурации.

Для четырёх разных/ненулевых токов и каскада разрешена отдельная явно
маркированная **TEST_ONLY** имитация на изолированном bench: documented
M900G RTU slave при доступном адаптере либо отдельная PLC-test копия для
проверки тракта PLC→HMI. Не имитировать прямо конечные HMI valid/числа,
которые проверяются. Указать, какой слой настоящий, какой подставлен;
без реального serial slave нельзя заявлять end-to-end FUN150.
TEST_ONLY/форсировки/искусственные источники исключить из field-выхода.

Пройти независимые3/4выдержки: разные active/shadow, Edit/Apply/Cancel в
STOP, диапазоны/сохранение/отказ, чтение вMANUAL/AUTO, новый countdown
с физическим номером/остатком. На реальном PLC можно проверить запись/
эхо параметров без запуска нагрузки. Если сценарий блокируется реальным
допуском, записать отказ, не ослаблять защиту в выпускаемой программе.
Стендовые значения/отключённые3насоса/параметры AC590 не переносить в release.

Режимная ошибка: коррелированный M667/M1563/D251/D231/D232/D320/321/
D340/341/R2402 и per-pump latch/code. У M900G nominal FC06/FC03 по61442
one-based даёт PDU0xF001; actual M900G hardware сегодня отсутствует.
Ошибку такого запроса к несовместимому AC590 не объявлять полевой причиной.

## 4. GSM и повторная загрузка результата

Через подтверждённый bench route проверить PLC→GSM→существующий OPC read:
Map/schema/новые счётчики/current/параметры, качество/возраст, естественную
потерю/возврат без повторной записи. Если нужный route/Server недоступен,
зафиксировать конкретный остаток. Shared Server/SQL/радио других объектов
не перестраивать; недоступный Client не блокирует проверку HMI/PLC.

Новый field-кандидат сохранить с диска, закрыть/reopen, выполнить native
Compile/F8 по изменённой части и применимые regression. Затем проверить
на стенде **этот выход**, не прежний RAM/TEST_ONLY. Добавленная диагностика
остаётся read-only и показывает build-метку. Сохранить новые функции только
если проверены, иначе исправление/диагностический кандидат назвать точно.
Если корень на живом стенде не воспроизвёлся — написать not reproduced,
не выдавать случайную правку за устранение полевого дефекта.

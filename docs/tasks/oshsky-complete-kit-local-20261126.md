## 1. Создать комплект на фактическом Рабочем столе

Получить Desktop штатно через Windows SpecialFolder, включая перенаправление.
Создать `Ошский_4насоса_Комплект_2026-11-26` и ZIP с тем же именем **рядом**.
BuildID: `oshsky-4p-plc-r3-hmi-r3-scada-r4-20261126`.
Существующее отличающееся содержимое не затирать; при занятом имени добавить
время. Не перезаписывать исходные проекты. Сохранять исходные имена файлов.
Результат должен физически находиться на Windows пользователя, не в Cloud.

Рекомендуемая структура:

```text
Ошский_4насоса_Комплект_2026-11-26/
  PLC/
  HMI/project/
  HMI/assets/
  HMI/fonts/
  SCADA/oshsky_scada_ux_r4/
  OPC/review_only/
  peripherals/
  tools/
  docs/
  screenshots/production/
  screenshots/TEST_ONLY/
  README.txt
  manifest.json
  dependencies.json
  SHA256SUMS.txt
```

## 3. Все зависимости и периферия

1. Инвентаризировать реальные внешние ссылки точного SKM, private manifests,

   JPEG. Для каждого исходного пути записать путь копии и статус ссылки.
   Оригинал `assets/automatikakg.jpg`703677байт,
   SHA`2266c6ce15726bac815b7f8d6084a7b35c545591440020df4899268ce1d395c7`.
2. Добавить `assets/hmi/pump-animation/PumpStationRotor.ttf`3520байт,
   SHA`70c76c96778838c13b384cee32578b6ef967ef0774165b02bf5173f4dd862f22`.
   В README объяснить его установку перед редактированием/компиляцией HMI.
   SCADA-графику и прочие реально используемые внешние файлы собрать отдельно.
3. В peripherals составить фактический перечень оборудования и подключения:

4. Приложить найденные схемы шкафа, I/O/Modbus карту, параметры/экспорты ПЧ,
   инструкции панели/контроллера и радиоканала, относящиеся к этому объекту.
   Настройки радио/OPC брать только из подтверждённых материалов объекта;
   стендовый маршрут не объявлять рабочим маршрутом Ошского по имени файла.
5. В tools добавить имеющиеся нужные установщики/драйверы, если подтверждены

## 4. README, манифест и проверка ZIP

README должен назвать: «Ошский —4насоса — PLC/HMI r3 — SCADA UX r4», модели,
версии редакторов, назначение папок, порядок открытия/сборки и восстановления
внешних путей. Копия assets **не меняет абсолютные ссылки SKM**. Не объявлять
проверенной переносимость на другой ПК, если проект открыл зависимости из
прежних папок. Эталонные ссылки не переписывать; отдельную переносимую
производную, если нужна, делать отдельно с собственным SHA и проверкой.

Указать действительные границы: PLC F8 0ошибок/25прежнихW85; HMI Script0/0,
Compile/Simulator; SCADA Compile/Save/reopen/104hostcases, но actual Client/
клики/ack/native archive-gap и идентичность полевого маршрута ещё pending.
Упаковка не равна загрузке/приёмке шкафа, OPC review-profile не активирован.
Это не причина откладывать сам комплект.

Для каждого вложения manifest/dependencies содержат относительный путь,
размер/SHA, происхождение и статус необходимости. Разделить **полноту файлов**
и **статус аппаратной/Client-приёмки**. При недостаче обязательного файла
собрать доступную часть и отметить НЕПОЛНЫЙ с точным списком; не подставлять
другую версию и не останавливаться на вопросе о продолжении. Отсутствующий
необязательный установщик перечислить отдельно от отсутствующей прошивки.

Сначала проверить SHA копий и замыкание внешних зависимостей. Сформировать
manifest без самохеширования и SHA256SUMS без собственного хеша. ZIP создать
существующим Python/PowerShell, без установки пакетов; ZIP вне папки, без
самого себя и scratch-каталогов. После упаковки проверить CRC, состав и SHA
**всех** вложенных байтов и распаковать в отдельный временный каталог вне
комплекта. Сравнить распакованное с manifest и всеми13SCADA-файлами.
Хеш/размер ZIP записать рядом в `.sha256.txt`.

Повторять весь прежний кодовый suite/95маршрутов ради побайтной копии не нужно.
Открытие копии из распаковки и проверка доступности ресурсов полезны, если
безопасны без запуска рабочего Server/связи с полем. При новом offline Compile
использовать scratch-копию, эталонные исходники/манифест сохранить. Не делать
Download/Force/RUN/пуск/сброс/Apply, не переключать службы/OPC/радио/БД.

## 5. Отдать результат

Открыть готовую папку в Проводнике. Проверить существование и выдать:

- **полный фактический Windows-путь папки** и **полный путь ZIP**, без многоточий;
- BuildID, размер/SHA ZIP, число файлов, статус полноты и конкретные недостачи;
- совпадение PLC/HMI/SCADA/OPC SHA, результат ZIP/распаковки, зависимости;
- что осталось непроверенным в Client/на объекте.

Краткий отчёт с реальными путями и результатами, HANDOFF/карточку объекта
закоммитить в handoff-ветку, push и проверить remote SHA; main не менять.
Native/ZIP/полные private manifests/configs не публиковать. Комплект на Desktop
не должен оказаться в индексе; для scratch внутри worktree использовать local
exclude с учётом `git rev-parse --git-path info/exclude`, не глобальный gitignore.
Закрыть свои промежуточные окна после сохранения буферов; пользовательские
окна и службы сохранить. В конце оставить папку комплекта в Проводнике.

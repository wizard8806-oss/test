всех вкладок. Верхние вкладки, отдельное окно и отмена черновика уже проверены
локально. Apply не выполнялся. Открытие журнала кнопками не подтверждено,
архивная панель открывалась с пустым рядом; настройки остаются каталогом.
Рабочие транспорт и фоновый сборщик в этой задаче не перенастраивать.

**Уточнение пользователя после этого прохода:** основным графиком использовать
штатную панель трендов. Актуальное продолжение —
[штатный график уставки и частоты](station11-native-trend-viewer.md).
Требование встроенного компонента в разделе3 ниже — прежний этап, не обязательная
следующая реализация. Права/переходы проверять только при актуальном отказе.

## 1. Сначала права конкретных страниц

Сохранить местные изменения и подробный предыдущий отчёт. Найти сохранённую
R2 и её native SHA в приватных артефактах; пользователь уже прислал результат,
не просить его снова воспроизводить весь обход. Сохранённую рабочую R2 не
переписывать; изменения готовить в отдельной приватной копии. При несохранённой
модели Editor сначала сохранить её отдельным резервом.

Справка **именно2.6.15.0**: «Пользователи» (`editor-users.html`) сообщает,
что страница в колонке «Только чтение» запрещает выполнение OnClick, OnDblClick,
OnMouseUp, OnCellClick. Открытие верхней вкладки/подсветка объекта этого не
опровергают. Проверить настоящего текущего пользователя, права страниц
`PageUiAlarms`/`PageUiCharts`, отдельные ограничения объектов `UiMessages2`/
`UiTrendsAll1` и видимость нужных системных групп. Права Windows здесь не
заменяют права пользователя проекта; не менять ACL/DCOM ради гипотезы.

Если установлен конкретный запрет, исправить только нужные права навигации
в копии, сохранив ограничения командных объектов. Не выдавать всем пользователям
полные права и не снимать проверки Apply. Сохранить изменения штатно, проверить
две кнопки и получить фактическое открытие нужной панели текущего Client.
Исправленную причину подтвердить сравнением до/после, а не предположением.

## 2. Если причина не установлена — две трассируемые кнопки

Готовый файловый helper `tools/prepare_native_panel_probe.py` меняет только
тела OperatorConsole, UiMessages2_OnClick и UiTrendsAll1_OnClick в новой копии.
Он требует текущие проверенные SHA сохранённых Pages/Scripts и источник
семейства `codex_diag_11_review_station_card_*`:6 страниц/169 Text/48 скриптов/
15 связок. ID, metadata, Pages, Windows, архив, переменные и профили сохраняются;
старый bytecode исключается. Не применять к более раннему sidebar-probe.

Пример вызова с локально установленными путями/хешами, не с примерами хешей:

```powershell
python -I -B tools/prepare_native_panel_probe.py `
  --project $uiSource --out $uiProbePath `
  --probe-id $uiProbeId `
  --expected-pages-sha $uiPagesSha --expected-scripts-sha $uiScriptsSha
```

Назначение — новый приватный `codex_diag_11_panel_probe_<уникальный суффикс>`
вне Git и исходника; ID — `UIPANEL11-` плюс8–32 заглавные латинские буквы/
цифры. Пример — схема, а не заполненные переменные. CLI сам устанавливает
пути и hash по своему проверенному дисковому источнику.

Штатно открыть/Compile All/Save **новую** копию и проверить её фактическую
активацию одним проектом, сохранив возможность возврата. Выполнить один
проход: BOOT в Server-log → «Аварии»/«Все сообщения» один раз → возврат →
«Графики»/«Все станции ·1ч» один раз. Apply, квитирование, очистку архивов,
пуск/сброс для этого не выполнять. Если захват окна мешает — сразу попросить
оператора открыть конкретное окно/прислать один кадр через доступный канал.

Интерпретация приватных записей с тем же уникальным ID:

- Нет BOOT: ещё не подтверждены нужный модуль/проект/источник журнала.
  Отсутствующий ENTER тогда ничего не доказывает.
- BOOT есть, ENTER нет: проверить доставку события, права и перекрытие
  именно этих объектов; статический audit этого не проверяет.
- CLIENT_EMPTY: источник вызова не дал клиента; не подставлять вымышленное имя.
- BEFORE_API без AFTER_API: прочитать относящуюся к вызову ошибку host/Server.
  Helper оставляет исключение штатного API наблюдаемым, не маскирует его.
- AFTER_API: процедура вернулась; отдельно подтвердить видимую панель,
  правильную группу/период и текущий Client. Это ещё не PASS перехода.

Трасса не пишет имя клиента/пользователя/значения. Она всё равно остаётся
приватным диагностическим материалом. После установления причины вернуться
к копии без трассы; probe не выдавать за готовый интерфейс.

## 3. Завершить один настоящий график в чистой копии

Пустой ряд не объяснять OnClick. Сначала различить сохранение переменной,
наличие тренда/группы, права и выбранный период. БД раньше сохраняла события;
это не доказывает архивацию переменных. Не переустанавливать БД, не сбрасывать
пароли и не добавлять фиктивные архивные точки.

Через штатный Editor проверить существующие архивные настройки переменных
и группу `UiTrend_station_001` из archive-plan. При отсутствии создать группу
в новой копии с существующими проверенными переменными, правильными единицами
и масштабом, не меняя OPC-адреса/свойства командных переменных. SP использовать
по обратной связи, а не по черновику. Давление допустимо только с проверкой
качества, источника и свежести; не заменять недостоверность нулём и не продолжать
линейную кривую как достоверную при потере источника. Если штатный архив raw PV
этого не обеспечивает, сначала реализовать/проверить отдельное представление
достоверности; не объявлять такой график завершённым.

На `PageUiCharts` добавить штатный компонент **«Временные тренды»**, а не новый
прямоугольник с инструкцией. Документация этой версии: `time-trends.html`.
Он показывает текущую историю в диапазоне до60 минут; это **не** архивный
просмотр6/24ч. Сохранить оформленную область, легенду и единицы; подписи давления
с одним знаком. Для6/24ч оставить рабочий переход в настроенную архивную
группу с фактически проверенными периодом, курсором и рядами. Не обещать
встроенный архивный компонент без доказательства его наличия в этой версии.
Свойства шкалы компонента сами не масштабируют переменную: фактический масштаб
задаётся переменной, его нужно проверить отдельно.

Native компонент создать и сохранить штатно. Сначала сохранить приватный
образец/зафиксировать его формат; нынешний Python parser понимает только Text.
Не подавать файл с новым классом в старый Text-only преобразователь и не
дописывать бинарную запись по выдуманной структуре. Подготовить воспроизводимый
source/шаблон/извлечение без профилей/секретов и уместную проверку новой структуры.

После Compile/Save проверить реальное отображение кривой и отдельно архивные
точки за наблюдаемый интервал. Уже существующие точки можно читать; запись
уставки/изменение калибратора без участия оператора для демонстрации не нужны.
При необходимости конкретного опыта с калибратором попросить оператора,
пока продолжая независимую проверку. Длинные подписи/фон/размеры сравнить с
`docs/ui/operator-console-visual-contract.md`, не принять текстовый экран за график.

## Результат и следующий этап

Цель этого прохода — установленная причина переходов и первый реальный
график с проверенным архивом, либо конкретный воспроизводимый блокер с native
доказательством. Не заменять работу ещё одним общим отчётом по15 связкам.
Настройки с полями/действиями остаются **следующей реализацией**, не PASS
нынешнего каталога; не разрабатывать параллельно новую радио/OPC-диагностику.

Проверить изменения нужными тестами и native Compile/Save/Client, сохранить
подробные версии/пути/SHA/действия/снимки только локально. В handoff-ветку —
проверенные исходники/тесты и согласованную краткую публичную сводку без новых
операционных подробностей. main не менять, чужие местные изменения сохранить.
Если дальнейшее действие заблокирует автоматическая проверка, не обходить
её; записать точное действие/причину и завершить доступную часть.

# Station002: после r15e сохраняется отказ; один контроль полного проекта

Локальный `c549261` подтвердил создание exact r15e1480005/SHA219832…171d,
проверку пакета и шести байтов. Его native Open/Compile оставались pending.
Затем оператор снова прислал Illegal opening of configuration file! в
контексте r15e; полный путь на снимке отсутствует. Открытие полной HMI не
принято. Новая production-ревизия на очередном предположении не выдаётся.

Подготовлен **CONTROL_FULL_ORIGINAL_ALARMS.skm**, 1461495 байт, SHA256
`790f095467a359f1896938ab424bb4adb5365af2992ef68046e72d8a53d4700e`.
Источник — только exact полный r15e. Сохраняются 16 страниц, пользовательская
раскладка, оба C, обе Batch-таблицы, кодовая/reset-страница, HAD, навигация
и ссылка на логотип. Только добавленные определения и их каталог заменены
исходной R2550/25, взятой из той же r15e. Указатели релокированы с полной
обратимостью. Ни accepted source, ни повторный nativeR80 для генерации не нужны.

Контроль побайтно равен ранее подготовленному D_FULL_WITHOUT_ALARMS,
которого пользователь не нашёл. Это не повтор завершённого Open: результата
D никогда не получали. Новый helper выводит один полный путь в явной
текущей Windows-папке15, исходник и существующие результаты не перезаписывает.

Восемь целевых проверок прошли: совпадение с независимым frozen D,
побайтная сохранность UI/исходной группы/обоих C, guard изменённого источника,
создание одного файла и отчёта, отказ перезаписи, отказ tampered output,
сохранность источника во всех путях. Нативное открытие контроля ещё не
наблюдалось. Общие 56 тестов не повторялись: runtime/PLC не менялись,
следующее необходимое наблюдение — реальное Open этого контроля.

При Open PASS нужен отдельный штатный SaveAs C_native_full_control.skm
и возврат этого файла для восстановления новых групп через нативную запись.
При Open FAIL остаётся ошибка совместных остальных изменений; блок аварий
не может считаться её единственной причиной. Ни один исход заранее не
объявляется. Задание: `docs/tasks/station002-full-open-control-local.md`.

## Что сделано в Cloud

- `assets/scada/oshsky-ux-r4/layout.json`: единый шаблон четырёх равных карточек,
  крупные F/I/часы, верхняя сводка, existing PLC countdown, ротация/разница часов,
  сессионная лента. Native верхние вкладки/viewer и действующая палитра сохранены.
- `OperatorUxR4.txt`: read-only Pascal форматирует роли/статусы/причины,
  участие в AUTO, разницу часов и пять наблюдавшихся изменений. Нулевой F
  не создаёт резерв/готовность; RUN называется командой; reconnect/перерыв
  не создают выдуманных стартов/остановок. У модуля нет командного/SQL/API I/O.
- Четыре ROкандидата R720..723 и описанный контракт адаптера. Это подготовка
  отдельного OPC review-profile, без изменения работающего сервера.
- [Конкретная локальная задача](../tasks/oshsky-scada-ux-r4-local.md):
  actual r3 → отдельная r4, одна станция во всех входах/окнах, native-графики,
  сохранение старых pressure guards и75сценариев, сборка и свежие доказательства.
  Новых remote start/stop/reset/preset write нет.

## Проверки

Фактический Pascal модуль компилируется FPC3.2.2 с range/overflow checks,
полным Boolean evaluation и UTF-8 строками; **95assertions PASS**. Покрыты
четыре насоса, source/own/current unknown, нулевые/противоречивые состояния,
uint32max, режим/ведущий/RUN, wrap/replay/loss/recovery/clock-gap/разные станции.
Manifest: четыре одинаковые карточки, интервалы и внутренние bounds проверены.

`python tools/run_checks.py`: **63изолированные build/check группы PASS**;
исходное дерево после сборки не изменилось. Выполнены также сверка74полей,
проверка JSON, относительных ссылок новых документов и `git diff --check`.
Native SCADA r4 Compile/Save/Client, actual OPC/radio cadence, события/ack и
SQL-gap Cloud не проверяло. Новая native-копия создаётся локальным по задаче.
Windows пути/хеши выдаёт он после фактического Save As. PLC/HMI/Бабанов и
активные SCADA/OPC/БД/радио не менялись; команд оборудованию0.

# Анимация трёх насосов, HMI-r7

09.11.2026. База кода c2193de, ветка codex/project-handoff-2026-10-31.
Пользователь принял предложенную анимацию и отдельно потребовал сохранить
существующие динамические шкалы. Создан отдельный кандидат HMI-r7 из r6;
ПЛК и оборудование не менялись.

## Результат

- Маленькая четырёхкадровая крыльчатка на каждом двигателе. Кадры переключает
  существующий глобальный макрос HMI, без непрерывного автономного GIF.
  При останове/недостоверных данных первый кадр серый и неподвижный.
- Пять состояний под насосом: «Нет данных», «Остановлен», «Работа»,
  «Подготовка», «ПЧ не готов». Работа зелёная, подготовка жёлтая,
  неготовность ПЧ красная. Это признак физического входа готовности,
  не выдуманный собственный код ошибки преобразователя.
- «ВЕДУЩИЙ» появляется при совпадении выбранного номера и подтверждённой
  роли6, только с достоверными данными/готовностью ПЧ.
- Сохранены все3 существующие BG-шкалы, числа частоты, r6-навигация,
  три колонки управления, настройки/Apply и раздельные таймеры.

## Сигналы и ограничения

Все четыре новых macro input только R: R2500..2512, R2320..2326,
R2380..2382,R2304. Первые три прежних input и их порядок сохранены;
прежний BootAck=W не менялся. Крыльчатки/статусы/метки записываются только
в ранее неиспользуемые LW900..908. Штатный macro-период250мс сохранён.
Две копии C-source и обе variable-table mirrors обновлены согласованно.
Из исходного macro-source сохранено всё вне вставки функции и её вызова.

Работа требует LB60107, карты31, отсутствия per-drive communication alarm,
согласованных частоты и качества1/2. Частота используется в прежнем масштабе
0.1Гц; калибровка реального ненулевого показания ещё не подтверждена.
Темп750/500/250мс на кадр условный, не измеритель механических оборотов
или расхода. Красный статус не выдаёт неизвестную диагностику за fault code.
Недостоверный снимок обозначается «Нет данных», поскольку причиной может
быть как связь, так и несовместимая карта/несогласованные значения.

Новые чтения суммарно48байт полезных данных плюс протокол; реальную нагрузку
на последовательный порт и обновление интерфейса нужно измерить на стенде.
Реализация не утверждает нулевого дополнительного трафика.

## Выполненные проверки

-59 сценариев исполняют именно новый C-код через host C compiler:
  независимость1..3, останов/возврат связи, несовместимая карта, per-drive
  link loss, некорректное качество/частота, приоритет неготовности,
  подготовка в AUTO/MANUAL, подтверждённый ведущий, три диапазона темпа.
  Входной снимок не меняется; HMI-записи ограничены LW900..908.
- Структурное восстановление всего source побайтно: изменены только3
  status-records, добавлены6 display-records, macro и служебные адреса.
  В основном экране79widgets вместо73; остальные13 counts сохранены.
  Все24 directory offsets/back-pointer/EOF корректны; единственная
  изменённая metadata-секция17 — macro, остальные21 сохранены.
- Предпросмотр через Chromium/localhost: шрифт загружен, три крыльчатки
  переключают кадры; при снятии связи останавливаются, все метки исчезают,
  ошибок JavaScript нет. Это браузерный макет, не SKTool Simulator.

- Полный изолированный прогон52групп PASS; рабочие исходники сохранены.
- Чистая минимальная4-file Python-S сборка воспроизводит exact-r7;
  неверный source и существующий target отвергаются без перезаписи/побочных
  output-файлов. Источник сохранён.

Native SKTool opening/Compile/font embedding/Offline Simulator ещё НЕ
наблюдались. Попытка независимого запуска vendor SKTool в отдельном
Linux/Wine окружении не дошла до приложения из-за сбоя32-bit загрузчика;
это не результат проверки SKM и не причина переустанавливать Windows SKTool.
На локальном ПК использовать уже установленный редактор, File→Open.
Облачные vendor-exe/runtime/logs находятся внеGit и не поставляются.

Полный native-проект в Git не публикуется. Для локального готовятся
source-locked Python3stdlib сборщик, рецепт, C, шрифт, интерфейс и проверяемый
manifest. Сначала создать готовый новый SKM, затем native-приёмка; работу
не заканчивать только helper-файлами. Если исходной r6 ещё нет, её можно
воспроизвести включённым прежним r6-пакетом из точной последней r5.

Шкаф под напряжением без двигателей; Port0 общий для ПК/HMI. Физическая
связь/backup/загрузка не подтверждены новыми сообщениями. Этот пакет не
разрешает подключение/Download/команды ради проверки анимации.

# Восстановление исходника PLC05 для подготовки унификации

05.11.2026. На пользовательском снимке локальный CLI сообщил, что PLC05
отсутствует в его дереве, а получение новой ветки блокируется записью
FETCH_HEAD. Новые PLC/HMI-файлы и native-проверки этим проходом не выполнены.
Полного локального отчёта в удалённой ветке нет; вывод относится к снимку.

Cloud подтвердил причину отсутствия PLC05: файл
`artifacts/station-setpoint-feedback-01/station_MC_CM55_900G_05.pdw`
исключён правилом `.gitignore`, поэтому checkout не доставляет его.
В прежнем задании этот путь ошибочно был указан без шага восстановления.
Отслеживаются исходник04 и детерминированный offline-сборщик05.

В отдельную временную директорию извлечён именно коммит `a931a68`, уже
имеющийся у локального CLI. Из корня этой копии успешно выполнены:

```text
python tools/build_setpoint_feedback_pdw_01.py
python tools/check_setpoint_feedback_01.py artifacts/station-setpoint-feedback-01/station_MC_CM55_900G_05.pdw --out recovery-check.json
```

Сборщик проверяет SHA исходника04, сохраняет отличающийся существующий
файл назначения и создаёт также вспомогательные артефакты в своём каталоге.
Поэтому выполнять в отдельной доступной для записи копии подготовки,
сохраняя прежние локальные результаты.

Результат: 178479 байт, SHA256
`6aba2a67d07596e4a479c462412859565186de86b410a3cd44476a81f20ffe81`.
Побайтово совпадает с PLC05, ранее проверенным в cloud. Строгий checker
подтвердил 7 добавленных сетей/56 байт, сохранение 1834 прежних сетей,
всех девяти таблиц и версии карты32. Это статическая проверка файла,
не native F8, не загрузка и не испытание ПЛК.

Между `a931a68` и `fdab562` менялась только документация, поэтому новый
fetch не является зависимостью именно восстановления05. Отказ доступа
к Git-метаданным не обходить; работу вести в разрешённой копии.

Далее продолжить ранее согласованную унификацию2/3/4 с HMI-настройкой
в отдельных проектах. Пути WinProLadder/SKTool установить по имеющимся
процессам/ярлыкам/установкам: отрицательный `where` проверяет лишь PATH.
Фактические CPU/порты/HMI-профиль и native-компиляция остаются отдельной
проверкой; наличие окна другой программы не подтверждает выбор нужного
насосного проекта. Полные частные отчёты сохраняются локально.

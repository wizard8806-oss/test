# Исправление сетей защиты давления: r2

07.11.2026, cloud Linux; ветка `codex/project-handoff-2026-10-31`, база
`accd2e9`. На снимке пользователя WinProLadder отклонил HP-r1 при F8:
E0 Unrecognized network в20_SAFETY, видны11ошибок. Заголовок и дерево
показывают HP-кандидат и FBs-24MC. Это реальный отказ первой версии,
несмотря на прежние27сценариев и успешное форматирование мнемоник.

## Причина и изменение

Изолированный hash-checked Prolad18.dll воспроизводит отказ11из29сетей
r1 через `_CodeTranNode`. Две ветви ADD имели непредставимое подключение
EN/carry; остальные отказавшие сети содержали слишком длинные условия.
Мнемонический formatter эти ошибки не выявлял.

В r2 арифметика использует существующую топологию native-сети60.138:
OUT TR0, AND SHORT, LD TR0, AND OPEN, FUN11. Условия проверки параметров
и давления разбиты на короткие этапы. Внутренние R2880..R2883 каждый scan
обнуляются и вычисляются до использования; HMI их не записывает.
Прямых ссылок в исходном code и перекрытий с9Modbus-таблицами/их R-буферами
нет. Полная проверка внешних/косвенных привязок остаётся отдельной.

Контракт защиты сохранён: срабатывание PV>SP+Δ, начальный Δ2,00бар,
автосброс при достоверном PV≤SP, удержание состояния между этими порогами.
Недостоверное давление запрещает RUN и не сбрасывает trip. Исходный
абсолютный предел12бар сохранён. Новых команд пуска нет. Настройка запаса
через draft/Apply подготовлена только при STOP и выключенных RUN.

## Доставка и следующий шаг

Создать r2 через локального Python по обновлённому pinned manifest,
в новой папке, сохранив r1 для сравнения. GUI/DLL/pip не нужны для сборки.
Затем открыть именно `_r2.pdw` в WinProLadder и выполнить F8; если ошибки
останутся, фиксировать полный результат, файл/сети без загрузки в оборудование.
Новые предупреждения отличать от уже наблюдавшихся исходных W85.

SKM и N2/3/4 всё ещё не изменены. Интерфейс R2868..R2879 не меняется,
R2880..R2883 служебные. Следующие правки HMI/N сохраняют защиту и её адреса.

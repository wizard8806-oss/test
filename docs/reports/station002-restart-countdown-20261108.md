## Источник времени и отображение

В существующем30_RECOVERY: R2520/R2521 — заданные15..3600секунд,
R2522/R2523 — фактически прошедшие секунды. Счёт разрешён M1764/M1765
только после восстановления соответствующего входа. После обеих пауз
T96(.1,20) проверяет готовность ещё2секунды. Эти условия/значения не меняются.

Новая вставка **только читает** состояние контроллера и публикует:

| Слово | Значение |
|---|---|
| R2525/R2526 | Остаток отдельной паузы, с; минимум0 |
| R2528 | Общий отсчёт до разрешения AUTO, с; max остатков + финальные2с |
| R2532 | Причина/состояние0..7, совместимые с существующим Message Display |
| R2533 | 1 — общий отсчёт достоверен и активен;0 — показывать прочерк |
| R2534 | Внутренний максимум остатков |
| R2535 | Текущее слово T96, единицы0.1с, только чтение |
| R2536 | Оставшаяся финальная проверка2/1/0с |
| R2537 | Маркер интерфейса27115 |
| R2538/R2539 | Значения строк сухого хода/питания на странице пауз |

При обоих событиях паузы идут как в исходнике; они не складываются.
После окончания первой ждём более долгую и затем исходную проверку2с.
При отсутствии воды/питания нет обещания времени пуска; причина остаётся
«ожидание подпора/питания». При других блокировках общий индикатор — прочерк,
статус5 «ожидание готовности», отдельные ещё идущие паузы продолжают
отображаться на странице настроек. В STOP/после отмены или завершения
ожидания отсчёт скрывается. Последнее активное значение —1, не «пуск через0».
По завершении исходная логика разрешает AUTO; фактический RUN также зависит
от обычного запроса давления/прочих условий, которые не менялись.

В неактивных строках настроек R2538/39 показывают действующий период,
сохраняя прежнюю возможность сравнить его с черновиком. При активном
ожидании соответствующая строка показывает остаток; общий допустимый
отсчёт включает финальную проверку. Ввод/Apply R2540/R2541 не менялись.

  SHA256 `780267f80d2f107c584ded1e8f48a63c65ad23d977255cdcbe895ed2b791b73b`.
  Source — точный трёхнасосный r1 SHAa6e9c5c0…c745.29сетей/434байта перед

- HMI `pump_station_3p_countdown_r2.skm`,1321783байта,

  База — принятая HMI-r1 SHAd9f089f0…f43175 (либо точное воспроизведение
  из draft7484c947…a2e5e7 по прежнему pinned geometry-рецепту).

На главной странице освобождённый четвёртый информационный блок стал
«ПУСК, с»: существующий ND10048 читает R2528, целые секунды/5разрядов.
Его прежнее условие видимости ненулевого слова перенесено с R2513 на R2533;
существующий MD10050 показывает прочерк в состоянии0. Пустые состояния1/2
fallback сохранены. Не создавались новые Qt-объекты или непонятные флаги.
Формат5/0 взят из существующего ND12004 для секунд. Старые ток/Гц/подписи
четвёртого слота заменены описанием автоперезапуска. Четвёртый нижний статус
получил уже существующий valid-only visibility-блок BG10054; R2513=0 в3PLC.
Главный фон переключён на согласованный `pumps-3.png`, первые три подписи/
индикатора переставлены по проверенным зеркалам геометрии к трём насосам.

На странице существующих пауз ND12004/ND12012 читают R2538/R2539,
MD12018 — новый статус R2532 с теми же8состояниями. Три текста уточнены
как обратный отсчёт/ожидание готовности. Изменены108точных полей/зеркал:
QString и разделённые адресные дескрипторы заменены целиком, включая
числовой индекс адреса; длины/количество объектов/кнопки/управляющие
привязки сохранены. Все изменения привязаны к exact source SHA.

Полные PDW/SKM/детальные журналы приватны. Во внешнем пути ST0 требуется
согласованный `pumps-3.png`: источник в публичных assets и его SHA указаны
в manifest; существующую отличающуюся картинку не заменять вслепую.

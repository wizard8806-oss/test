## Что установлено по документации

Для анализа извлечены справки оригинального **Simple-Scada Demo 2.6.15.0**
из [публичного архива производителя](https://disk.yandex.ru/d/WtVahxw0U7nrJg),
раздел выпуска 24.11.2024. Installer не запускался; сторонние binaries/Help
остаются вне Git. У извлечённого Editor.exe FileVersion=2.6.15.0, SHA256
`7690ae80f6f0c51347f1580a7298304d5e156f0b25c278fecbe165d7617aff3c`.
Этот demo-бинарник отличается от экземпляра прежней loader-проверки;
новой эмуляции/нативного исполнения Editor в этом проходе не было.

В `Simple-Scada 2 Скрипты.chm`:

- `gotomessagesgroupclient.html`: функция действительно открывает меню
  сообщений на заданном Client; ALL=-1, ACTIONS=-4, UNCONFIRMED=-1000,
  ACTIVE=-1001. Текущие константы сборщика соответствуют справке.
- `gototrendsclient.html`, `gototrendsgroupclient.html`: переход в меню
  трендов с необязательными From/To. Дни в TDateTime и текущий часовой
  диапазон соответствуют контракту; возвращение функции не доказывает GUI.
- `howfindclientname.html`: GetClientName предусмотрен для OnClick.
  Пустое имя остаётся отдельной проверяемой причиной, подставлять имя нельзя.

В `Simple-Scada 2 Руководство.chm`:

- `editor-users.html`: «Только чтение» страницы запрещает выполнение
  OnClick и нескольких других управляющих событий. Это основание проверить
  права конкретных страниц, **не установленная причина** текущего отказа.
- `time-trends.html`: существует встроенный компонент «Временные тренды»
  с диапазоном до60мин. Шкала компонента не меняет масштаб тренда: он зависит
  от шкалы переменной. Этот компонент не заменяет архивный просмотр6/24ч.
- `editor-trends.html`, `vararchive.html`, `trend-sect-prop.html`: группа,
  архивация переменных и права просмотра — отдельные настройки. Наличие БД
  с сообщениями не доказывает накопление точек переменных.

## Что подготовлено

`tools/prepare_native_panel_probe.py` создаёт отдельную приватную копию
сохранённой R2 по проверенным Pages/Scripts SHA. Меняются три тела скриптов:
OperatorConsole и две конкретные кнопки. Остальные45 скриптов, metadata/ID,
169 Text/6 страниц/15 привязок и остальные ресурсы сохраняются; bytecode
исключается. Ни активации проекта, ни изменения прав/архива, ни команд нет.

BOOT/ENTER/CLIENT_EMPTY/BEFORE_API/AFTER_API отделяют загрузку/событие/вызов.
Имя клиента не пишется, GetClientName считывается один раз. Ошибка самого
логирования не ломает навигацию; ошибка штатной функции остаётся видимой host.
Отсутствие ENTER нельзя трактовать без BOOT и исправного логирования.
AFTER_API не равен видимой панели или наличию архивных точек.

Новый validator выполняет 34 Pascal assertions с синтетическими API: оба
обработчика, текущий/пустой клиент, точная группа и часовой интервал, исключение
API, отказ логирования и отсутствие записи уставки. Проверены сохранение
ресурсов/metadata, отсутствие перезаписи исходника, пины и отказы для чужого
тела/повторной трассы/неверного пути/обрезанного файла; CLI работает с `-I`.
Это облачные проверки, не native-исполнение/GUI на ноутбуке.

Полный `tools/run_checks.py` выполнен 04.11 в изолированной копии: **46 групп
PASS**, включая новую проверку, Pascal/PowerShell и исходные контракты.
Проверенные исходники при прогоне не менялись. Optional vendor loader и
Windows/GUI/архивный runtime в этот прогон не включены. После него исправлена
только документация с фактическим hash demo-бинарника и результатом тестов.

## Независимая проверка подключения SCADA

Локальный отчёт подтвердил у рабочей10 `Servers.ssr`,241байт, SHA256
`efd91d5df93359c3320c72e185941247688b9ffad8fe3a5af196a9ed675a15fc`.
В репозитории есть **побайтово соответствующий этому SHA** профиль seed.
Это позволило проверить его самостоятельно без передачи приватного проекта.

Оригинальный Editor2.6.15.0, SHA256
`c90b3e893d9918c3e0dd95aedb7d0b6744453dc96003244d51dd8d2282078b57`,
содержит в RTTI TM_DAServer Boolean-поле **ReadOnly по object+0x26**.
Его загрузчик0x11e0214 при версии2615000 читает этот флаг из **file offset236**.
Это проверено исполнением оригинальной функции в изолированной x86-памяти:
адаптированы только строковые/потоковые чтения и очистка пустых mock-строк,
OS/GUI/OPC не вызываются. Стоп до cleanup0x11e049c.
Соседнее integer-поле Tag по+0x28 не перепутано с Boolean ReadOnly.

**В совпадающем сохранённом профиле ReadOnly=true.** Это настройка
подключения `localhost / InSAT.ModbusOPCServer.DA` внутри Simple-Scada,
а не флаг доступа отдельного тега в MasterOPC. По
[официальному руководству](https://simple-scada.com/help/manual/opcdanew.html)
«Только чтение» запрещает запись из SCADA в переменные этого OPC-сервера.
ReadWrite у PressureSP_Command и хороший readback этот запрет не отменяют.
Найдена конкретная блокирующая настройка файла; UI/состояние загруженного
runtime всё ещё нужно сверить на ноутбуке перед исправлением.

В копии байтов, только в памяти,236 изменён1→0. Та же оригинальная функция
прочитала ReadOnly=false; прочие байты прежние. SHA такой конфигурации:
`c0662185786f2204479c9ad90d2dcc2ed0dbb79d9d532942f1841f650ef498b6`.
Ни рабочая10, ни seed, ни GUI, ни ПЛК этим тестом не изменены.
Это ещё не доказательство исправленной доставки OPC/успешного Apply.

## Инструменты и проверки

[Данные нативной эмуляции](station10-opc-write-gate-native-20261101.json)
и [верификатор](../../tools/verify_scada_opc_write_gate_native.py)
фиксируют версии/хеши/порядок чтений/оба состояния. Для повторения нужен
отдельно полученный проверенный Editor, pefile/unicorn, запуск с
`PYTHONPATH=tools:.local-tools/python`, `--editor <Editor.exe> --out <новый.json>`.
Дистрибутив редактора в Git не добавляется.

[Read-ScadaOpcWriteGate.ps1](../../tools/Read-ScadaOpcWriteGate.ps1) — только
чтение. Поддерживает ровно два проверенных241-байтовых SHA: исходный профиль
и его изменение единственного флага. Любой другой профиль отклоняется;
не выводит содержимое неизвестной конфигурации и не изменяет файл.
`connectionReadOnly=false` означает флаг файла, не проверку полевой записи.

[Проверка считывателя](../../tools/validate_scada_opc_write_gate_reader.py):
8 сценариев PASS на PowerShell7.5.4/Linux — оба профиля, неизвестное изменение,
усечение, хвост, невалидный Boolean, приватный неизвестный профиль, отсутствующий
файл. Входы сохранили байты, секретная тестовая строка не попала в вывод.
Windows PowerShell5.1 этим облачным прогоном не заявляется; новый probe надо
запустить локально перед изменением. Старые runtime-исходники не менялись,
полный runner/установщики не повторялись.

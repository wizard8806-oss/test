Проверять общую PLC/CL50 логику вместе с HMI, не назначать единственной
причиной дисплей или заранее объявлять одинаковый root двух эпизодов.

## Что проверено в Cloud

1. Из исходного четырёхнасосного SKM
   SHA `13cc9f7d1c5fa59d25c0eb871a2deb3e6f1ef6ca5079be2f5828df5f9e8f5867`
   прочитаны два одинаковых C-зеркала. Этот **архивный** макрос ожидает31;
   текущую actual native HMI r3d/новее и её ABI Cloud не читало.
2. Архивный C скомпилирован без правки алгоритма, с host memory/aliases.
   Шесть случаев PASS: неизменная маска после mute21600вызовов с движущимся
   RTC (условные90мин при250мс, не90мин реального ожидания); потеря/возврат
   связи без изменения маски; новый бит; снятый и снова появившийся бит;
   изменение CL50 generation при той же24-битной маске; перезапуск static-state
   макроса. Первые два сохраняют тишину, остальные четыре вновь разрешают звук.
   Проверялись логические bits, не физическое звучание.
3. В source04 PLC SHA
   `a25f9b5d2fe006bcb039896bae3989569b08e1b1adc4b503a755bfd5e3b22993`
   найден настоящий CL50-компонент96.L. **Он публикует поколение в старших
   битах R2551**; нельзя анализировать только95.W и считать эти биты нулевыми.
   M1801 — новое событие, M1802 — mute, R2678 — поколение1..127,
   R2679 — ожидаемый token256+generation, R2676 — захваченная команда сервиса.
   96.L127..135 обновляют/публикуют поколение и mute. R2660 — желаемый режим
   CL50; в этом коде1 — красный без звука,12 — красный с пульсацией/звуком.
4. На actual bytecode-предикатах96.L077..140 существующим interpreter
   выполнены4последовательных состояния. При стабильных двух авариях и
   принятом mute token поколение10, M1802=1, R2660=1. Искусственная третья
   авария на один scan дала поколение11/M1802=0/R2660=12. После исчезновения
   третьей исходная маска восстановилась, но поколение11 и режим12 остались.
   FUN150/CL50/настоящий40-минутный эпизод этим не исполнялись.

Отсюда есть **проверяемое объяснение**, согласующееся с неизменным журналом:
короткий PLC-импульс успевает изменить generation и сбросить mute, хотя HMI
не опросила сам импульс и не добавила строку. Архивный HMI также снимает
mute по новому generation при той же видимой маске. В реальном эпизоде такой
импульс **ещё не записан**. Возможны также перезапуск PLC, повторная загрузка
локальным или иной источник звука; незамеченный перезапуск HMI не исключён.

В архивном HMI нет40-минутного expiry mute. Там есть legacy запись LB60185
при принудительном LB60117=0; её наличие/назначение в текущем файле/модели
нужно проверить. Предыдущий [vendor-backed разбор звука](station002-panel-services-r8-20261109.md)
относился к другой трёхнасосной версии. Не переносить весь её макрос/Map31
или автоматически объявлять старую запись причиной нынешнего эпизода.

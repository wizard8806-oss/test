# Телеметрия «Бабанов»: подготовка исправления и настольной проверки

17.11.2026. Пользователь сообщил, что последние версии уже работают на
объекте: ток не отображается, у всех трёх насосов пропадают частота, шкала,
зелёный вентилятор и статус; общей ошибки связи панели с ПЛК нет. Доступ
к объекту затруднён. Сейчас на столе компьютер с редакторами; пользователь
может позднее добавить ПЛК, панель и один ПЧ. Это уточнение заменяет старое
состояние «на оборудование ещё не загружали». Точные байты полевых файлов
отдельно не снимались.

## Дефекты сохранённой программы

Исследован принятый native PLC `station_3p_reset_r15_native.pdw`,
206320 байт, SHA256
`d45ada8b0781175cf5c4a91e14a2f4bf23d9c037957ce830da44c1daca2e58ae`.

1. Сети `65.T005/014/023` сбрасывают собственную свежесть семисловного
   снимка `M1748/1749/1750` при ошибке любого FC03 того же slave. Они
   сравнивают `D301`, но не номер строки в младшем байте `D300`.
   Ошибка другого параметра стирает ещё свежую частоту/качество.
2. Сети `65.T008/009`, `017/018`, `026/027` дополнительно требуют
   `M610/611/612` для публикации STOP/RUN. Эти общие признаки меняются
   от других запросов. Поэтому свежий собственный снимок всё равно
   превращается в `R2510..2512=0`.
3. В прежнем `PumpAnimation` есть ещё один фильтр: общий Modbus alarm
   `AlarmWords[0].9..11` скрывает вентилятор/статус независимо от качества
   собственного снимка.

Рабочая RAM-таблица `R2900` содержит 14 строк; нужные FC03 `0x1000/7`
имеют номера 0/3/13 для ПЧ1/2/3. ROM-шаблон `R5000` содержит 18 строк;
не подменять им работающую таблицу. Старший байт D300 — результат,
поэтому номер строки выделяется через AND255.

Ток уже приходит с тем же ответом в `R2806/R2814/R2822`. В доступной
облаку HMI r17a вместо чисел остаются `Text16002/16004/16006` со значением
«— А», а Screen4 сообщает, что опрос тока ещё предстоит добавить. Опрос
уже есть; не закончен путь от снимка до виджета. В cloud нет самого r18a,
поэтому сохранность этих конкретных заглушек в нём проверяет local.
Масштаб 0.1 А — по принятому [руководству900G ver1.26](../drive-frequency-current-2026-10-29.md);
на конкретном ПЧ сверить с его дисплеем, не считать масштаб измеренным.

Это воспроизводимые дефекты исходника, согласующиеся с жалобой. Они ещё
не доказаны как единственная причина именно полевого отказа. Задержки
RS485, реальные ответы и качество питания на объекте здесь не измерялись.

## Подготовленное исправление

`tools/build_telemetry_quality_r16.py` принимает только указанный native
r15 и создаёт новый PDW. Добавляет `R3080=D300&255`; ошибка инвалидирует
снимок только для собственной строки. Boot и прежний watchdog 5 с
продолжают инвалидировать. Только шесть сетей качества индикации перестают
требовать общий M610. Общий Modbus alarm и все сети управления/защиты
сохраняются. При принятом снимке одновременно копируются F и I.

| Поле | ПЧ1 | ПЧ2 | ПЧ3 |
|---|---|---|---|
| Частота, 0.1 Гц | R2500 | R2501 | R2502 |
| Ток, raw ×0.1 А | R2504 | R2505 | R2506 |
| Качество снимка: 0 unknown /1 stop /2 run | R2510 | R2511 | R2512 |
| HMI ток | LW960 | LW961 | LW962 |
| HMI достоверность тока, 0/1 | LW963 | LW964 | LW965 |

Новый контракт тока `R2509=27133`, build marker `R2861=27133`.
Используются свободные слова уже существующего Batch16 R2500/26 байт;
нет новых опросов, входных переменных макроса или изменений pVar ABI.
Reset27131/NativeFault27120/Map32, Port2/CL50, Port3, serial-таблицы,
приоритеты, команды RUN/reset и STOP guard не переписываются.
M1748..50 также используются downstream-потребителями свежести; смысл
теперь относится именно к их собственному ответу, а не чужой ошибке.

Кандидат `station_3p_telemetry_r16_candidate.pdw`: **206362 байта**, SHA256
`15151a98daa5c34eb3c64dd2bbebecf71a5f77cf441c2218180584e839e2091c`.
Программа выросла на 46 байт; свободно **618 байт /309 WORD**.
Все не перечисленные сети, данные и non-PC metadata/9 таблиц проверены
побайтно; штатные PC/checksum пересчитаны. Native Open/Syntax Check
этого нового кандидата ещё не выполнялись. Прежние r15 имели 0 errors /
25 inherited W85; это не результат проверки нового файла.

`tools/prepare_telemetry_hmi_r19.py` по умолчанию требует точный последний
r18a f09dd824…53d5. Точечно меняет два зеркала PumpAnimation и подпись
зонда: убирает общий alarm gate, публикует ток/достоверность в LW960..965,
маркер зонда **27134**. LB60107/Map32, собственное качество F/Q, READY,
приготовление и роли сохранены. Без нового PLC marker ток недостоверен,
а старая частота продолжает использовать прежний контракт.
Настройки/таблицы переменных/группы не меняются; абсолютные указатели
перенесены; обратное преобразование полностью восстанавливает исходник.
Виджеты тока затем добавляются штатно в SKTool. **Stage не является
готовой HMI для загрузки.** Макрос надо нативно Compile/Save/reopen.

Cloud не имеет r18a; helper испытан на доступном **r17a ancestor fixture**
3fa5c20f…0e1. Такой fixture нельзя выдавать вместо полевого r18a: он
потерял бы памятку РКФ и последующие native-правки. Полная HMI r19 пока
не изготовлена. Новую основу брать только r18a, все 17 страниц/7 групп,
PNG16fad…3ee78, автопоказ РКФ/LB811 и ручной LB810 сохранить.

## Доказательства и границы проверки

- Независимый `validate_telemetry_continuity.py` исполняет реальные байты
  PDW: старый r15 **66/162 FAIL**, новый кандидат **162/162 PASS**.
  Отдельно проверены другие строки/функции/slave, result high byte,
  boot/watchdog, выигрыш нового снимка, generic-link false, границы F,
  согласованное принятие/отклонение F/I и новый marker.
- `validate_telemetry_hmi_r19.py` извлекает настоящий PumpAnimation C из
  двух согласованных зеркал SKM и исполняет его через host C compiler.
  Старый r17a **102/115 FAIL**, изменённый ancestor **115/115 PASS**.
  Проверены три независимых канала, общий alarm при свежем снимке,
  invalid F/Q/link/map/marker, READY/роли, нулевой ток и uint16, потеря
  одного канала/восстановление; нет изменений входов/команд/чужих LW.
- Повторная сборка детерминирована. Подмена источника и подстановка r17a
  вместо default r18a отвергаются; существующие output/report не затираются.
- В изолированной папке только с 30 файлами manifest повторены обе сборки
  и оба validator: зависимости доставки полны, native в Git не требуется.
- `tools/run_checks.py`: **57/57 build/check groups PASS**, источники
  сохранены; FPC/PowerShell взяты из имеющегося `.local-tools`.

Host execution не доказывает SKTool ABI, native rendering, Syntax Check
нового PDW или физический Modbus. DLL/GraphChecker в этой сессии не
запускался; native Syntax Check обязателен локально. Полевых команд не было.

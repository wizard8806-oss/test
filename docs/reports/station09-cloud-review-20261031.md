## Подготовленный инструмент и его проверки

`tools/Read-MasterOpcProfile.ps1` читает MBP-кандидат офлайн. Он не подключается
к OPC/Modbus, не меняет файл и не выводит пароли/скрипты/посторонние объекты.
Повторяющиеся JSON-члены не схлопываются, повреждённый/незавершённый JSON
отклоняется до разбора. Вычисление выводится лишь как boolean/0/1 флаг;
тело вычисления скрывается и отмечается ограничением.

Команда: `python3 tools/validate_masteropc_profile_reader.py`.
**13 сценариев PASS** на PowerShell7/Linux: UTF-8/BOM/CP1251, отсутствие целевого
объекта, повреждённый JSON, незавершённый внешний объект, лишняя запятая,
неверное число, несколькоMBC, превышение размера, вложенное поле вместо адреса,
тело вычисления и неоднозначное имя узла. Все входы сохранили SHA; синтетические
секреты/тела скриптов отсутствовали в stdout/stderr; дубли тегов/Access сохранены.
Подходящие поля сопоставлены с существующим независимым Python-разборщиком MBP.
Проверены состав изменений и ссылки отчётов;225 существующих файлов вне
AGENTS/HANDOFF сохранили хеши, включая исходный локальный отчёт и ресурсы
SCADA/ПЛК/HMI. Индекс при приёме был пустым, местные изменения не удалялись.

Облачные инструменты: PowerShell7.5.4, Python3.12.14. Нативный запуск считывателя
в Windows PowerShell5.1 и разбор действующего MBP **ещё не проверены**.
Даже успешный разбор не доказывает активность файла, текущие значения,
масштабирование SCADA или правильную расшифровку числовых enum MasterOPC.
Полный программный runner не запускался: существующий runtime не менялся,
выполнен целевой набор нового офлайн-считывателя. Оборудование не затрагивалось.

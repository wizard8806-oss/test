## Что означает прежний таймаут SCADA

Пользователь уточнил цель: штатно уставка задаётся с HMI, SCADA должна
корректировать **тот же регистр**, сохраняя работу HMI. Это не отдельная
уставка SCADA/ПЧ. Дополнительно самостоятельно прочитан сохранённый
`source/hmi/pump_station_4_37.skm`, SHA256
`13cc9f7d1c5fa59d25c0eb871a2deb3e6f1ef6ca5079be2f5828df5f9e8f5867`.
Найдены точные UTF-16BE строки `R2100#1#6#1#2100#R#1#`, в том числе рядом
с именами NE5002/ND3014. Смещения сохранены в JSON. Это согласуется с общим
входом R2100; строки не заменяют полный нативный разбор объекта/макросов
и не доказывают, какой проект загружен в работающую панель.

Принятый путь остаётся общим: HMI → R2100 ← PressureSP_Command SCADA;
R2360 — читаемое зеркало ПЛК. Временный черновик SCADA не является второй
рабочей уставкой. Уже существующая защита до Apply отменяет устаревший
черновик, если рабочая уставка изменилась с HMI/другого источника. Возможную
периодическую обратную запись старого значения из панели здесь не исключили;
исправлять HMI/вводить второго владельца уставки по гипотезе нельзя.

Повторно прочитан
[StationDiagnostics.txt](../../artifacts/station-setpoint-click-fix-01/scripts/StationDiagnostics.txt).
После проверок актёра/черновика/привязок сначала вызывается AddMessage с
номером/целью запроса, затем один внешний setter
`Command.Value := Integer(SpControlTarget)`. Его возврат без исключения
сам по себе не подтверждает асинхронную доставку OPC.

Этап2 завершается приёмом ПЛК, только если и R2100/readback команды, и
R2360/рабочая уставка равны цели, а счётчик ПЛК отличается от исходного
на двух последовательных подходящих обновлениях с разными счётчиками.
Иначе через20с фиксируется таймаут без повтора/отката. Последующее ожидание
подтверждения ПЧ — отдельный этап45с. Из текста таймаута нельзя вывести
ошибку ПЧ, неверный пароль или отказ конкретного Modbus-запроса.

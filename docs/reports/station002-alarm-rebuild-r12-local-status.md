# HMI alarm rebuild r12 — краткий локальный статус

Задание закреплено к `00fc8a2c17a9ab128985ef4658cf2d19f5d5aeb0`. Из точного r11 создана отдельная диагностическая основа без целого HAD8288: 1,282,099 байт, SHA256 `e5ae403199a9fc774a80e95905babc876a443b1e792c1e391b1a6a817c64606a`. Четыре package-файла прошли проверку размера/SHA; validator подтверждает сохранность остальных native widgets/macros/alarm definitions/metadata. Это **не готовая HMI**: replacement Historical alarm Display пока отсутствует.

Пользователь сообщил, что r11 таблица видна в Simulator, но открытие Screen9 редактора зависает независимо от состояния Simulator. Причина не установлена. В этом сеансе невозможно сопоставить процесс SKTool с зависшим r11; ни один экземпляр не завершался, другие проекты не затрагивались. Native открытие r12, создание нового HAD, Compile, Simulator и compiled image не проверены.

Следующий шаг оператора: закрыть только свой отдельный зависший r11 экземпляр, затем в доступном SKTool открыть r12 base при закрытом Simulator и проверить Screen9 на открытие/отзывчивость. При успехе создать новый HAD штатным Toolbox; при зависании не удалять другие объекты и не объявлять ремонт. PLC/каскад/макросы/оборудование не менялись; загрузок, Force и RUN не было. Полные проекты и сырые журналы не публикуются.

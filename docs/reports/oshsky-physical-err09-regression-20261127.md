# Ошский: на приводе Err09, на физической HMI «Остановлен»

27 ноября 2026, МСК. Cloud-база8e0fb3601512b13f563ed334209131938e5b1b1d.
Пользователь прислал фото Main физической панели и отдельно подтвердил:
**Err09 оставалась на самом ПЧ в момент этого фото**. После запроса локального
о проверке/фото пользователь подключил ПЛК и сообщил, что доработки сейчас
не работают, хотя при прежних загрузках нужные сообщения появлялись.

На фото Main:

| Поле | Видимое значение |
|---|---|
| ПЛК / режим | Зелёная точка / СТОП |
| Давление / уставка | 0.0 / 4.1 бар |
| В работе / частота ведомых | — из4 /35.0Гц |
| Насос1 | «Остановлен»,0.0Гц,0.0А,наработка0.0ч |
| Насосы2–4 | «Нет данных», F/I прочерки, наработка0.0ч |
| Ведущий / ротация | «Не выбран» /0.0из24ч |
| Общая строка | «Звук отключён» |
| Код/описание ошибки ПЧ | На Main не показаны |

Это подтверждённое пользователем расхождение drive→HMI. По фото неизвестно,
пропал код на Modbus/PLC export, native batch, macro или слое видимости.
Зелёная точка не доказывает свежесть отдельного fault-канала. «Звук отключён»
не подтверждает приём нынешнего mute поколения ПЛК или долгую тишину.
В STOP фото не проверяет active AUTO-отсчёт и вращение работающего насоса.
Общее сообщение о регрессии нужно проверить сравнением версий, не объявлять
все функции проверенными или сломанными по этому одному кадру.

На следующем пользовательском скриншоте локальный пишет: прямые чтения через
COM28 закончены, установленная **r3k** совпала с USB-копией; просит вернуть
кабель HMI→PLC, открыть «Насосы»/«Аварии» и нажать mute. Это сообщение на
скриншоте, не опубликованный native-протокол/хеш r3k. В remote на момент
проверки только8e0fb36; последняя опубликованная HMI —r3j, PLC —r3g.
Текущее установленное состояние/совместимость должны быть сверены локальным.
Из нового сообщения нельзя считать прежнее «кабель на ПК» текущим состоянием.

Действие: принять уже предоставленное фото и Err09 как неуспешную проверку,
сохранить актуальный readback/SKM/макрос/журналы и сравнить r3k с последней
версией, на которой сообщения действительно наблюдались. Совпадение USB
доказывает доставку образа, не его правильность. Использовать уже снятые
COM28-данные; повтор фото/Пуск не нужен. При подтверждённой регрессии вернуть
рабочую логику/привязки в отдельной проверенной копии, сохранив новые функции.

Главный маршрут проверки — [раздел0.1/3 текущего задания](../tasks/oshsky-live-pump1-data-and-native-fault-local-20261127.md).
Mute не должен скрывать код/описание или очищать ошибку ПЧ. В предложенной
нижней области Main сейчас живёт статус звука; это учесть при доработке
[макета](../ui/oshsky-native-fault-preview-20261127.md), его размещение не утверждено.
Текущую SCADA/Gateway/OPC работу и разрешения сохранить.

# Полный контроль не открывается: разделение оставшихся изменений

Пользователь подтвердил по имени CONTROL_FULL_ORIGINAL_ALARMS.skm после
снимка «Illegal opening of configuration file!». Локальный отчёт e73b88c
перед этим подтвердил exact 1461495 байт/SHA
`790f095467a359f1896938ab424bb4adb5365af2992ef68046e72d8a53d4700e`.
Результат — **operator-reported native Open FAIL**, не наблюдение cloud-GUI.
Новые группы отсутствуют: их формат не единственная причина отказа full.
Это тот же файл, что исторический D, которого раньше не было у оператора.
CONTROL_WORKING, A_PAGES_ONLY и C_MACRO_ONLY ранее открывались; их не повторяем.

Две приватные диагностические копии создаются одним stdlib-helper из
единственного existing CONTROL790. Источник не меняется.

| OPEN_PAGES_AND_MACRO_ONLY.skm | 1461431 | 119155c0b1f4ed1e8cbcb69162722955d7773e61df7a254bf1fe0895f28fd00f | Ещё возвращены исходные SB6010, SB24002, ND8278 |

В первом всё остальное сохранено; во втором остаётся в точности объединение
ранее принятых по отдельности A+C. В обоих 16 страниц и одна исходная
R2550-группа, одинаковые с CONTROL новые C и две Batch-таблицы. Старый путь
лого может не существовать: проверяется открытие потока, наличие картинки
этим тестом не утверждается. Никакой JPEG не менялся и не публиковался.

Целевые проверки прошли:

- Независимая композиция вперёд из accepted3599: восстановлен полный producer
  по его edit-review; отдельно выбраны слои без alarm/лого/трёх виджетов.
  Результаты побайтно совпали с контрольным файлом и обеими новыми копиями.
- Та же композиция воспроизвела исходные A и C, ранее открытые оператором.
- Инверсия всех правок, 24 указателя и locator, общий заголовок/16 страниц,
  обе alarm-записи/две C-копии сохранены. У второго файла три возвращённых
  виджета побайтно равны пользовательскому accepted-источнику.
- CLI из Python -S -B даёт ровно заявленные файлы; повтор в ту же папку,
  повреждённый source и source-symlink отклоняются, источники сохранены.

Native Open новых копий не наблюдалось. Порядок: OLD_LOGO; если ошибка —
PAGES_AND_MACRO. Если первая открылась, подозреваем перепривязку ресурса;
если только вторая — старые изменённые виджеты; если обе отказали —
совместную композицию A+C. Это направления следующей проверки, не уже
доказанные причины. При PASS нужен отдельный штатный SaveAs для сравнения.
Новая production-ревизия, Compile/Simulator и аппаратные команды не выполнялись.
Runtime/PLC/STOP-допуск reset и main не менялись. Шкаф отдан.

## Подготовленный пакет радио03

[Payload/инструкция](../../artifacts/radio-autostart-03/README.md),
builder `tools/build_radio_autostart_03.py`, общий runtime/helper и template
manager, validator `tools/validate_radio_autostart_03.py`. C# transport
байт-в-байт соответствует02/SHA89c5762599b6b43044d0688f98f5df4e0d80ac603a70d446ee131351607b0e82.
Новые команды модему/ПЛК/USB/Main50008 не добавлялись. ARADIO1/collector.lock/
обычный сетевой backoff и запрет конкурирующего reconnect сохранены.

Runtime03 получает секреты из DPAPI LocalMachine, не вызывает Read-Host;
его локальные ошибки записываются как UTC/PID/code/type/HResult, без текста
исключения. Подготовка выполняется локально от администратора, вводит ключи
один раз и создаёт SYSTEM/Admin каталог в ProgramFiles и отключённую задачу.
Проверяются хеши payload до выполнения helper, копии/источник конфигурации,
ACL/своя task action/principal. Prepare не перезаписывает каталог/задачу;
Enable отдельно требует подтверждённую публикацию, проверяет lock и только
запрашивает запуск. Disable/Remove отключают триггер, graceful-stop через
radio.stop; файлы/credentials сохраняются для возврата. Автостарт привязан
к boot с30с задержкой, без login/окна; одна задача/одна фактическая станция.

Локальные IO-отказы дают exit1 и максимум3 попытки Планировщика с интервалом
1мин. Protocol fatal (в том числе SESSION_REPLACED) публикуется и даёт exit0:
это предотвращает новый захват сессии, но task result0 не означает здоровье
радио. Состояние нужно читать по radio/status и UTC/PID локального failure.
В XML SYSTEM задан SID/параметром регистрации, без недопустимого LogonType
ServiceAccount: [официальная XML enum](https://learn.microsoft.com/en-us/windows/win32/taskschd/taskschedulerschema-logontype-simpletype)
содержит только S4U/Password/InteractiveToken/InteractiveTokenOrPassword.
Windows-регистрация этой задачи ещё не проверена.

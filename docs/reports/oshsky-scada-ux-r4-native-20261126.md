## Экран и данные

- Обзор и вкладка станции ведут на `PageProcess`. Отдельное окно содержит те же 94 компонента в уменьшенном масштабе. Его значения обновляет общий обработчик. Для регулирования используются прежние обработчики команд. Сохранены верхние вкладки и отдельная страница выдержек и наработки.
- Четыре карточки сохраняют исходные идентификаторы показаний. Для каждой видны частота, ток, часы команды RUN, роль, участие в АВТО, состояние, код и задание. В MANUAL показано индивидуальное задание. В AUTO у работающего ведомого — общее задание ведомых. Для ведущего отдельная действующая частота задания в исходном контракте отсутствует, поэтому поле остаётся с прочерком.
- Возраст показывает время с последнего продвижения счётчика. Экран различает проблемы OPC, карты, свежести ПЛК и отдельного ПЧ. Отказ Q4 оставляет часы четвёртого насоса доступными при достоверном чтении накопителя. Таймер ожидания использует физический номер и остаток из ПЛК. Для ленты изменений используется одно наблюдение на станцию. Радиоканал отдельно в этом проходе не измерялся.
- Частота и ток каждого насоса открывают отдельный ряд в штатном viewer. Все восемь ссылок на сохранённые переменные сверены. Проверена единица четвёртого тока в свойствах Editor, диапазон 0–6553,5 А. Давление и уставка открывают прежнюю группу станции. Выбор насоса, единицы и периода хранится по имени клиента. [Тренды и источник тока ПЧ 4](oshsky-scada-ux-r4-20261126/trend4.png)
- Код каждого ПЧ ведёт в свою группу журнала. При изменении достоверного кода регистрируется время наблюдения SCADA. Ненулевой код требует квитирования, возврат к нулю записывается отдельно. После перерыва первое чтение восстанавливает исходное состояние наблюдения. Для выяснения момента физического отказа или действий персонала нужны независимые данные. Инструкция РКФ для Ошского не привязана. [Группы и ID четвёртого ПЧ](oshsky-scada-ux-r4-20261126/archive4.png)

## Остаток приёмки

На ноутбуке Server использует общую конфигурацию с включённым резервированием. Для отдельного поддерживаемого Server/Client с тестовой БД и отключёнными полевыми выходами изолированная среда не обнаружена. Для завершения приёмки нужны клики из обзора, вкладки и окна в Client при его DPI, просмотр 1/6/24 ч с курсором и возвратом, квитирование с фактической записью времени и чтение архивных точек до и после интервала потери качества. В частности, ещё предстоит проверить, рисует ли viewer линию через пропуск. Полевой лист 26 ноября остаётся самостоятельной проверкой.

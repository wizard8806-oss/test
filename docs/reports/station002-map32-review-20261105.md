# Проверка PLC05 после восстановления: использовать контракт карты32

05.11.2026. На пользовательском снимке сборщик05 завершился с ожидаемым
SHA, строгий `check_setpoint_feedback_01.py` подтвердил сохранение старой
программы/таблиц. Затем старый `review_fatek_process_map_01.py` остановился
на `MOV anchor mismatch: 65.T006 | P1_FREQ_VALUE`.

Cloud воспроизвёл этот отказ и на04, и на05. Старый анализатор рассчитан
на исходник02/карту31: частоты D200/D203/D206/D209, одиночные чтения,
версия31 и отсутствие штатного чтения тока. В04/05 — карта32, семисловная
телеметрия и частоты R2803/R2811/R2819/R2827 → R2500..R2503. Поэтому
исправлять PLC05 под старые ожидания или отключать guard нельзя.

Добавлен отдельный read-only `tools/review_fatek_map32.py`:

```text
python tools/review_fatek_map32.py artifacts/station-setpoint-feedback-01/station_MC_CM55_900G_05.pdw --out map32-review.json
```

Он принимает только точные проверенные SHA исходника04/восстановленного05,
проверяет контрольные суммы, MOV версии32, четыре источника частоты и
четыре семисловных чтения R5000. Выдаёт инвентарь девяти таблиц. Отчёт
запрещено направлять во входной PDW, включая hardlink/symlink. Произвольно
изменённые кандидаты требуют нового разбора, не добавления SHA в allowlist.
Для запуска не нужны vendor DLL, pefile/unicorn или Windows GUI.

Проверки `python tools/validate_fatek_map32_review.py` прошли:04/05,
правильность старого анализатора на02, отказ от другой версии/повреждений,
standalone CLI в isolated Python и сохранность входа/его двух видов alias.
Валидатор включён в общий runner; полный runner в этом проходе не повторяли.
На реальном сохранённом05 подтверждены1841 сеть/9 таблиц/четыре чтения.
Native F8, HMI-компиляция и унификация2/3/4 этим не выполнялись.

Продолжение локального задания: база05 восстановлена; перейти к реализации
конфигурации в отдельных копиях, сохранив график и прочие открытые проекты.
Получение нового helper не является обязательной зависимостью: точный SHA
и уже пройденный строгий comparator подтверждают восстановление базы.
При недоступном fetch использовать доступные исходники и нативный редактор,
фиксируя отдельно результаты/ограничения. Отказ доступа не обходить.

Последняя строка `Bad Request` на снимке получена при вызове терминального
инструмента. Она не является результатом проверки ПЛК. Статус/восстановление
локального инструмента cloud этим разбором не проверял.

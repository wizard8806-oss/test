# Код аварии ПЧ читается, но не выведен на HMI

## Уточнение: пользователь сообщил A52

Пользователь назвал код на самом ПЧ «А52». Повторно получено ранее выбранное
руководство900G/900M ver1.26, SHA256
`84957452679700c5b34ba1025b522df333f054b7e005fdc396a3c3137f679da1`.
НаPDFстр58 прямо указано **Err52 (A52) — «Ошибка нехватки воды»**.
Источник: https://m-driver.by/wp-content/uploads/2025/11/Manual-M-driver-900G_900M.pdf#page=58
Это текст из используемого руководства900G/900M, а не отдельно найденный
паспорт конкретной прошивки ASDA AC900. Сырое значение0x1001/R2801 на
данном шкафу ещё не снято; числовое значение52 пока не подтверждено.
Целевое сообщение после проверки данных: «ПЧ1: A52 — нехватка воды».
Это собственная защита ПЧ, отдельно от дискретной готовности и реле уровня.
Параметры защиты/перезапуска не менялись. Для чтения raw слова добавлено
поле в отдельную диагностическую HMI-копию, см. animation-probe-r13 report.

`a3990e9f37561529aa01128f7536f02a7c4b5fa9`. Анализ сохранённых файлов,

Пользователь сообщил: при запуске AUTO намеренно получил ошибку на ПЧ;
в журнале только «ПЧ1 нет готовности/питания», номера/расшифровки ошибки

пока нет. Конечное «7» в вопросе не является надёжным сообщением fault7.
Диагностика анимации локальным продолжается; этот вопрос её не заменяет.

## Что проверено

PLC: `station_3p_24MC_cascade_r10_candidate.pdw`,187549байт,
SHA256 `b5de31e3fddd45041c8f11b97be94eb55cf13f7aad7b63f3467707227c192a8b`.
Декодирована инициализация10.N3... рабочей RAM-таблицы R2900: header
0xa550/0x070e,14строк. Это фактическая таблица для FUN150 в этом кандидате;
оставшийся ROM-шаблон R5000/18строк не подменяет её при анализе.

| ПЧ | Строка RAM, с0 | Начальный PDU / WORD | Приёмный блок | Код0x1001 |
|---|---|---|---|---|
| 1 | 0 | 0x1000 /7 | R2800..2806 | R2801 |
| 2 | 3 | 0x1000 /7 | R2808..2814 | R2809 |
| 3 | 13 | 0x1000 /7 | R2816..2822 | R2817 |

Следовательно, при успешном ответе нужной строки код уже приходит вместе
с состоянием, частотой и током. Это настройка/путь данных в файле, а не
живое подтверждение конкретного ответа сейчас. Ссылка U0-01/0x1001 взята
из ранее проверенного руководства900G/900M; расшифровку применительно к
ASDA AC900 и фактическому коду надо сверить, не выдумывать соответствия.

Поиск адресных WORD-операндов R2801/R2809/R2817 во всех комментированных
сетях кандидата не нашёл прямых потребителей. Это ограниченный статический
поиск, не доказательство отсутствия любого косвенного доступа. В собственных
источниках HMI отсутствуют входы/декодер native fault; точные QString
привязки R2801/R2809/R2817 в HMIr10 отсутствуют. HMIr10:
`pump_station_3p_cascade_r10_candidate.skm`,SHA256
`e7752b52bfbbc9e74f04391aa0aa9ffc09e9437cc189d55632a41401495c76f4`.

Сети95.A010/011/012 HMI_ALARM_VFDn_NOT_READY формируют общую неготовность
по дискретным X1/X2/X3 (с boot-условием). Это сообщение не является номером
ошибки из Modbus и не различает все причины снятия готовности.

Старые profile-map31/review/telemetry-plan описывали прежний однорегистровый
опрос частоты. Их формулировка «normal poll не читает0x1001» не относится
к нынешнему семисловному опросу r10. Сейчас пробел находится после чтения:
нет законченной публикации достоверного per-drive кода и его отображения.

## Следующая доработка после локализации анимации

Довести по каждому из трёх ПЧ raw fault и качество/свежесть успешной выборки
до HMI; показать номер ПЧ, код и подтверждённую расшифровку. Получать код
также при снятом READY, если Modbus продолжает отвечать. Не выводить
«нет аварии»/код0 по тайм-ауту или пустому начальному буферу; неизвестный
код сохранять числом, качество отличать от отсутствия записи в словаре.
Общую дискретную неготовность и ошибку связи оставить самостоятельными
признаками. Новые экспорты/ячейки выделять только после проверки текущей
памяти и native переменных, не пересекать countdown/каскад и не ломать
существующие map32/diag27110. Способ отображения значения в журнале
подтвердить штатными возможностями SKTool, включая состояние при потере
связи. Аварийные команды/сбросы этой доработкой автоматически не выдавать.

Код PLC/HMI пока не менялся, новые адреса не назначались; runtime вывод
native fault ещё не реализован. Текущий принятый локальным native r12
зафиксирован отдельно в `station002-alarm-native-r12-acceptance-status.md`:
1280596байт,SHA256

Native state1/2/3 и ненулевой Q не являются самостоятельным доказательством
реального вращения. В подписях различать команду RUN, свежую измеренную
частоту и физическую обратную связь. Параметры режима остаются под управлением
прежнего физического селектора; в R2300 не писать.

Для runtime допустим существующий корректный uint32 item, если доказаны
порядок слов/целостность и scale. Не заменять его парой ради CSV. При паре
word чтение согласованное, low +65536×high вычислять без signed overflow.
Проверить переход65535→65536мин и4294967295мин. Потеря Q4 не скрывает свежую
наработку4; потеря PLC freshness скрывает её. Сброс счётчиков не вводить.

## Свежесть функций и разные каналы

Для F/Q требуется свой accepted snapshot: Q0unknown; Q1 только F0;
Q2 ненулевая частота в исходном PLC-диапазоне1..5990raw. Не подменять
нет данных нулём и не сбрасывать остальные насосы при unknown одного.
Новый ток дополнительно требует GOOD I/Q/marker/newheartbeat. raw0валиден,
raw65535 означает6553.5А, без придуманного sentinel. Наличие маркера без
движения нового heartbeat не подтверждает работу нового экспорта после отката.
Отсутствие current-feature скрывает только I, не всю старую индикацию F/Q.

Countdown читает R3120..3125 согласованно. Только action1/2, физический
номер1..4, остаток>0 и≤preset, AUTO и свежая функция. Нет ожидания/STOP/
MANUAL/ошибка данных — скрыт. R2508 не подтверждает R3125 после откатаr3→r2.
SCADA не считает секунды по собственному таймеру и не выбирает номер по
ступени. При редком опросе показывать именно последнее PLC-значение с
возрастом данных, не имитировать точность1с.

R2132 в r3 отражает elapsed выбранной ступени, включая новые выдержки
до3600с. Если в actual SCADA есть старый прогресс/расчёт R2123−R2132,
его сверить: общий R2123 больше не preset для всех ступеней. Новую индикацию
остатка брать из R3123 вместе с action/target/preset, не из этой разности.
R2133 остаётся elapsed обычного снятия, не готовым remaining.

Период HMI и SCADA через радио различается. Не копировать автоматически
HMI timeout3с в SCADA и не увеличивать лимит ради PASS. Сверить actual
OPC poll/таймер/измеренный jitter и прежний station stale15с; зафиксировать
конкретную политику по каждому новому heartbeat. Сам по себе OPC GOOD,
timestamp чтения или зелёный модем не доказывает продвижение PLC.

## Команды и настройки

В word-профиле CSV **единственная описанная RW-привязка — прежняя
PressureSP_Command/R2100**. Новые параметры/ручные задания здесь указаны
как read-only наблюдение. Это не изменение существующей whitelist команд
actual SCADA. **Уточнение28.11:** пользователь согласовал следующую доработку
— [адресный сброс аварии ПЧ из HMI и SCADA без остановки остальных насосов](../tasks/oshsky-scada-selective-vfd-reset-20261128.md).
В существующем проверенном OPC90 этого канала ещё нет. Его протокол и
приёмку оформить отдельно; Пуск/Стоп и другие новые RW пока обсуждаются.

Существующий путь уставки сохранить: владелец client/user, неизменность
базы/контекста, единственное Apply, no retries/replay, echoR2100+R2360 при
новом counter, затем отдельная обратная связьR2850..2856. OPC write-success
не равен «применено ПЧ». Таймаут/другой оператор/HMI не вызывает перезаписи.
Новые shadows R2887/R2888 и сессию STOP/Edit/Apply нельзя обойти прямой
записью R2884/R2885. Если remote settings/ручные команды уже реализованы,
сверить их actual протокол/guards; не включать недоказанный новый канал.
Fixed-three Бабанов r16/r21c и его reset-протокол в Ошский не переносить.

## Метаданные: воспроизводимый read-only проход

`tools/review_oshsky_scada_r3.py` без аргументов показывает перечисленные
public-source факты. `--bindings <private.json> --report <new-private.json>`
сравнивает **предоставленную** нормализованную word-выгрузку с CSV. Формат:

```json
{"schemaVersion":1,"bindings":[{"logicalId":"current_1","pduAddress":2504,"region":"HOLDING_REGISTERS","deviceType":"uint16","serverType":"uint32","access":"ReadOnly","scadaExternal":true,"decimalOffset":0,"scalingEnabled":false,"useBit":-1}]}
```

Пример частичный: отсутствующие строки будут отмечены. Выгружать из actual
OPC config +Variables.svr, приложить локально provenance/хеши/объекты,
не заполнять export функцией expected_bindings и не считать этот PASS
доказательством live quality, fresh gating, адреса правильного шкафа или
native-архива. Существующая эквивалентная DWORD/runtime binding требует
отдельной проверки: word-checker сам её не разворачивает/не подтверждает.
Ошибка mismatch не является командой автоматически переписать рабочий тег.
Публичный отчёт не выводит private имена/endpoint/учётные данные.

# «Ошский» r3 — независимые выдержки и отсчёт ПЛК

25.11.2026. Новая offline-функция после native PLC r2 / HMI r2b.
Пользователь согласовал расположение и поручил начать. Новых отдельных
**задержек остановки** пока не вводим: вопрос об их необходимости не отвечен.
Существующая выдержка остановки отображается. Шкаф уже отгружен;
настройки/загрузка оборудования этим заданием не поручены.

## Порядок подключения

Ступень — количество работающих, а не физический номер. D903/D906 — число
ведомых, D904 — выбранный следующий насос после штатного отбора по R480..483,
D909 — последний подключённый, выбранный из стека D900..902.
Отбор/ротация, команды RUN, защиты и последовательность Modbus сохраняются.

| Выход на количество насосов | Preset, секунды | Shadow | Elapsed, секунды |
|---|---|---|---|
| 2 | прежний R2123, 1..600 | прежний R2163 | прежний D910 |
| 3 | новый R2884, 1..3600 | R2887 | R2896 |
| 4 | новый R2885, 1..3600 | R2888 | R2897 |
| Снятие ведомого | прежний R2124, 1..1800 | прежний R2164 | прежний D911 |

Задержки независимы, равные/уменьшающиеся допустимы. При первом boot новой
версии R2884/R2885 наследуют валидный R2123; если он невалиден — 10с,
прежний исходный default. Не выбирать новые 30/60с без задания пользователя.
R2886=27402 отмечает однократную инициализацию, последующие настройки
сохраняются. Он не заменяет проверку свежести функции на панели.

Новые значения участвуют в прежнем STOP/Edit/Apply атомарно через M1467,
M1469 и M1471. Cancel/невалидный ввод/нет сессии/не STOP не изменяют active.
В idle оба shadow отражают active. Нельзя давать оператору прямую запись active.

Отсчёт не наследует время другой ступени/кандидата. Потеря спроса/разрешения,
изменение настроек или цели сбрасывают соответствующее ожидание. При смене
цели снятия заново сбрасываются D911 и его clock-arm. Сами условия, preset и
сети обычного снятия сохранены. Аварийный останов не ждёт этой индикации.
Прежняя синхронизация секундных TU-контактов M1780 сохранена: отображается
остаток PLC-счётчика, не новый точный настенный таймер HMI.

R2898/R2899 — выбранные preset/elapsed. R2132 теперь отражает выбранный
счётчик пуска, как прежде отражал общий. Адрес не меняется. R2889..2895,
R2900..2903 — служебные snapshots/validation/one/target/active, HMI их не пишет.
Вместе с двумя счётчиками весь новый диапазон R2884..2903 занят этой функцией.

## Read-only экспорт и свежесть

Один **Batch16 R3120, Bytes12**, без write-операций:

| Регистр / индекс | Значение |
|---|---|
| R3120 / 0 | capability 27402 |
| R3121 / 1 | 0 нет ожидания; 1 пуск; 2 обычное снятие |
| R3122 / 2 | реальный физический насос 1..4, иначе0 |
| R3123 / 3 | оставшиеся секунды, только >0 при ожидании |
| R3124 / 4 | выбранная выдержка, для проверки границ |
| R3125 / 5 | новое зеркало R2840 PLC_ALIVE_COUNTER |

Экспорт формируется после счётчиков и commit: на импульсе пуска/снятия уже
action0/target0/seconds0. При отсутствии активного ожидания поля0; capability
и heartbeat продолжают обновляться. Выбор физического номера не делает HMI.

Нужны успешный свежий batch, прежние PLC-link/Map32/контракт R2329=27110,
существующий physical AUTO gate и **наблюдённое изменение нового R3125**.
Неподвижный новый heartbeat ≥3с скрывает надпись. R2508 старой r2 продолжает
двигаться после отката: он не подтверждает эту новую функцию. Retained
маркер тоже недостаточен. После reconnect сначала повторить handshake.
65535→0 heartbeat валиден. Отрицательные/нулевые/выходящие за preset секунды,
номер вне1..4 и неизвестный action не отображать. При старте/инвалидации
выходы и visibility очищаются до возврата из функции.

Готовый read-only C-компонент:
`assets/hmi/oshsky-cascade-r3/cascade_countdown.c`. Он не знает ABI/pVar,
адресов LW/LB, не пишет PLC и не ведёт локальный обратный отсчёт.
Native-адаптер должен выделить свободные LW/LB после аудита actual r2b,
читать generated alias, использовать настоящий RTC и очищать outputs
**до любого раннего return** основного макроса. Нельзя прекращать вызов
адаптера при потере связи, оставляя прежнюю видимость.

У старой программы поля показывают прочерк и недоступны. Остальные настройки
не блокировать только из-за отсутствия r3.

## Проверяемые исходники

PLC builder принимает только exact r2 generated SHA
`aec1a1c053681ea98f0ee26f5064e6a7bd808cc0835759461d1d7b4acdaabbda`
или reviewed native SHA
`ecdc1abc4ea0cf3162a1757c86d0a9b1aa1ca9769f6093d92f874cb38bf9ca4a`.
В облаке проверен generated-вход; native-вход приватный, обязан проверить
локальный. При более свежей копии сохранить её отдельно и сравнить, не
перезаписывать/ослаблять пин. Сборщик сохраняет payload, non-PC records,
9 таблиц и все1837 не затронутых сетей, в том числе повторяющиеся метки.
Новых serial-запросов0. Map32/контракт27110, R2504..2509/R3080,
SCADA-feedback2850..2856, Runtime2200..2207 и Бабанов не переносить/не менять.

Облачный аудит операндов/11BT_M/таблиц — не проверка внешних OPC/HMI. Actual
allocation, native F8, SaveAs/reopen и SKTool Compile/Simulator подтверждает
отдельная локальная проверка. После native Save строгий validator может
отклонить новую mask/StatusPage-cache: сохранить обе версии, разбирать
конкретные изменения отдельно; не нормализовать code/data без доказательств.

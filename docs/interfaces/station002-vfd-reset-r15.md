# Сброс аварии ПЧ и вывод кодов, r15

Подготовлено на последних пользовательских «бабанов байтик.skm/.pdw».
Пользователь 10.11.2026 сообщил, что шкаф отдан, и разрешил сразу добавить
кнопку сброса, включая изменения ПЛК. Это заменяет прежнее откладывание.
Сброс на оборудовании не выполнялся.

Точная карта: `assets/hmi/fault-reset-r15/interface.json`. ПЛК сохраняет
исходный ключ, данные, таблицы и все прежние сети, кроме перечисленных
согласующих контактов Port3 и приёма собственной подтверждённой выборки.
Защиты, RUN, каскад, ручные пуски и счётчик управления R2363 не заменены.

## Операторский результат

На «Аварии» кнопка «Коды ПЧ» открывает Screen15. Для каждого ПЧ показаны
текущий код, свежесть данных, последний ненулевой код, счётчик выборок и
отдельная кнопка «Сброс ПЧ N». Результат: «Выполняется», «Сброс подтверждён»,
«Переведите в СТОП» либо «Не подтверждено». Последний вариант включает
сохранившуюся причину аварии и отсутствие подтверждения обмена.

Сброс подтверждается только после успешных FC06 и FC03 с правильными
адресом ПЧ/функцией/WR0 и свежим нулём fault-регистра. Подтверждение доставки
FC06 само по себе успехом не считается. При оставшейся A52 панель продолжит
показывать 52. Сброс не подаёт RUN и не устраняет физическую причину аварии.

В существующий Alarm Login добавлены сообщения для кодов 1..80 всех трёх
ПЧ, включая 37 описаний из справочного каталога. Подтверждено на стенде
только соответствие физической A52 ПЧ2 числу52/R2809; остальные описания
имеют статус reference. Неизвестные значения 1..80 записываются числом с
«Расшифровки нет». Для значений >80 журнал содержит общий неизвестный код,
а точное число видно в текущем/последнем коде Screen15; сохранение каждого
такого числа в исторической строке здесь не реализовано.

С r15d используется семь групп: исходные события станции, по одной группе
80 последовательных битов для кодов каждого ПЧ и по одной группе для
неизвестного кода каждого ПЧ. Маски остаются R3056..3060, R3061..3065,
R3066..3070, неизвестные — R3071..3073. Справка SKTool ограничивает SK-серию
десятью группами цифровых аварий; прежние 13 групп r15c превышали этот
предел. Объединение сохраняет все 268 привязок битов и сообщения. Это
устранение превышения документированной ёмкости, а не уже подтверждённое
открытие новой r15d в SKTool 7.1.

С r15e исправлена также нумерация определений: ID0..6 согласованы с
именами B00..B06. Ранее сборщик копировал ID0 исходной группы во все
добавленные группы. В двух нативных образцах SKTool7.1 (LB1 и R3056/80)
номера исходной/новой групп равны 0/1; поле номера отделено от периода
сканирования и типа. В полной r15d правка занимает ровно шесть байтов,
остальной файл сохраняется. Нативное открытие и Compile r15e ещё нужны.

Старый объект HAD1794244624 сохранён побайтно. В его счётчике отображается
R3077: прежние общие сигналы плюс нативные коды. Общий READY и конкретный
код одного ПЧ могут давать две отдельные записи. R2363 остаётся контрольным
счётчиком программы. Screen16 восстанавливает просмотр уже существующего
локального журнала пяти запусков ПЛК, не меняя его формат хранения.

## Условия и обмен

Разрешение: ModeSTOP, исправный селектор, подтверждённый T51 останов,
X8/X9 сняты, Y1..Y4 выключены; у выбранного ПЧ свежая выборка, частота0 и
ненулевой fault. READY не требуется. Единственный владелец Port3 отправляет
FC06 PDU0x2000=7, затем FC03 PDU0x1000/7WORD. В FUN150 ссылки **8193/4097**,
поскольку они однобазные. Port2 звукового CL50 не меняется.

Очередь ждёт завершения старых Port3 работников. На владении новые старые
задания не стартуют; ACT старых работников вручную не сбрасывается. Общий
тайм-аут5с, при выходе из СТОП/ошибке/тайм-ауте — abort своего активного
FUN150, затем освобождение только после снятия собственных ACT. Нет
автоматического второго сброса. Для новой попытки требуется новое нажатие.

D4044 только читается. При highbyte56h и bit3=1 Port3 работает непрерывно:
сервис отклоняет запрос, не перенастраивает системный режим. Предикат
FUN18 AND проверен для всех65536 значений D4044.

## Защита от старого запроса

R3216..3221 — один Batch16 W из шести WORD: mask1/2/4, seq, session,
~session, window, ~window. Одна последовательность потребляется один раз.
Новая сессия при запуске ПЛК, окно2с с допуском предыдущего, ненулевая seq;
неправильная сессия игнорируется, просроченное окно отклоняется. Счётчик
сессии R2857..2859 должен входить в нативно проверенную сохраняемую память.

C макрос ждёт продвижения окна после подключения/смены сессии. Startup
очищает местные LB-кнопки. До ACK повторяется **тот же замороженный кадр**,
без освежения nonce; это доставка кадра с PLC-дедупликацией, не новый
сброс. Через3с либо при потере связи/версии/сессии pending отменяется, без
автоматического повторного запроса. На потерянном/застывшем окне кнопка
не создаёт команду. ПЛК остаётся окончательным арбитром разрешения.

Все R-входы C — Batch16. Новые входы80/64байта, W-кадр12байт; BootAck
scalar W R2553 последний, перед ним216байт, кратно4. Исправленная r14b
анимация и probe27124 сохранены. Нельзя возвращать scalar R или вручную
подгонять pVar. Заголовок, сгенерированный настоящим SKTool, ещё нужен для
проверки ABI; host IN этого не доказывает.

Нативные alarm-биты переживают потерю свежести, пока не получен новый ноль.
C сохраняет маску аварии при потере профиля/связи; новое ненулевое событие
после mute снова включает звук, даже если поменялся только код того же
ПЧ. Застывшая fault-выборка через6с помечается устаревшей.

## Проверки и ограничения

132 новые сети прошли изолированный конвертер узлов исходной Prolad18.dll;
10 изменённых старых FUN150-сетей имеют прежнее ограничение этого API,
одинаковое до/после, и не объявлены прошедшими. 43 сценария исполняют новые
байткоды с моделью асинхронного FUN150; она не моделирует настоящий порт.
64 C89 differential cases/576ticks сохраняют старые выходы, 21 сценарий
проверяет новый протокол/звук, в том числе совместный C+PLC проход1/2/3.

Строгая пересборка, полная обратная инверсия SKM, сохранение HAD, размеры
800x480 и оба списка макропеременных проверены. CPU: добавлено3054байта,
остаток664байта. Нужны F7/F8/память/retain, Compile/generated aliases,
симуляторы и позже аппаратная приёмка. Поведение/скорость реальной линии,
сброс конкретной модели ПЧ и отсутствие повторного пуска физически ещё
не проверены. Готовые файлы считаются кандидатами до этих проверок.

Screen14 перепривязан на локальную копию оригинального AUTOMATIKA KG JPG.
Исходный рисунок не перерисовывается. Облачный helper не встраивает JPG и
не угадывает SysParame: native HMI Start Setting loading/saver остаётся
завершить локально. Наличие пути не означает работающую заставку.

# Постоянный запуск радиодиагностики

Пользователь спросил, потребуется ли каждый раз вручную запускать PowerShell
или опрос будет встроен в скрипт SCADA. Текущий успешный сборщик02 —
foreground-пилот одной станции. Автозапуск и сохранение ключей ещё не настроены.

Предлагаемая конечная схема: одна фоновая служба на диспетчерском Windows-ПК,
автоматически запускаемая при включении ПК. Нативные скрипты Simple-Scada
читают результаты, проверяют состояние/возраст и показывают их. Перезапуск
клиента/редактора SCADA не должен останавливать радиосборщик.

Опрос давления, состояния ПЛК, ПЧ и штатные команды сохраняются в существующей
цепочке MasterOPC → Main → ПЛК. Фоновая служба использует отдельный служебный
канал M2M24 для параметров модема. Это разделение не даёт радиосборщику
полномочий управлять насосами или занимать локальный Main50008.

## Требования к постоянной реализации

- Одна служба для всех станций. Одна облачная сессия на группу; ответы
  маршрутизируются по deviceID/IMEI в постоянный stationID. Нельзя запускать
  копию нынешнего синхронного пилота в отдельном процессе на каждый объект.
- У станций свои очереди, периоды, пределы ожидания и состояния. Недоступный
  модем не блокирует остальные. Ограничения параллелизма проверяются на
  сервере и реальном канале, а не выводятся из одного успешного стенда.
- Общий транспорт обслуживает входящие кадры независимо от одного ожидаемого
  ответа. Успех одного IMEI не обновляет возраст другого. Групповой обрыв
  инвалидирует данные затронутых станций.
- Обычные временные обрывы получают ограниченный повтор с задержкой.
  CLOUD_SESSION_REPLACED отдельно останавливает конкуренцию за сессию и
  отображается оператору: бесконечный перезапуск такой сессии запрещён.
- Ключ группы и пароли модемов вводятся локально при настройке. Для фонового
  режима потребуется защищённое хранилище Windows с доступом служебной
  учётной записи. Конкретная схема DPAPI/учётной записи ещё не реализована;
  текущий сборщик хранит ключи только в памяти. Паролей в JSON, командах
  запуска, журналах и диагностических файлах быть не должно.
- Сохраняется контракт ARADIO1 с отдельными run/seq/published/sample/state
  для каждого объекта и атомарной публикацией файла. Нынешний Station50008
  остаётся совместимым путём стенда; TCP-порт не становится ID станции.
- Остановленная служба, отсутствие нового результата и ошибка опроса
  скрывают устаревшие числа в SCADA. Рабочие данные ПЛК и радиодиагностика
  оцениваются раздельно.
- Синхронный сетевой опрос с ожиданиями не переносится в таймер SCADA.
  Настоящая Windows-служба требует совместимого с Service Control Manager
  хоста. Команда sc.exe create с обычным powershell.exe -File сама по себе
  такой хост не создаёт.

## Переход со стенда

Сначала сохранить текущий работающий источник и закончить приоритетные
показатели давления/ПЧ. Затем подготовить исполняемый хост, общее расписание,
защищённое хранилище и обратимую установку службы. При переключении останавливать
пилот только после подготовки нового пакета; два писателя radio.txt недопустимы.

Для приёмки нужны включение/перезагрузка ПК без интерактивного ввода,
перезапуск SCADA, восстановление обычного сетевого обрыва, отсутствие модема,
отказ одной из двух станций при продолжающемся опросе второй и сохранение
штатного Main-опроса. Пока эти проверки не пройдены, автоматический городской
режим не считать внедрённым. Пользователю сейчас нужно оставить открытым
единственное окно рабочего пилота; на новые станции окна не размножать.

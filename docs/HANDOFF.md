# Передача контекста — 31.10.2026

## Архитектура и текущее состояние

Общий проект для многих насосных станций города. Приоритет: давление,
ошибки ПЧ **900G**, фактические частота и ток, затем управление.
CL50S остаётся особенностью стенда.

`Simple-Scada 2.6.15 → OPC DA MasterOPC 5.0.44 → Gateway/Main 50008 → TELEOFIS → RS485 → FATEK`.
MasterOPC — единственный владелец основного канала, RTU-over-TCP **без MBAP**.
Привязка SCADA: `localhost`, `InSAT.ModbusOPCServer.DA`, `codex.Device1`.
ПЛК стенда FBs-32MCR2-AC + CM55/CB5, четыре адреса приводов 900G.

Радиодиагностика независима: `сборщик PowerShell/.NET → hub.m2m24.ru:7000 →
ServiceDiag 9336 → служебный канал модема`. Main-группа 7058 не заменяет 9336.
На ноутбуке USB отключён, конфигуратор закрыт. Ключ группы — не её числовой ID;
второй секрет — пароль настроек модема. Оба вводятся локально и не сохраняются.
При вытеснении облачной сессии сборщик останавливается (`CLOUD_SESSION_REPLACED`).

Windows-копия **не синхронизирована с Git**. Последний подтверждённый интерфейс
на ноутбуке — `codex_diag_06`; режим отображается, пользователь сообщил «работает».
Все положения селектора отдельно не засняты. Рабочая карта ПЛК — 32,
полученный исходник — `source/plc/station_MC_CM55_900G_04.pdw`.
Файл 05 — кандидат для обратной связи уставки: он получен обратно и совпал
с генерацией, но отдельного подтверждения F8, загрузки и живых семи тегов нет.
Не переносите «работает» для интерфейса на этот ещё не подтверждённый этап.
Облачная Linux-среда Codex уже используется; в ней нет работающей SCADA/ПЛК.

## Что подтверждено

- Карта 32, базовые теги 7/7 и теги ПЧ 3/3; на остановленном стенде
  частота 0.0 Гц, ток 0.0 А, собственный код ПЧ 0, уставка 3.50 бар.
  Калибратор не подключён: недостоверное давление не заменяется числом ноль.
- Общий счётчик ПЛК `R2840` (`PlcAliveCounter`) — M1922 → FUN15P, 16 бит,
  один импульс в секунду. Первое изменение подтверждает маршрут; 15 с без
  изменения скрывают процессные данные даже при OPC GOOD. Остановка/восстановление
  проверены на ноутбуке. Радиоблок при этом остаётся независимым.
- TELEOFIS через ServiceDiag: сигнал 26–27 по собственной шкале, 4G, около 11.7 В.
  Просроченный/остановленный сборщик скрывает только радиоданные.
- Режим `R2300/StationMode`: 0 СТОП; 10–12 АВТО; 20–22 РУЧНОЙ; 90 ошибка селектора.
  Режим селектора не означает фактическое вращение двигателя.

Ключевые адреса PDU Holding Registers (все текущие теги только чтение):

| Данные | Адрес | Примечание |
|---|---:|---|
| Давление / достоверность | 2302 / 2303 | давление /100 бар; флаг ПЛК не доказывает обрыв 4–20 мА |
| Уставка для отображения | 2360 | зеркало R2100, /100 бар |
| Частота / её состояние | 2500 / 2510 | частота ×0.1 Гц |
| Состояние / ошибка / ток 900G | 2800 / 2801 / 2806 | ток ×0.1 А; AlarmLo/Hi не код ПЧ |
| Режим / живой счётчик / версия | 2300 / 2840 / 2554 | ожидаемая версия 32 |

Источники ПЛК 02, 03, 04 и seed SCADA закреплены хешами в `source/resources.json`.
`artifacts/**/scripts` — исходники; последний процессный модуль находится в
`station-mode-display-01`, радиомодуль — в `teleofis-radio-display-01`.
Полная история и границы доказательств — в JSON checkpoint и `native-observation*.json`.

## Установка, запуск и проверки

Linux-зависимости и проверка всей цепочки описаны в README. Команда
`python3 tools/run_checks.py` строит пакеты и выполняет тесты в отдельной
временной копии. Python, FPC и PowerShell проверяют логику, сохранение исходников,
копирование и имитаторы протоколов. Реальных сессий M2M24/ПЛК тесты не открывают.
Новые отчёты не перезаписывают сохранённую историю наблюдений.

На Windows остаются запущенными Gateway, MasterOPC и Server/Client SCADA.
Пока радиосборщик запускается вручную и его окно требуется оставить открытым:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File 'C:\ProgramData\Automatika\RadioServicePilot01\Run-Radio-Service-Collector-02.ps1' -StationId 'station-001' -ConfigPath 'C:\ProgramData\Automatika\RadioServicePilot01\stations.json'
```

Он публикует `C:\ProgramData\Automatika\Station50008\radio.txt` и
`radio-service-status.txt`. ARADIO1 хранит источник, run ID, последовательность,
время публикации/выборки, состояние, сигнал, сеть и питание. Возраст выборки
более 15 с или публикации более 20 с скрывает значения.
Установка Windows с нуля ещё требует настройки OPC, проектных переменных и
проверки F9; полной актуальной Windows-копии в репозитории нет.

### Дополнительные проверки

Установите `requirements-dev.txt` в venv. Для `--vendor-pages` отдельно получите
**официальный Editor 2.6.15** и его matching Demo-project, задайте
`CODEX_SCADA_EDITOR` и `CODEX_SCADA_DEMO_PAGES`. Для `--framework48` нужны
`CODEX_FRAMEWORK48_REFS` (mscorlib/System/System.Core/System.Xml из официального
Microsoft.NETFramework.ReferenceAssemblies.net48 1.0.3).
Для исторического полного JVM-сравнения `validate_radio_service_01.py`
нужны JDK и `CODEX_TELEOFIS_PLUGINS` из официального конфигуратора.
Эти сторонние бинарные файлы и лицензии не распространяются в репозитории.
В обычном наборе vendor-loader и Framework проверки явно пропущены.

## Следующие задачи и известные ограничения

1. Уточнить результат нативной F8 файла 05 и, после обновления **только стенда**,
   подтвердить `SpFeedbackVersion=1` и GOOD для семи новых тегов 2850–2856.
   `python3 tools/build_setpoint_feedback_pdw_01.py` воспроизводит кандидат:
   SHA256 `6aba2a67d07596e4a479c462412859565186de86b410a3cd44476a81f20ffe81`.
   Добавлены семь MOV в `95_HMI_STATUS`, сохранены 1834 старых сети и девять таблиц.
2. Реализовать изменение уставки через **R2100**, не R2360. Контракт ПЛК:
   0.10–11.90 бар, шаг 0.10. Разделять приём ПЛК и подтверждение приводом.
   D672/D673 — кэш ведущего привода/уставки, достоверен только при M969;
   M968 — ошибка применения, D676/D677 — её детали. WM968 в R2856:
   bit0=M968, bit1=M969; оба установлены — недопустимо. Это не атомарный снимок
   и не подтверждение с request ID. Кнопка/запись/журнал уставки ещё не реализованы.
3. Затем согласовать командные контракты пуска/стопа и сброса аварии.
   Самостоятельного универсального протокола команд пока нет. Сброс 900G
   может восстановить работу при удерживаемом RUN; при установке ничего не писать.
   Выбор разрешённых насосов опционален. R2553 занят, не использовать как свободный.
4. Заменить ручной радиосборщик одной фоновой службой Windows с автозапуском,
   защищённым хранением секретов и очередью опроса станций одной Service-группы.
   Несколько конкурирующих клиентов одной группы недопустимы.
5. Подключать новые станции по профилям (ID, IMEI, OPC prefix, группа, пути,
   модель ПЧ), без копирования логики. `stations.json` уже отделяет привязку,
   но полноценный массовый onboarding и универсальные SCADA-карточки ещё не сделаны.

Полевой шкаф в АВТО не менялся. Облачная сборка не разрешает считать его
проверенным. Исходный старый MBP не сохранён как действующая конфигурация:
он устарел и может содержать настройки доступа; оставлен разбор тегов без параметров доступа.

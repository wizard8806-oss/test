runID, последовательность, время публикации/выборки, состояние, сигнал, сеть,
питание. Отдельный `radio-service-status.txt` содержит UTC/SOURCE/STATION/GROUP/
IMEI/STATUS; при успешном удалённом опросе были SOURCE=SERVICE,GROUP=9336,STATUS=OK.
`collector.lock` защищает каталог от второго писателя, но для Service-группы
всё равно нужен один владелец сессии. Остановка — Ctrl+C в окне сборщика;
предусмотрен и файл `radio.stop`. При CLOUD_SESSION_REPLACED02 публикует отказ
и останавливается, не вступая в цикл взаимного вытеснения. Закрытие окна
останавливает сборщик; перезапуск Client SCADA сам по себе его не запускает.

При инвентаризации CLI сверить код/выбранные поля конфигурации, свежесть UTC
и STATUS, путь чтения из SCADA. Не собирать дамп памяти/всей конфигурации и
не запускать заново ради повторного подтверждения первого успеха. Полный
план интеграции — `docs/radio-runtime-integration-2026-10-30.md`: одна служба
Windows и общая очередь, одна сессия на группу, отдельные состояния станций.
Текущий пилот выбирает одну станцию, не является городским планировщиком.
Не переносить блокирующий сетевой опрос в таймер SCADA и не создавать окно
PowerShell на каждую станцию. Простое `sc.exe create` с powershell.exe ещё
не даёт совместимого со SCM хоста службы. Защищённое хранение ключей/автозапуск
пока не реализованы. Это следующая разработка, не уже установленная функция.

Остальные задачи: контракты пуска/стопа и сброса; выбор насосов опционален.

## Обновление ноутбука с сохранением локальных изменений

Рекомендуется **новый git worktree** рядом с текущим репозиторием. Он получает
опубликованный проект, сохраняя существующую ветку, индекс и все изменённые,
неотслеживаемые и игнорируемые файлы в прежней папке. Локальные правки сами
в новый worktree не переходят: CLI сначала сравнивает и переносит только выбранные
исходники. Рабочая SCADA09 остаётся отдельно и этими командами не обновляется.

В PowerShell из **локального Git-репозитория**, не из папки SCADA:

```powershell
git status --short --branch
git branch --show-current
git log -1 --oneline

$repoRoot = git rev-parse --show-toplevel
if ($LASTEXITCODE -ne 0) { throw 'Open the local Git repository first.' }
$repoRoot = $repoRoot.Trim()
$handoffStamp = Get-Date -Format 'yyyyMMdd-HHmmss'
$continuePath = Join-Path (Split-Path $repoRoot -Parent) ('test-codex-' + $handoffStamp)
$continueBranch = 'codex/laptop-' + $handoffStamp

git fetch --no-tags origin
if ($LASTEXITCODE -ne 0) { throw 'Fetch failed; existing files preserved.' }
git worktree add -b $continueBranch $continuePath origin/codex/project-handoff-2026-10-31
if ($LASTEXITCODE -ne 0) { throw 'Worktree not created; inspect the error.' }
Set-Location -LiteralPath $continuePath
git status --short --branch
git log -1 --oneline
```

Проверить, что origin относится к `wizard8806-oss/test`; токены в URL/команды
не вставлять. Проверенная базовая версия этой редакции —232bf5f; после
публикаций ветка продвигается. Эти команды не выполняют pull/merge/rebase/stash
или замену файлов старой папки и не меняют main. Не применять `reset --hard`,
`clean` или принудительное переключение для обновления.

Если Git-репозитория ещё нет, клонировать в **новую пустую папку**:

```powershell
git clone --branch codex/project-handoff-2026-10-31 --single-branch https://github.com/wizard8806-oss/test.git test-codex
```

**HANDOFF передаётся через Git вместе с согласованными изменениями.** Агент
сам публикует подготовленные документы, проверяет удалённый SHA и сообщает
его принимающему сеансу. Локальный CLI обновляет свою копию с сохранением
изменений и читает HANDOFF из полученного коммита; ручное копирование файла
пользователем больше не является порядком передачи.
Локальные исходники объединять выборочно; секреты, профили доступа, лицензии,
рабочую SCADA,PLC/HMI и результаты сборки автоматически не копировать в Git.
Установленные `RadioServicePilot01\*.ps1`, `stations.json` и результаты
`Station50008\radio*` тоже не синхронизируются fetch/clone. CLI должен учесть
их отдельно и сохранить текущий работающий PowerShell-процесс.

## Сравнение и рекомендации

| Область | Что уже есть в HMI r3 | Целевое улучшение SCADA |
|---|---|---|
| Главное окно | Давление/уставка/число работающих/задание ведомых;4равные карточки | Те же значения и четыре одинаково полные карточки; рядом возраст данных и актуальная причина проблемы |
| Карточка насоса | Роль, состояние, частота, ток, шкала, наработка | Добавить понятную расшифровку готовности/исключения/блокировки и переход к истории именно этого насоса |
| Ввод и индикация | Прозрачные поля, голубой ввод, белый read-only, серый disabled | Сохранить семантику цвета/одинаковые единицы; редактируемость подтверждается правами и реальными guards, не только цветом |
| Ожидание каскада | Только active/valid, физический номер и остаток янтарные | Та же строка на станции; по нажатию — действующие выдержки2/3/4иобщего снятия, состояние/возраст чтения |
| Прочерки | Новые поля скрыты до fresh contract; старые могут показывать начальные нули | Единый unknown во всех полях и причина: нет связи, устарело, нет данных одного ПЧ, несовместима версия; неизвестность не похожа на измеренный0 |
| Уставка | Локальный ввод под условиями PLC | Ясно отделить черновик от действующего значения, показать этап ожидания/эхоPLC/подтверждениеПЧ и внешнее изменение |
| Ручной режим | Локальные4Пуск/Стоп/частоты и прежние блокировки | Явно показывать режим шкафа и причины запрета; существующее SCADA-управление проверить, новые кнопки не включать простым копированием адресов HMI |

## Главный приоритет: объяснять состояние

Для каждого проблемного показателя нужен понятный ответ «почему». Примеры
целевых формулировок: «Нет данных ПЧ4», «Данные станции устарели»,
«Насос исключён из АВТО», «Ожидается подтверждение новой уставки».
Конкретная причина берётся только из достоверного PLC/OPC-признака; по
нулевой частоте нельзя придумать причину остановки или готовность резерва.
Если причина не подтверждена, так и сообщить.

В краткой строке связи показывать, например, «Данные ПЛК:2с назад» и
независимое состояние радио. В диагностике раскрывать уровни
SCADA→OPC→ПЛК→каждыйПЧ, raw/quality/counter/возраст. Адреса и версии
остаются там; главный экран говорит языком оператора.

Последние события на станции: изменение режима, зафиксированные команды
SCADA, смена ведущего, авария/восстановление. Время и источник достоверны.
Для запроса SCADA можно назвать известного пользователя; внешнее изменение
уставки не приписывать HMI/конкретному человеку без данных. При отсутствии
истории показывать её отсутствие, не создавать демонстрационные события.

## Компоновка станции, предложение без нового native-макета

```text
Штатные вкладки SCADA; выбранная станция сохраняется
Ошский     Режим     Данные ПЛК/возраст     Радио     Активные аварии
Давление        Уставка        В работе        Активный отсчёт
Насос1          Насос2         Насос3          Насос4
Роль / состояние / причина / Гц / А / часы — одинаковые строки
Ведущий / ротация         Последние события / пояснение проблемы
```

Четыре знакомых синих насоса можно сохранить как общий визуальный образ.
Главную иерархию задают крупные цифры и состояния, равные зазоры и общая
линия единиц. Без отдельных цветных подложек у каждой подписи/цифры.
Белые значения читаются, голубой связан с доступным вводом, янтарный —
с ожиданием/предупреждением. Работу/аварию обозначают также текстом, не
только цветом. Это предложение развития, не замена уже согласованных
SCADA runtime tokens или новое утверждение pixel-perfect результата.

Основной график остаётся в согласованном штатном native-viewer; новую
встраиваемую архивную панель ради этой схемы не изобретать. Выбранный насос
может открывать отфильтрованные графики и события со своей карточки.
Новая авария выделяет соответствующую станцию; диспетчер открывает её
памятку по нажатию, сохраняя контекст других станций.

## Порядок работы

1. **Перед выездом26.11:** завершить уже выданный r3 preflight: реальные
  4F/I/runtime, quality/возраст, новая индикация ожидания, отсутствие ложных
  нулей, прежняя уставка/подтверждения. Визуальная идея не задерживает эту
  проверку и не меняет проверенную PLC/HMI-пару.
2. **Следующий проход интерфейса:** одна улучшенная карточка станции,
  единые объяснения состояния, цвета ввода/показа и контекст навигации.
  Сверить actual Client при его DPI/размере и состояния normal/unknown/
  stale/confirmed0/longtext; использовать существующие native-контролы.
3. **Затем:** связать события с native-графиками, сравнение наработки и
  полезные памятки. История/gap/архив требуют подтверждения actual runtime.

Изменение интерфейса не открывает новые remote write-пути, не меняет
ротацию/защиты ПЛК и не сбрасывает историю/часы. Памятка CHINT XJ3-D
подтверждена для Бабанова; для Ошского выбирать памятку по его оборудованию.

В этом сравнении не менялись UI-код/токены, native/оборудование/SCADA/
архивы; не создавались новые screenshots/mockups. Проверены источники и
относительные ссылки. Browser/strict web-audit/native visual matrix здесь
не являются пройденной приёмкой: это документ предложений для desktop UI,
без реализации и без свежего actual SCADA Client. Полный runner ради
аналитического документа повторять не требуется.

# Исправление контекста кнопок — SCADA09

Нативные файлы08 показали сохранные страницы и OnClick-ссылки, все четыре
обработчика и неизменённый модуль. Проверка входа по инструкции не устранила
отсутствие реакции. Экспорт пользователей/ACL не запрашивался.

В08 GetClientName/GetUserName/GetUserID вызываются внутри глобального модуля.
Руководство2.6.15 гарантирует контекст для пользовательских событий; перенос
этого контекста внутрь внешнего модуля нашими предыдущими тестами не проверялся.
Если модуль получает пустого клиента/-1,08 молча прекращает действие и не
может адресовать сообщение клиенту. Это воспроизведено в изолированном тесте;
это ещё не прямое наблюдение значения GetClientName в работающем08.

В09 три значения получаются в каждом OnClick, до входа в модуль, и передаются
параметрами. Модуль больше не вызывает эти функции. Причина отказа остаётся
в строке состояния даже при пустом клиенте или недоставленном всплывающем окне.
Проверка авторизации, владелец черновика, профиль и все проверки команды
остаются. Установка/таймер/восстановление не пишут в ПЛК. Разрешения и логика
ПЛК/HMI не меняются, чтение/запись для всех не включается.

Установщик создаёт `Desktop/codex_diag_09` из рабочей08. Принимается точный
SHA присланных страниц, проверяются исходный модуль и четыре события. Pages,
Variables, Servers, настройки пользователей и другие ресурсы сохраняются;
радиомодуль/таймер копируются побайтно. Исходная08 не изменяется, существующая09
не заменяется. Скомпилированный кеш не переносится — требуется F9/сохранение.

При первой попытке установки09 пользователь получил в Windows PowerShell
«Не удается найти свойство Id». Проверка уникальности использовала
Select-Object -ExpandProperty для ключей Hashtable, что работало в наших PS7
проверках. Она заменена прямыми индексаторами и отдельными словарями.
Ошибка возникла до записи файлов,09 не создана. Добавлен тест старого поведения
проекции ключей, успешная установка с этим ограничением и отказы при дубликатах
ID/имён. Это узкая имитация границы cmdlet, не запуск самого Windows PS5.1.

Длинный повторный ответ с пакетом повредился/превысил лимит вывода. Для
повторения без пересылки Base64 подготовлен `tools/retry_setpoint_click_install.ps1`:
три отдельные части поиска, исправления и запуска. Первые две не выполняют
установщик. Поиск читает только Get-History того же открытого окна, принимает
ровно старый SHA `c0dd106e…239b3dc`, заменяет одну проверку и требует новый SHA
`a176ed6d…658b60d7`. История на диске не читается, команды/секреты не выводятся,
сетевого скачивания нет. При отсутствии/изменении пакета запуск блокируется.
`python3 tools/validate_click_install_retry.py` проверяет восемь случаев
синтетической истории и копирование проверенным установщиком с сохранением08;
реальное повторение на ноутбуке пока не наблюдалось.

После SAVED открыть09 в Editor2.6.15, F9, сохранить, запустить Server/Client
этой копии и войти тем же локальным пользователем. Импорт новых тегов не нужен.
Первый нативный тест только `+` → черновик3.6 и `Отмена` →3.5; верхняя уставка
ПЛК остаётся3.50бар. Применение оператором пока не наблюдалось.
Если изменение не произошло, нужен точный текст под кнопками09; если строка
не меняется вообще — проверять нативную отправку события и эффективные права.

Проверки компилируют настоящий новый модуль и настоящие четыре тела OnClick
как отдельные Pascal-модули. В окружении общего модуля API клиента возвращает
пустую строку/-1, в окружении события — заданного оператора. Старый08 теряет
изменение,09 проходит сценарий. Также повторяются прежние проверки управления,
карточки/свежести и реальные сценарии сохранения/отказа PowerShell/Linux.
Это не нативная Windows F9/диспетчеризация события;09 ещё проверяется на ноутбуке.

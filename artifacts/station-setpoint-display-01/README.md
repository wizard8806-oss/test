# Обратная связь уставки — копия SCADA codex_diag_07

Пользователь подтвердил `SpFeedbackVersion=1` и GOOD для семи новых тегов
в MasterOPC. Эта стадия подключает их к отображению в SCADA; кнопка записи
уставки на этом этапе не добавляется.

`tools/build_setpoint_display_01.py` собирает установщик и полный inline-блок
PowerShell. Он создаёт `Desktop/codex_diag_07` из рабочей `codex_diag_06`.
Исходник, страницы, переменные, OPC-серверы, радиомодуль, таймер и остальные
файлы сохраняются; старые скомпилированные скрипты в копию не переносятся.
Существующий каталог назначения и изменённый исходный модуль не заменяются.
Папку `Projects` можно указать вместо самой `codex_diag_06`.

После сообщения `SAVED:` открыть `Project.spr` новой копии в Editor 2.6.15.
Если семь тегов ещё отсутствуют в переменных SCADA, обновить дерево
`InSAT.ModbusOPCServer.DA → codex → Device1` и импортировать:

`SpFeedbackVersion`, `SpConfirmedDrive`, `SpConfirmed_x100`, `SpApplyPhase`,
`SpApplyError`, `SpApplyDetail`, `SpApplyFlags`.

Повторно создавать их в MasterOPC не требуется. Выполнить F9, сохранить,
запустить Server/Client этой копии вместо прежней. Текущий служебный
радиосборщик остаётся отдельным процессом.

Под большой уставкой ПЛК отображается отдельный статус подтверждения
ведущим ПЧ. На странице диагностики — этап, слово признаков и при активном
M968 числовой код/подробность ошибки применения. Это не код аварии 900G;
существующее поле аварии ПЧ и его приоритет сохраняются.

Для зелёного подтверждения нужны карта 32, изменение общего счётчика,
семь доступных GOOD-тегов правильной привязки, версия 1, M969=1/M968=0,
ведущий ПЧ 1–4, допустимое давление, совпадение с текущей уставкой ПЛК и
нулевой этап координатора. Два полных одинаковых набора, включая текущую
уставку, должны быть получены при разных значениях счётчика ПЛК.
При изменении набора, потере качества, смене уставки, остановке счётчика,
паузе таймера или сбросе контекста прошлое подтверждение скрывается.
Биты M970–M983 не расшифровываются; D676/D677 трактуются как активная ошибка
только при M968. Старый кэш без M969 не выдаётся за применение уставки.

Нулевые начальные значения/отсутствие M969 могут дать «Подтверждение …
не получено» при всех GOOD-тегах — это нормальное различие качества OPC
и результата применения. Установка не отправляет команд ПЛК или ПЧ.
Это индикация текущего состояния координатора, не атомарный снимок и не
подтверждение новой команды по request ID. Будущей записи R2100 нужен
собственный контракт и проверка результата.

Проверки: `tools/validate_setpoint_display_01.py`, также включённые в
изолированный `tools/run_checks.py`. Нативный запуск новой копии/F9 и
снимок результата от пользователя пока ожидаются. HMI SKTool и программа
ПЛК не изменяются этой стадией.

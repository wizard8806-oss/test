# Изменение уставки — копия SCADA codex_diag_08

Рабочая карточка07 подтверждена нативным снимком пользователя: СТОП,
уставка3.50бар, давление недостоверно, частота/ток0, собственный код ПЧ0,
подтверждение уставки ведущим ПЧ не получено. Это не повод повторять
проверку калибратора, режимов или семи уже работающих тегов обратной связи.

Эта стадия добавляет внизу карточки черновик с шагом0.10бар и кнопками
«-», «+», «Применить», «Отмена». Диапазон текущего ПЛК0.10–11.90бар.
Изменения черновика не пишут в ПЛК. Только OnClick «Применить» от клиента
с GetUserID>=0 может один раз присвоить Value отдельного командного тега.
Скрипты установки, таймер, запуск/восстановление проекта записи не выполняют.

## Настройка и запуск

В существующем `codex.Device1` MasterOPC нужен **один новый тег**:

| Свойство | Значение |
|---|---|
| Имя | PressureSP_Command |
| Holding Registers, адрес PDU | 2100 (0x0834) |
| Тип устройства → сервера | uint16 → uint32 |
| Доступ | ReadWrite |
| Масштабирование | выключено |

Семь тегов обратной связи и R2360 остаются ReadOnly. Прямых подключений
к Main50008 нет: запись идёт через тот же MasterOPC. Требуется карта32,
версия обратной связи1 и GOOD необходимых тегов. Значение R2100 перед
отправкой сверяется с зеркалом R2360. В SCADA у командной переменной
DecimalOffset должен быть0, DecimalMultiplier1; иначе запись блокируется.

`tools/build_setpoint_control_01.py` создаёт установщик и inline-пакет.
Они копируют рабочую07 в `Desktop/codex_diag_08`, проверяя исходный модуль
и точный SHA страниц. Изменённые страницы/скрипт не заменяются. Исходный
проект сохраняется; радиомодуль и таймер копируются байт-в-байт.
При ошибке `Station pages differ` нужен фактический Pages.spg рабочей07,
а не ослабление проверки или замена пользовательских экранов.

После SAVED открыть Project.spr копии08 в Editor2.6.15, импортировать
существующий PressureSP_Command в переменные SCADA, проверить нулевое
смещение, F9/сохранение, запустить эту копию вместо07. В клиенте требуется
авторизованный пользователь SCADA (это не ключ группы M2M24/пароль модема).
Первое принятие интерфейса и реальная запись пользователем пока не наблюдались.

## Семантика результата

- Черновик принадлежит паре клиент/пользователь, истекает через60с,
  сбрасывается при потере контекста или изменении уставки другим источником.
  Другой клиент не может применить/отменить этот черновик.
- Перед отправкой повторно проверяются привязка, качество, живой счётчик,
  режим, профиль, неизменность исходной уставки и отсутствие другой записи.
  Та же уставка не отправляется повторно; отмена касается только черновика.
- Приём ПЛК требует двух наблюдений целевого R2100 **и** зеркала R2360
  при разных значениях счётчика после отправки. Затем отдельно ожидается
  уже проверенная обратная связь ведущего ПЧ (M969, допустимые поля, этап0).
- Через20с без эха результат неподтверждён. Через45с после приёма ПЛК без
  подтверждения ПЧ отображается «ПЛК принял; подтверждение ПЧ пока не получено».
  В СТОП это не выдаётся за полное применение приводом.
- Изменение уставки другим источником, ошибки/потеря связи после отправки
  не вызывают повторов. Ошибка после присвоения может быть неоднозначной,
  поэтому результат помечается неподтверждённым. Никаких откатов/пусков нет.
- Журнал фиксирует запрос с клиентом/пользователем, приём ПЛК и итог без
  сообщений на каждом тике. Если запрос нельзя записать в журнал, команды нет.

Это наблюдение результата значения, **не** эксклюзивный request-ID протокол
ПЛК. Другие HMI/операторы могут изменить тот же R2100; код это не перезаписывает.
Локальный номер запроса не является подтверждением ПЛК. Производственная
политика ролей, параллельные клиенты Windows и городская многосайтовая схема
не подтверждены этими тестами. Программа ПЛК и проект SKTool не меняются.

## Проверки

`tools/validate_setpoint_control_01.py` компилирует настоящий модуль Pascal
с имитатором единственного тега записи, проверяет отсутствие автоматических
записей/повторов, диапазон, владельца, качество/масштаб, эхо, подтверждение ПЧ,
таймауты, неоднозначные ошибки и сохранность файлов в реальном PowerShell/Linux.
Прежние проверки карточки/режимов/обратной связи запускаются против нового
модуля. Страницы и четыре OnClick-ссылки дополнительно прочитаны исходным
загрузчиком официального Editor2.6.15 в изолированной x86-среде.
Это не нативная F9 Windows и не реальная операция на стенде.

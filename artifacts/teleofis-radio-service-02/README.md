# Раздельный служебный доступ и один владелец сессии

Актуально 30.10 в 18:46–18:47: удалённый радиоопрос через ServiceDiag9336
подтверждён на ПК пользователя. Нативная SCADA показывает источник
«служебный канал M2M24», сигнал 26, режим 4G, питание 11,812 В и возраст
успешного опроса 3 с. Отдельное чтение radio-service-status.txt подтвердило
SOURCE=SERVICE, GROUP=9336, целевой IMEI и STATUS=OK. Подробности и ограничения:
native-observation-2026-10-30.json. Повторный ввод ключей и пересоздание группы
для подтверждения первого успеха не требуются. Ключи здесь не сохраняются.

ServiceDiag содержит правильную онлайн-запись WRX11x8/«Служебный канал».
Основная запись осталась в Main; служебная исчезла из старой Service.
Start-ServiceDiag-9336.ps1 использует подтверждённый ID и запрашивает локально
ключ группы9336 и пароль настроек модема. Основной Gateway остаётся на7058.
Сборщик работает в открытом окне PowerShell. Свежий основной опрос ПЛК,
длительная устойчивость и общий диспетчер города требуют отдельной проверки
или реализации. Ниже сохранена история подготовки до успешного запуска.

Пользователь подтвердил логин7058/порт7000 рабочего конфигуратора. У MainGateway
и первого сборщика тоже7058. TCP доступен, сборщик получает CLOUD_LIST_TIMEOUT;
конфигуратор получает список и авторизуется в модеме, но сообщает о разрыве
из-за другого клиента. Какая именно сессия вызвала разрыв, не доказано.

Официальная инструкция разделяет основной и служебный каналы и рекомендует
группуService с записями служебного типа:
https://teleofis.ru/faq/gprs-3g-4g-terminaly-teleofis-serii-wrx/udalennyy-dostup/udalennaya-nastroyka-wrx-sluzhebnyy-kanal-m2m24-cloud/

На этапе подготовки требовалась отдельная ServiceDiag для существующей
служебной записи целевого модема. Пользователь затем сообщил ID9336 и
подтвердил правильный тип канала. WRX, ПЛК и канал Main не перенастраивались.
Первый успех после разделения групп и ввода действующего ключа не доказывает
единственную причину всех предшествовавших тайм-аутов.

Прочитан официальный Gateway2.9.1: https://teleofis.ru/php/download.php?f=8085.
SHA256M2M24Gateway.jar15909cdb6b07a032930055fa3edfdf8724f8389a2ed29c4059cba45497922e06.
GroupInfo передаёт login/password; bridge.Server пробрасывает данные TCP,
отдельного API радиопоказателей нет. Dispatcher на внешнюю команду5 останавливает
шлюз и показывает сообщение о другом клиенте. Поэтому после закрытия конфигуратора
проверить запуск Gateway и свежие строки MasterOPC; старые GOOD недостаточны.
Gateway3.0.1 прочитан только для справки; обновление пользователю не требуется.

Set-Service-Group-And-Run-02.ps1 берёт установленный01 с XML-исправлением,
проверяет SHA256 и создаёт отдельный02. C#-транспорт побайтно прежний.
Политика PowerShell теперь превращает внешнюю команду5 при входе и при опросе
в CLOUD_SESSION_REPLACED и останавливается, не выдавая ошибку пароля и не
устраивая цикл взаимного вытеснения. Скрипт просит новый ID, отклоняет7058,
проверяет профиль/блокировку, сохраняет резервную копию конфигурации и меняет
служебную группу. Секреты вводятся локально и в файлы не записываются.

9сценариев настройки и3независимых TCP-loopback сценария прошли на настоящем
PowerShell/Linux. Смена группы в облаке, запуск02 на Windows и первый
удалённый радиоопрос теперь подтверждены нативными наблюдениями. Общий
городской диспетчер с одной сессией на группу и
независимыми очередями пока не реализован; не создавать окно на каждый объект.

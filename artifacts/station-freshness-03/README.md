# Общий контроль обновления ПЛК

На20:20:33 30.10 подтверждены карта32,7/7базовых тегов,3/3новых тегов900G и
продолжающаяся Service-радиодиагностика27/4G/11,683В с возрастом2с.
Общий контроль свежести на том экране ещё не реализован.

Нативный проект дополнения: одна сеть95.A100/PLC_ALIVE_COUNTER в95_HMI_STATUS
перед95.W032/WORD_STATUS_VERSION. Нормально открытый M1922(1с) управляет
FUN15(+1), Pulse включён,32bits выключен,D=R2840. Карта остаётся32;R2328,
все прежние данные и18строк опроса ПЧ сохраняются. В самой SCADA счётчик
не увеличивается. Проект сначала сохранить новой копией_04, выполнить F8
и прислать для сравнения; автоматической загрузки/изменения ПЛК здесь нет.

plc-counter-edit-spec.json содержит ссылки и SHA256 руководств, адреса,
проверку исходника0c2c847b946f17c39290a056518235b2940a5a29dcc8813e3eadc33de6a4f69d,
отсутствие прямых кодовых ссылок наR2840и пересечений с приёмниками9таблиц.
Это не полный анализ косвенного доступа/внешних HMI. Команда15может выдавать
OVF на знаковой границе; дополнительные функциональные выходы оставляются
неподключёнными. Сырые16бит читаются беззнаково и продолжают0…65535→0.

Новая совместимая SCADA-копия05 подготовлена из04. Один дополнительный
ReadOnly-тег PlcAliveCounter/R2840,uint16→uint32,HOLDING_REGISTERS,
без масштабирования. На32 требуется первое изменение после базового
образца. После15с без изменения технологические показания скрываются,
включая старые0А/код0; нули не подставляются. Большой скачок счётчика,
пауза таймера>10с, перевод часов назад или потеря качества сбрасывают
подтверждение. Допустимо беззнаковое переполнение. Для стенда1Гц скачок>60
считается новой базой и требует следующего изменения.

Меняются только исходники StationDiagnostics в новой копии; страницы,
переменные, серверы, таймер и запись радиомодуля сохраняются. Source04 и
сборщикService9336не меняются. Контроль общего маршрута не заменяет
PressureSourceOK, состояние обмена с каждым ПЧ, защиты и подтверждения команд.
Согласованного снимка нескольких OPC-элементов этот пакет не добавляет.

Проверки:59утверждений прежнего отображения31,237утверждений общего счётчика,
тайм-аутов и скрытия/восстановления UI;8сценариев реального PowerShell/Linux
копирования. Эти проверки не заменяют нативную F9/загрузку в ПЛК и тест
останова/возобновления реального ПЛК.

Пакет выдан пользователю. После исправления пути исходного проекта получен
нативный экран Diagnostics с картой32,7/7базовых и3/3тегов ПЧ и зелёной строкой
«Обновление ПЛК подтверждено. Счётчик:6472. Без изменения:3с».
Проверенный скрипт выдаёт эту строку только после первого допустимого изменения
счётчика. Это подтверждение выполнения нового модуля и наблюдаемого изменения
через OPC; отдельного считывания программы ПЛК или команды F9 на снимке нет.
См. native-observation-2026-10-30.json. Радиоблок серый: его последний результат
«Сборщик радиодиагностики остановлен»; отказ модема этим не установлен.
Следующий нативный снимок после задания на стендовый STOP подтвердил красную
строку «Нет изменения общего счётчика ПЛК более15с» при доступных7/7 и3/3
тегах. Подтверждение давления и сырые слова состояния скрыты. Service-радиоблок
остался зелёным:26/4G/11,721В, возраст1с. Это подтверждает независимый опрос
модема при истечении контроля обновления ПЛК. Режим CPU непосредственно на
снимке не показан. Восстановление после RUN и скрытие значений на вкладке
«Станция» на этом снимке не наблюдались.

На последующее задание проверить скрытие показаний и вернуть стендовый ПЛК
в RUN пользователь ответил «работает». Сценарий останова/восстановления принят
по этому подтверждению. Отдельных снимков восстановления и вкладки «Станция»
не предоставлено; точное восстановившееся значение счётчика не известно.
Повторять установку и этот тест не требуется.

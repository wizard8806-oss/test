# Диспетчеризация насосных станций

Исходники и средства подготовки проектов FATEK / Simple-Scada 2.6.15,
профили MasterOPC и независимый служебный опрос TELEOFIS.

Продолжение работы: [передача контекста](docs/HANDOFF.md).
Полный разбор исходных **199 файлов**: [аудит](docs/repository-audit-2026-10-31.json).

Windows-проект на ноутбуке пользователя **отдельный и не синхронизирован**
с этим репозиторием. Файлы здесь не доказывают состояние работающего ПЛК.
Работа в Codex уже идёт в облачной Linux-среде `/workspace/test`.
Проект локальной HMI-панели восстановлен из предоставленной пользователем
копии: [pump_station_4_37.skm](source/hmi/pump_station_4_37.skm), редактор
**SKTool 7.1**, модель проекта **SK-102CE**. Нативная проверка и сверка адресов
с текущим ПЛК пока не подтверждены. См. [описание HMI](source/hmi/README.md).

## Структура

- `source/plc/` — полученные от пользователя проекты 02, 03, 04.
- `source/hmi/` — исходный проект панели SKTool 7.1 и инструкция продолжения.
- `source/scada-seed-2.6.15/` — минимальная исходная заготовка SCADA, без лицензии и скомпилированных скриптов.
- `artifacts/**/scripts/` — **исходные** Pascal-модули SCADA; это не мусор сборки.
- `artifacts/teleofis-radio-service-02/` — текущий исходник сборщика радиодиагностики и привязка ServiceDiag.
- `artifacts/` также содержит профили тегов, контракты, планы и историю проверок.
- `tools/` — сборщики, шаблоны PowerShell, сравнение PDW, проверки без оборудования.
- `docs/` — текущая передача контекста и исторические исследования.

Архивы, установочные inline-пакеты, скомпилированные SCADA-файлы,
кандидат PDW05 и кэш исключены из Git. Они собираются из сохранённых исходников.

## Установка и проверки в Linux / Codex

Нужны Python 3.10+, Free Pascal 3.2.2 и PowerShell 7 для проверок.
В Debian/Ubuntu установите `fp-compiler`, `curl`, `tar`, `libicu-dev` и `libssl3`
средствами пакетов среды, затем:

```bash
bash tools/setup_dev.sh
python3 tools/run_checks.py --report /tmp/station-checks.json
```

Скрипт установки скачивает PowerShell 7.5.4 в игнорируемую `.local-tools/`
и проверяет SHA256 по файлу выпуска. Можно использовать имеющийся `pwsh`.
Для нестандартных путей задайте `CODEX_PWSH`, `CODEX_FPC` и при необходимости
`CODEX_FPC_UNITS` (каталог `units/x86_64-linux`). Секреты для тестов не нужны.
Проверки собирают отдельную временную копию и не меняют исходники/исторические отчёты.
Они работают с имитаторами и loopback, без подключения к M2M24 или ПЛК.

Дополнительные проверки оригинального загрузчика Editor и .NET Framework:
[инструкция](docs/HANDOFF.md#дополнительные-проверки).
Облачные тесты не заменяют F8/F9 и проверку на Windows.

## Подготовка пакетов для Windows

Для новой копии репозитория выполните сборщики в порядке, указанном в
`tools/run_checks.py:BUILDERS`, из корня репозитория, например
`python3 tools/build_station_mode_display_01.py` **после сборщиков предыдущих стадий**.
Они создают `Install-*.ps1` и `Paste-*.ps1` в соответствующих каталогах `artifacts/`.
Сборка отдельных стадий обновляет их исторические манифесты; для разработки
предпочтителен изолированный `run_checks.py`.

Текущий проверенный на ноутбуке интерфейс — `codex_diag_06` (режим АВТО/СТОП/РУЧНОЙ).
Пакет режима создаёт новую копию из `codex_diag_05`; это не полная установка
рабочего Windows-проекта из Git. Пароли вводятся локально, в Git их нет.
